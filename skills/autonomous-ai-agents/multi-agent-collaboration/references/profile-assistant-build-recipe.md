# 建一个专属助理 profile 的完整配方

> 2026-10-18 实装。用户目标：建一个只管健康的「健康助理」，不被财经/美股上下文污染。
> 配套阅读：`hermes-profile-isolation.md`（调研阶段：Bot Mode 是什么、@为何在 TG 无效、--clone 污染陷阱）。
> 本文件是**执行阶段**：从头建到一个验证通过的专属 profile。

适用场景：用户想给某一领域（健康/投资/写作/运维…）建一个只懂那一域的助理，
它有自己的记忆、自己的 skill、自己的数据目录，不影响主 profile。

---

## 一、七步配方（实测跑通）

### Step 1：先建数据层（可逆、无副作用，且两种方案都要）

```
<域根目录>/
  profile.md      基线档案（每次分析必读）
  records/        原始记录（体检/账单/工单…）
  diet|logs/      日常流水（YYYY-MM-DD.md）
  reviews/        分析归档（YYYY-MM-DD_<主题>.md）
```

**域根目录放在 hermes 目录之外**（如 `~/health/`）——这样主 profile 与子 profile 都能读，
将来要换方案也不用搬家。

### Step 2：先想清"该域专属内容是什么"

因为 Step 4 要现写覆盖。提前想好它的 `USER.md` / `MEMORY.md` 该装什么。

### Step 3：建 profile

```bash
hermes profile create <name> --clone --no-alias \
  --description "<一两句该 profile 擅长什么>（kanban 分解器据此路由）"
```

- `--clone` 继承 config.yaml / .env / SOUL.md / skills（**含 memory——见下**）
- `--no-alias` 跳过 wrapper 脚本（**不加会在 PATH 多几个命令**）
- 建完 `hermes profile list` 应看到新 profile，Gateway 列显示 `stopped`（正合按需调用模式）

### Step 4：🔴 立刻清洗（不做这步等于白建）

**4.1 覆盖两个 memory 文件**

```
profiles/<name>/memories/USER.md   → 该域专属的用户画像
profiles/<name>/memories/MEMORY.md → 该域专属的运作规则
```

实测：clone 后 USER.md / MEMORY.md 各命中 2 处财经关键词（黄金/纳指/财务/OpenCode/A2A）。

**4.2 归档克隆进来的 skills，换一个空的**

```bash
cd profiles/<name>
mv skills skills.bak_cloned_$(date +%Y%m%d)
mkdir skills
touch .no-bundled-skills          # 阻止 bundled skills 被重新灌入
```

实测克隆进来 **101 个 skill**。skill 名 + 描述会进系统提示词，属于轻度污染，必须清。

`--no-skills` 与 `--clone` 互斥（源码明写），所以只能这样后置清理。

**4.3 ⚠️ 但 `.no-bundled-skills` 拦不住全部**

实测：标记文件在位的情况下，`skills/autonomous-ai-agents/hermes-agent/` 仍被自动装进来。
它不含该域污染，但会让子 agent 具备"重新配置 Hermes"的能力 → **手动 `rm -rf` 掉**。

### Step 5：写该域 skill

放在 `profiles/<name>/skills/<域>-analysis/SKILL.md`。推荐骨架：

```
## 数据在哪            ← 文件路径表，开头就写
## 触发场景            ← "他说什么 → 你做什么" 对照表
## 核心算法/核算        ← 含算术自检铁律
## 参考值表            ← 把权威阈值固化进来，别让它凭记忆
## 输出格式            ← 日常反馈 vs 归档文件，两种格式
## 安全边界            ← 硬约束，什么必须转给外行（医生/律师/工程师）
## 升级通道            ← 见第四节
## 已知陷阱            ← 该域特有的坑
```

**description 必须 ≤60 字符**（新 skill 的系统提示词预算，超了会被拒）。

### Step 6：在主 profile 的 **memory** 里写触发词

```
说「<触发词>」→ 读 <域根>/profile.md 并调 <profile>
  (hermes -p <profile> chat -c "Bot Chat" -Q --query-file)
```

- **触发词进 memory**（每轮加载才全局生效），**完整流程进 skill**（按需加载）
- 触发规则要带**防误触发条款**：只在"让它做事"的语境触发，拿不准先问
- ⚠️ memory 接近满时，加这条前先腾地方（见 `hermes-memory-hygiene`）

### Step 7：验证（必做，别跳）

见下节。

## 二、隔离验证（实测用的提问脚本）

```
只回答下面四件事，逐条编号，不要展开：

1. 你的记忆文件里有没有提到"投资""黄金""纳指""美股""OpenCode""A2A""日报"这些字眼？
   有就列出来，没有就回答"无"。
2. 你的<域>数据放在哪个目录？
3. <一个只有读过基线档案才答得出的具体问题，如"你的目标体重区间和减重速率上限是多少">
4. 你现在能读到几个 skill？它们的名字是什么？
```

**期望**：1 答"无"；2、3 答对（证明它真读到了档案）；4 只列出你装的那一个。

外加一条**功能性测试**：给它一个真实样本，看它会不会按 skill 走流程（先追问口径、拒绝擅自落盘）。

## 三、🔴 软边界：profile 隔离隔的是上下文，不是文件系统

**这是实测中最重要的一条。**

上面验证脚本第 1 问，子 agent 回答了「无」，**但它主动补了一句**：

> 另有一份不属于本 profile 的默认记忆 `...\hermes\memories\MEMORY.md` / `USER.md`，
> 里面确实有「日报/黄金/投资/纳指/A2A/OpenCode 相关」内容——那是另一台机/另一 profile 的，
> 没加载进我当前上下文。

**它是对的**：

- ✅ profile 隔离保证的是 **memory 不自动加载进上下文** —— 这是**硬保证**（机制层面）
- ❌ 它**不**保证文件系统隔离 —— 两个 profile 同机同用户，子 agent 有 terminal/file 工具，
  物理上就能读到主 profile 的 memory 文件

### 怎么写这条约束（用户拍板的版本）

**不要写成"禁读"**，写成"工作范围"：

```
🔴 工作范围（硬性）：做<域>判断时，依据只来自 <域根>/ 和本次对话。
需要<域>以外的背景（工作压力、经济约束、家庭情况等）？**直接问用户** ——
不要去翻其他 profile 的 memories / sessions / skills。
这不是"不许知道"，而是"<域>结论不由那些数据推导"。
```

**为什么不写"禁读"**：

| 写法 | 问题 |
|:--|:--|
| ❌ "不许读其他 profile 的文件" | 是**身份限制**。将来问跨域问题（"我最近工作压力大、吃不好睡不好"）时它会因自我设限而答不好 |
| ✅ "判断依据只来自 <域根> + 对话；需要别的就问用户" | 是**工作范围**。目标达成，且给了正当通路 |

而且第二种更好操作：**需要什么背景用户当场说一句，比它自己去翻文件更可控**。

**必须向用户讲清这只是软约束**：文字规则是劝阻不是强制。真要技术强制得改 gateway 代码或加文件 ACL ——
那是复杂方案，通常不值得。真正靠得住的是前两层硬保证：

1. 子 profile 的 memory 内容本身干净（清洗过）
2. profile 隔离 → 主 memory 不自动进它的上下文

## 四、升级通道：给小模型一条"找更聪明的脑子"的路

子 profile 的模型通常比主 profile 弱（或同款）。**要在建域 skill 时就给它一条升级通路**，
否则它会硬答或含糊过去。

### 放哪里

| 放哪 | 放什么 | 为什么 |
|:--|:--|:--|
| 子 profile 的 **memory** | 升级规则本身（一句） | memory 每轮加载 → 任何会话都生效 |
| 子 profile 的 **skill** | 完整调用姿势 + 坑 | 按需加载，不占日常上下文 |

### 规则该写什么（模板）

```
🔴 升级通道：遇到你自己推不出的问题（复杂归因、多因素交互、需要独立第二意见），
不要硬答也不要含糊过去 —— 调 <强模型> 帮你推。姿势见 skill <域>-analysis「升级通道」节。

⚠️ 配额与用户其他任务**共用且有限**（<实测日期>实测已撞限额，提示 <重置时间> 重置）。
→ 只在真正需要时用；撞限额就退回自己答，并如实说明"外部推理通道暂不可用"。
→ **用了就要在回复里讲明**，不要假装是自己推出来的。
```

### skill 里要写全

- **什么时候用 / 什么时候不用**（给正例反例，否则它会滥用）
- 完整调用代码骨架（Windows 走 `cmd.exe /c <abs>.cmd`，见 `codex-cli` skill）
- prompt 要含：用户基线 + 原始数据 + **你自己的判断和你卡在哪** + 具体几问几答
  + **明写"你可以否定我的判断"**（否则对方和稀泥）
- 配额纪律条款（撞限额时的降级行为 + 透明披露）

## 五、实测观察：子 agent 会审计你的整理稿

把**原始产物路径**给它、并明确说"不要信摘要"时，它会去核对源头。本次它：

- 逐字回读了 25KB 的原始 OCR，发现整理稿与原文 2 处对不上
- 自己重跑了算术（FIB-4 纤维化指数、Friedewald 反算 LDL）
- **挑出主 agent 手写档案里的 4 处错误**（报告原文没有分级却写了"中度"、两处页码数字不一致、
  推导出的目标区间算错、内部描述与结论矛盾）

**可复用的做法**：让子 agent 的 skill 里写「原始记录在 `records/`，整理稿只是索引；
有疑问回原始件核对」。把"验证"写进它的职责，它就会做。

## 六、坑速查

| 坑 | 现象 | 处理 |
|:--|:--|:--|
| `--clone` 带 memory | 子 profile 继承主 profile 的投资/运维记忆 | clone 后立刻覆盖两个 memory 文件 |
| cloned skills 数量 | 实测 101 个全进来 | 归档后新建空 skills/ |
| `.no-bundled-skills` 拦不全 | `hermes-agent` skill 仍被装上 | 手动 rm |
| skill description 超长 | 新建 skill 被拒（>60 字符） | 描述压到 60 以内，细节放正文 |
| 跨 profile 调用丢上下文 | 每次新建会话 | 必须带 `-c "Bot Chat" --create-if-missing` |
| 查询含引号/换行 | shell 解析炸掉 | 一律走 `--query-file` |
| 以为 profile 隔离=文件隔离 | 子 agent 能读到主 memory | 见第三节，写工作范围条款 |

## 七、什么时候**不要**建 profile

先做数据层，跑两三周再决定。因为：

- 数据层是**无论选哪个方案都必须做的**，先做不损失任何东西
- "上下文过长"这个问题**本质靠落盘解决，不是靠分流** —— 数据写成文件后，
  即使会话被压缩，`read_file` 随时能捞回来
- 建了再拆比不建麻烦；数据层就绪后再建 profile，迁移是零成本的

只有当用户**明确要物理隔离**（不是"担心"，是"就是要分开"）时才值得直接上 profile。
