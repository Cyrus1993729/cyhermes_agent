# 第三方工具/项目采用评估

## 触发条件

- 用户看到第三方工具/AI 应用/开源项目（小红书/推特/GitHub 推荐），问「要不要下载/安装/用」
- 工具持有 API key、能执行命令/改文件、开 Web 控制台等敏感面时**必须**走本流程
- 结论可以是「不装」——评估的目标是正确决策，不是促成安装

## 核心原则（2026-08-15 Hermes Studio 评估沉淀）

1. **功能路径 vs 信任边界是两个独立问题，后者优先**。先问「安不安全」再问「有没有用」。功能读 README/源码即可；信任边界必须查：认证模块、默认监听地址、默认凭据、沙箱、外部可接入面（邀请码/端口/共享链接）
2. **读源码验证机制，不信宣传话术**。README 的 bullet 是营销；机制要看实现：执行器是否真实（如群聊的 agent 类型 hermes/codex/claude）、状态管理是否完整（重试/租约/幂等）
3. **弱证据清单**（数量≠质量）：
   - 测试文件数量/commit 数量 → 说明不了覆盖率或有效性
   - star 数（非官方项目）→ 可刷，可疑信号不是可信信号
   - 演示视频/小红书推荐 → 推广话术的形状
4. **身份核实**：先确认仓库真实存在（GitHub API：stars/topics/README），再确认官方 vs 第三方——蹭知名品牌名（如 Hermes）需要多一分警惕
5. **默认配置安全检查**（评估下载决策必查项）：
   - `BIND_HOST`/listen 默认是 127.0.0.1 还是 0.0.0.0（后者=局域网暴露）
   - 默认凭据（admin/123456 类）
   - 认证是否可关闭、CORS 默认策略
   - 是否持有用户全部 API key + 有真实命令执行权限 + 有外部真人可加入面 = 五属性叠加 RCE 结构

## 流程

1. **功能验证**：源码/README + GitHub API 核实 + 关键机制读实现（不读实现不下"是真机制"结论）
2. **信任边界**：查认证/监听/凭据/沙箱/外部接入面（见核心原则 5）
3. **增量清单**：区分「真实增量」和「听起来厉害但用不上」（对照用户实际工作流，一条条过）
4. **双模型 sign-off**：技术/投资方案须外部大模型（Opus 优先）独立评估——喂足背景（用户画像+内容+自己的发现+明确要求批判不附和），见 `opus-deep-thinking` skill
5. **交付双视角**：Opus 核心判断 / 自己判断（一致/分歧，被说服就明说）/ 结论+优先级 / 最小风险验证路径
6. **不装也给出零成本替代验证路径**（如「把管线中间输出推 Telegram 两周验证需求」），需求证实才承担风险

## 用户已有同类系统时的「对照迁移」评估（2026-11-05 Agent-Autoloop 实踩）

用户发来一个开源系统/工具，问的不一定是「这东西好不好」，而是「**这东西对我们有什么意义**」。这时候不是从零评估它，而是先做**能力重叠度对照**：

1. **先数自己已有的，报数字不报印象——但必须读字段，不是读任务名**：读 `~/AppData/Local/hermes/cron/jobs.json`，**逐个 job 看 `no_agent` / `script` / `monitor_script` 三个字段**，不要只按名字归类（cron / interval / deliver）。

   🔴 **2026-11-05 实踩纠正**：我按任务名数出「18 个 job，14 个纯时间触发、4 个看门狗、3 个投递检查」，据此宣称「现有系统只覆盖 70%、事件驱动几乎为零、在用不可靠修不可靠」。GPT-6.1-Sol 一看就指出不成立，回查 jobs.json 属实：**14 个是 `no_agent=true` + `script=xxx.py`，根本不调模型**；且 cron 数据结构自带 `monitor_script` / `monitor_state` / `monitor_url` 字段——「先跑便宜检查、有变化才叫醒 AI」这套**本来就有，只是没启用**。

   → **正确姿势**：`no_agent=true` = 不烧模型的纯脚本检查；`monitor_script` 非空 = 已具备「巡检 + 静默」能力；只有 `no_agent=false` 且无 `script` 的才是真·agent 任务。数清这三类再开口，否则你会把「已有的便宜检查」误判成「落后的定时任务」，高估差距、低估自己。
2. **两栏写法**：「你已经有的」vs「你真正缺的」，每栏都点名到**具体机制**（cron / 多通道送达 / skill 复用 / 会话续接 vs 事件驱动 / 挂起续跑 / 指令数据分离 / 跳数熔断），不要停在功能名。
3. **不要自己编重叠度百分比**：功能数换不成使用价值。说「18 个 job 里 14 个已经不调模型」「`monitor_script` 已具备但没启用」这种可核实的事实，比「覆盖 70%」有分量且不会被驳倒。
3. **平台兼容性优先终结**：先看官方支持哪些 OS。用户主力 Windows 而项目只支持 macOS/Linux → 直接给结论「现在不装」，不必再评质量（第三方移植版 star 数低的（如 5 star）一律不碰）。
4. **不建议部署时必须给「提取机制」的三档路径**，不能只否决：
   - 立刻能做（零成本穷人版）：如把请示改成「编号 + 选项」，用户回「1」你接回原任务 = 存档读档的穷人版
   - 中等改造：给现有定时 job 做事件化甄别——哪些必须定时（日报/日程）、哪些改「轮询 + 无变化就静默」（看门狗/巡检/额度）
   - 重：等条件成熟（如 Windows 版发布）再评估「它当内核 + 现有系统当 Agent 插件」
5. **「对我个人有什么意义」要延伸到用户点名的域之外**：他说了 A/B/C，答复里除这三域外再给 2-3 条他没提的（从现有系统观察出来的噪音/重复劳动）；每条落到「具体触发条件 + 具体动作」，不写愿景。
6. **给判断，不罗列**：结论先行（反对/赞成/等），理由三条以内，最后给一句能被记住的核心判断。

> **反面教材**：把外部系统的机制逐条复述一遍当「价值评估」，全文没有一句对自己系统的对照。用户要的是「对你意味着什么」，不是「这个项目讲了什么」。

## 最小风险安装路径（若验证为真才执行）

- 隔离环境（VM/容器），不装主力机
- 额度上限的子 API key，不放主力 key
- 不启用邀请/共享功能；`BIND_HOST=127.0.0.1` 显式绑定
- 工作目录指向空目录
- 先只用核心功能（如 Web UI）跑两周，高级功能（如群聊）后开

## 坑

- 只读功能路径（mention-routing/relay 类）就下结论 = 漏掉信任边界。评估「要不要装」，先读 auth/security/config
- 引用「测试文件 30+、commit 40+」当质量证据 = 弱证据当强证据（Opus 实踩批评）
- 双模型 sign-off 时，自己的分析要主动标注哪些是核实哪些是推断（Opus 会基于你的转述判断，它会明确说明无法验证的部分）
- 名称确认：封面 OCR/ASR 都可能读错产品名（Holmes vs Hermes），用帧内运行时自述+GitHub API 双重确认（见 `xiaohongshu-analysis` skill）

- ⚠️ **工具宣称「降低封号概率 / 防封保号」= 无法验证的因果主张，方向常反（2026-09-09 CodexFF 案例）**：本地工具改变不了服务端风控判定。核查三步：① 源码 grep 有无任何风控相关机制（该案例：`封号|ban|风控|risk` 零命中）② 查 issue/文档是否真有此主张（该案例：零相关 issue，主张纯属社区民间话术）③ 回到封号真实触发条件判断——出口 IP 稳定性/共享度、支付、脚本自动化、**把订阅额度当 API 经第三方网关分发（key 分发）**。结论口径：官方 CLI + 官方凭证 + 固定独享出口 = 低位；更要警惕**工具的核心卖点（切到第三方中转）本身就是触发红线的那类行为**——「防封」话术与它自身机制常常自相矛盾。
- **用户问「我这台机/这个工具是否在滥用账号」→ 读配置证据回答，不凭印象**：`~/.codex/config.toml` 有无 `base_url`/provider 覆盖（无 = 官方直连；有指向中转 = key 分发红线）、`~/.codex/auth.json` 的 `auth_mode` 与 `tokens` 键（chatgpt + tokens.* = 官方 OAuth 登录态，正常用法）、再 grep 其他工具配置确认第三方网关里**没有**该厂模型。把这些串成结论，比笼统说「应该没事」可信得多。

- **用户问「用这个 API 要不要钱/收多少」→ 价格结论只认官网 fresh 数据（2026-09-11 Perplexity 评估实踩）**：做法 = web_search 定位官方定价页 → web_extract 官方页面逐项核对数字 → 换算「每次调用≈XX元」→ 按我们的用量估月成本。禁止凭二手博客/搜索摘要/缓存结论单源断言（用户 2026-08-17 定调：对价格/额度直觉质疑率高且常对）。另注意：付费 API 常无免费额度（Perplexity Search API $5/千次、无免费档 vs Tavily 免费 1000次/月——免费额度对比是决策关键数）。
- **评估针对我们自己工具链的更新（Hermes 自身功能）→ 先查本地版本兼容，再谈质量价格**：`hermes --version` + `hermes config get web` 对照官方版本要求（如 Perplexity provider 需 v0.21.1+，本机 v0.21.0 不支持）——「装不上」直接终结讨论。
