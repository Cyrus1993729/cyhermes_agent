# 熟醉蟹/醉蟹：商品条目 vs 基础条目、钠字段、全营养素实测（2026-10-21）

用户周末聚餐要吃**熟醉蟹**（他自己纠正：「这种醉蟹都是熟醉蟹，不是生醉蟹」）。
这篇是那一轮的真实数字、踩的坑、以及「同一道菜多条条目怎么选」的判据。

---

## 一、先说结论：熟醉蟹本质是一道「不油的蛋白菜」

2 只（可食约 100g）：**145 kcal / 蛋白 12.9g / 脂肪 7.5g / 碳水 6.4g / 钠 738mg / 嘌呤 ~145mg**。

真正踩线的只有两处：**蟹黄（熟）182mg/100g 是表1-2 里唯一进「高嘌呤」档（>150）的部分**；
**腌汁的糖和钠**（碳水 6.4g/100g 基本全是花雕＋糖）。

第一版我按**生醉**写的（嘌呤 147–180、钠 2999mg、还讲了寄生虫/弧菌风险），被用户一句话推翻。

## 二、生醉 vs 熟醉：两处全错，都要收回

| # | 我按生醉讲的 | 熟醉的实情 |
|:--|:--|:--|
| ① **嘌呤档位** | 表1-2 生条目：河蟹(生) **147** / 河蟹肉(生) **167** / 河蟹黄(生) **180** | 该用**熟条目**：大闸蟹(熟) **121** / 冬蟹(熟) 137 / 河蟹肉(熟) 144 / 河蟹黄(熟) **182** |
| ② **生食风险** | 「生冷海鲜→尿酸盐结晶」「寄生虫/弧菌」 | ❌ **整段作废**：蒸透后再浸汁，指南「生冷海鲜」那条不适用 |

⚠️ **别机械套机制**：熟条目数值低是因为「煮后嘌呤溶进汤」，而熟醉蟹蒸完**不弃汤**。
即便如此，同一个表里熟的条目仍是最贴近的，**选它 + 说明这个选择，不要过度推理**。

## 四、缺字段时怎么拼（每条都要标来源）

| 字段 | 用哪条 |
|:--|:--|
| 热量/蛋白/脂肪/碳水/钠 | 商品条目（盒马熟醉大闸蟹 145/12.9/7.5/6.4/738） |
| 微量 + 胆固醇 | `蟹肉(大闸蟹,公,蒸)` **fd68891e**、`蟹黄(大闸蟹,蒸)` **fda65c1c** —— 公开接口字段就全 |
| 嘌呤 | 一律表1-2，商品条目的 0 是假的 |

```
蟹肉(大闸蟹,公,蒸) 100g：128 kcal / 蛋白 24.2 / 脂肪 3.4 / 碳水 0
  胆固醇 89mg、维E 6.9mg、钾 312、钙 28、磷 225、镁 36、锌 5.31、锰 0.7
  units：1只 = 150g 毛重 → eat_weight 45g（可食率 30%）

蟹黄(大闸蟹,蒸) 100g：255 kcal / 蛋白 24.0 / 脂肪 17.2 / 碳水 1.2
  胆固醇 252mg、维E 23.12mg、钾 128、钙 5、磷 463、镁 40、锌 3.79、钠 224.3
  units：1只 = 25g
```

🔴 **两者不可相加**：商品条目是「带壳带汁每 100g」，蟹肉/蟹黄是「纯可食部位每 100g」——
蛋白 12.9 vs 24.2 差一倍就是口径差，不是蟹变了。

🔴 **薄荷蟹类条目的「铁」是错的**：蟹肉 **30.2mg/100g**、蟹黄 **26.6mg/100g**，
而《中国食物成分表》河蟹约 **2.9mg/100g** —— 高一个量级，**标存疑，别推荐补铁**。

**一只多大的量级**：按薄荷单重表 1 只 150g 毛重 → 可食 45g；所以我给「2 只 ≈ 可食 90–110g，取中 100g」。

## 五、工具层三个坑（都真实吃过亏）

1. **`boohee.public_detail(code)` 的钠是 `natrium`**，不是 `sodium`。读错键 → 全 `None`
   → 误判「商品条目没录钠」→ **白花 1 次付费额度**。
2. **`Boohee().detail(code)` 返回的是 3 元组**，不是 dict；解析前先 `d = r[0] if isinstance(r, tuple) else r`。
3. **`two_step()` 是模块级函数**（`boohee.two_step(...)`），**不是** `Boohee()` 的方法。
   写 `boohee.Boohee().two_step()` 会报 `AttributeError`。

付费额度实耗：`two_step('醉蟹')` 1 次 + `detail('盒马熟醉大闸蟹')` 1 次 = **2 次**（钠其实免费就有）。
quota 10 → 12（当日上限 50）。
