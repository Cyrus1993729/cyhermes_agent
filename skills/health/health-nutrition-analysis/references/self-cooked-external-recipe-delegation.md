# 用户照外部食谱自炊 → 派活给健康助理的核算任务书（2026-11-17 定型）

触发形态：用户发一条小红书/抖音/菜谱链接，说「我今天晚饭就是按这个做的」，
然后报自己下锅的食材。**主 Hermes 不核算**，只做两件事：① 把帖子做法还原（含用油）② 写成任务书派给健康助理。

## 全流程四步

```
① 小红书 skill 还原做法（视频类：ASR 出骨架 + 抽帧读字幕拿用量）
② 看上去像健康域 → 派活健康助理核算（本轮只出数字，不落盘）
③ 把回执原样转给用户确认（不压缩、不改数字）
④ 他确认后才写 diet/YYYY-MM-DD.md 的晚餐小节
```

步骤 ③④ 是既有规矩（两段式：核算 → 确认 → 存档），本文件只补步骤 ① 产出如何进任务书。

## 步骤①：还原做法时，**用量只信字幕，不信 ASR**（2026-11-17 实踩）

> 🚩 这段的技术本体本该写进 `xiaohongshu-analysis` / `video-understand-core`，
> 但两者**都是 user-owned，autonomous curation 写不了**（已实测被拒）。
> 要用的话：`hermes curator adopt xiaohongshu-analysis`，再把本节搬过去。

ASR 对**结构**可靠（步骤顺序、火候、时机、博主的分份建议）；对**数字和量词**整类不可靠：

| ASR 听到 | 字幕实际是 |
|:---|:---|
| 来适量的油大概**六颗**的样子 | 来适量的油大概 **6 克** 的样子 |
| 无点**番茄高** | 补点**番茄膏** |
| 没有**浮味** | 没有**浮沫** |

**固定做法**：

1. 跑 ASR，拿 `start` 时间戳当骨架；
2. 凡句子里有**数字 / 克数 / 毫升 / 颗根勺 / 品牌名** → 标为「待核」；
3. 对每条待核片段抽帧：`ffmpeg -y -ss <秒> -i video.mp4 -frames:v 1 -q:v 2 f_<秒>.jpg`
   （秒数直接用 ASR 的 `start`，不用另算）；
4. Vision 逐字读字幕——**字幕 > ASR，字幕是最终权威**。

本例 133 秒视频抽 8 帧、Vision 4 帧就定死了油量。一个量词错 10 倍是常事（6 克 vs 6 勺），
**而它直接决定这顿饭的热量和脂肪结论。**

另外两条铁律：

- 🔴 **区分「帖子的做法」和「用户自己的改动」**：用户额外加的食材（本例娃娃菜、香干）
  **不在视频里**，写任务书时两节分开，不要混成博主的步骤，也不要反过来按视频否定他的改法。
- 🔴 视频里博主给的**分份建议**（「不常锻炼就分 2–3 份吃」）要保留——
  用户常按它决定自己吃多少，这是核算份额的**口径依据**，不是废话。

## 任务书必含的七节（缺一节它就自己补口径，回头对不上账）

| 节 | 内容 | 为什么 |
|:--|:--|:--|
| 1 日期与档案 | 今天几号 / 档案绝径 / **已有哪几个小节** / 晚餐小节不存在 | 防重复建档、防覆盖早餐 |
| 2 用户原话 | **逐字摘录**，不改写 | 他要的就是「我的原话一字不改」进去 |
| 3 更正声明 | 后到的更正**显式写「前一条作废」** | 本案例标签 502g → 他改口 150g，不写清会被混用 |
| 4 下锅食材表 | 每样一行：食材 / 量 / 备注 | — |
| 5 **做法（口径依据）** | 步骤 + 每步用量 + **来源**（视频字幕 / 博主原话） | 用油只在这里能定下来 |
| 6 核算口径 | 份额怎么分、油按几克、调料怎么估、没报克数的怎么换 | 见下节 |
| 7 禁止项 + 交付格式 | 不写文件 / 不评价食谱 / 字段齐 / 来源标签 | — |

## 口径清单（本项目专属，逐条写进任务书）

1. **份额先行**：他说「吃了一半」「剩一半明天吃」→ 锅里**全部食材 ×0.5** 算今晚，
   **油和调料也按整锅投入的一半算**（剩菜同样带走了油和调料）。
   剩的那份**不许**算进今天。
2. **用油取字幕里的那个数**：本例视频字幕原话「来适量的油大概 6 克」，主值必须是 6 g。
   允许它另给一个「折损档」，但**不许把主值换成折损值**。
3. **包装克数 vs 口述克数冲突 → 一律以他口述为准**（标签 502g、他改口 150g 那次）。
   任务书里**同时列出两个数并写明哪个作废**，别只改一边。
4. **他没报克数的食材**（番茄/娃娃菜/香干/洋葱）→ 让它按常见单重换算，
   并且**把换算过程写出来给他看**（他看得懂「一颗娃娃菜≈200–250g」，不需要他核）。
5. **调料他从头到尾不报量**（花雕/生抽/盐/白胡椒/黑胡椒/番茄膏）→ 按菜谱常见配比估，
   **明标估算**，并**明确写「不要让他核」**。他的确认边界只到菜名和份量。
6. **酒类要单独交代**：花雕按「酒精基本烧掉」处理，让它说明取了多少残留，别整勺算热量。
7. **米饭这类「另外吃的」单独成行**，不进锅里那份的分摊。他报的克数按熟重。

## 禁止项（抄进任务书原文）

- **本轮只核算，不写任何文件**（`diet/`、`reviews/`、`profile.md`、skill 一律不许改），
  收尾自报「本轮没有写任何文件」+ 给出参照（文件仍是原来的字节数和 mtime）。
- **不写劝诫、不评价这个食谱好不好、不给改进建议**——他没问，只要求记账。
- 不用「占额度 xx%」这类预算式语言评钠/嘌呤。
- 不为了维护上一轮结论辩护，错了就认；不确定就说不确定。

## 交付格式

1. **结论先行**：这半份的总热量/蛋白/脂肪/碳水一眼可见
2. 逐项一行，字段齐：热量｜蛋白｜脂肪｜碳水｜纤维｜钠｜嘌呤（有值的糖/钙/饱和脂肪也带）
3. 每行跟来源标签，合计行下跟来源图例
4. 单列「数据完整性检查」（真 0 / 缺录 / 补录走了哪一级 / `‡` 标注）
5. 单列「换算过程」（他没报克数那几样怎么折的、油和调料怎么估的）

## 派活命令

```bash
hermes -p health chat -c "Bot Chat" -m deepseek-v4.1-flash -Q --query-file "<绝对路径>" \
  > "$LOCALAPPDATA/Temp/health_dinner_<日期>.txt" 2>&1
```

用 `background=true, notify=true` 起，别在前台 sleep 等。
任务书写在 `~/AppData/Local/hermes/cache/query_dinner_<日期>.txt`。

## 转发回执时的形态

- **原样搬明细，禁压成摘要句**（踩过：午餐回执被摘要，他说没看到回执）
- 用户自己的改动（额外加娃娃菜/香干）可以点一句「帖子没有这两样，按你的做法记」，
  但**不要替他改口径**，也不要说帖子更好/更差
