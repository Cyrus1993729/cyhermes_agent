# 照片餐食 → 派活核算：确认清单与验收（2026-11-02 全流程实战）

> 当日：早餐口述 + 午餐五碟照片。主 Hermes 做识别与验收，核算落盘派给健康助理。
> 结论：**照片识别错是常态，必须先出确认清单、后派活**；派活后自述不算数，必须调免费接口复核。

## 一、流程顺序（错了要返工 13–15 分钟）

```
整图先看 → 按碗/盘分区裁切放大逐区问 → 出纯文本编号清单 → 他改 → 才派活 → 自己复核
```

本次 5 碟里**错了 2 项**：
- 「炒土豆片」→ 实为**红烧萝卜丝**（碳水/热量差一个档）
- 薄饼「2 张 150 g」→ 实为**1 张 70 g**

若跳过确认直接派活，拿回的是一份口径全错的完整档案，改起来比先问一句贵得多。

### 分区识别的具体做法
用 `vision_analyze` 带 `region=[x1,y1,x2,y2]`（原图像素坐标，先 PIL 取 `Image.size`），
每区只问四件事：**主要食材 / 烹饪方式 / 块数或片数 / 碗底有无汤汁**。
整图一次问容易得到「拼盘式平均描述」，分不清配菜算不算在菜里。

### 确认清单的形态
编号纯文本，每项一行「菜名｜克数估计｜备注」，**能整段复制编辑**，不要选项按钮。
另起一节「我拿不准的 2–3 条」，明确点出来要他判断（菜名 / 块数 / 是否另有主食 / 可疑物）。

## 二、不明物体一律问，别当食物估
画面里一块「浅绿色椭圆物」，我按「甜糕点 40 g」估了 → 他回：「**5 里面椭圆浅绿的东西是勺子底部**」。
只要形态不是明确食物，就问一句。一句话的成本远低于把它算进档案再撤销。

## 三、菜名对了 ≠ 克数对了，他会分两次给
先改菜名，隔一轮才报实数：「红烧肉120g 红烧鸡块可食用大概80g 红烧萝卜丝80g」——三项**全部小于**目测值（160/110/170 g）。

- 他给了克数 ⇒ **立刻按他的数覆盖**，不再目测、不再问。
- 档案里必须留覆盖记录：「克数最终以第 N 条口述为准，覆盖主 Hermes 的初始目测 160/110/170 g」，
  否则以后回看会以为当时就是那个数。
- 整道菜只给总量（如「红烧萝卜丝 80 g」）时，按原估比例拆分并**标明估算**（本次拆 白萝卜 70 + 肉丝 10，7:1）。

## 四、薄荷 `units` 的块重不可直套
`hongshaorou` units =「1 块 = 35 g」→ 8 块 = 280 g；他报 **120 g**（≈15 g/块，食堂小方块）。
**units 是通用口径，不是他那一盘。** 他给了克数就用克数，并在行内注明「不套 units」。

## 五、复合菜条目 vs 生食材条目，差一个档

| 条目 | kcal/100g | 脂肪 | ×120 g 热/脂 |
|---|---:|---:|---|
| `hongshaorou` 红烧肉（复合菜，已含油糖汁） | 497 | 49.8 | **596.40 / 59.76** |
| `zhurou_naifu` 五花肉（生食材） | 349 | 35.3 | 418.80 / 42.36 |

差 **177.60 卡**，全在红烧肉这一项。食堂/外卖的红烧类**默认用复合菜条目**，
但档案里必须把另一档一起给出来，不要只报一个数。
同类：`hongshaojikuai` 136（复合）vs 生鸡块；卤味/沙拉鸡胸也一样。

## 六、派活后必须自己调 `public_detail` 复核（硬动作）

本次核了 `hongshaorou`、`hongshaojikuai`、`a5752ac5_c_259924`「薄饼」、`mifan_zheng`：

`public_detail` 免费不花额度，复核不设上限。

## 七、剔除项、「—」、真 0 三者性质不同，都要留痕
- 他说「炸面丝我给同事了」→ 档案单列一栏「完全剔除，0 卡」，并写「若误按 50 g（450 kcal/100g）计入会多算 225 卡」。
- 条目缺字段（薄饼钙、酸奶纤维）→ 记「—」、不进合计、另写一句说明。
- 食用油是**真 0**（无矿物质、无嘌呤），与「未收录」不同，可以记 0.00。

## 八、`verify_diet_tables.py` 的「不一致」要会读
它报 `❌ 纤维: 有 1/4 行不是数值`、`❌ 钙: 有 1/11 行不是数值`，都是「—」格被判非数值，**属预期**。
判据是它 `重算 [...]` 那行数值与合计行**逐项一致**。
**别为了消掉报错把「—」改成 0**——那是把「不知道」换成假数据。
脚本直接吃路径参数：`python verify_diet_tables.py <档案绝对路径>`（传 `--help` 会被当成文件名）。

## 九、汇报格式（他明确要过的）
逐项一行「菜名 克：热量｜蛋白｜脂肪｜碳水｜纤维｜钠｜钙｜嘌呤 —— 数据来源 code」，
再给合计行，**合计下面给图例**（† 表1-2 有直接条目 / ‡ 借同类推算）。
修订轮次里**只报变动的几项 + 新合计**，不要把整表再抄一遍。

## 十、口径漂移的处理（2026-11-02 牛奶事件）
核算中途发现历史口径有两种（牛奶 200 ml 记 200 g 还是 206 g）时：
**先按当前口径算完并给出结论，再把差异单独摆成一行问他一句「要不要统一」**，不要自己默默选一个。
他回「统一吧」之后要做三件事：① 改当日档案 ② 把口径写进 `references/portion-calibration-2026-10.md`
（含固定值与作废口径）③ 向他报告改了几处、差多少卡。
本次实测：他一句「统一吧」，值 3.9 卡/200 ml —— 值得问，因为口径一旦漂，跨日横向比较就失效。

## 十一、🔴 工具被中断时，他上一条「去记餐」的指令不能丢（2026-11-03 实错）

经过：他发午餐照片并说「这是今天中午的午饭，让健康助理记一下」。我在看图的同一轮被中断（`vision_analyze`/`read_file` 均 cancelled），
随后他只说了另一件日程的事，我处理完日程就把记午饭这件事**整个丢了**，直到他自己说「发完照片我就让你安排健康助理记午饭了」。

规则：
- 只要有**未完成且未被取消**的指令（尤其「记一下」「存档」「派给健康助理」这类有落盘动作的），中途插入别的任务后**必须回收**：
  哪怕先回一句「照片那条我还欠着，处理完这个就做」，也不要静默跳过。
- 打断恢复后先看最后一条 user 消息里**有几个动作**，一个都不许漏。漏了比做错更伤——他会认为你在选择性听话。
- 回收时直接开工，不要长篇道歉；一句「抱歉，照片那条刚才断了，现在办」即可。

## 十二、两次目测打架 ⇒ 两档都摆出来问他，不要取中值

同一张照片「整图一次问」和「分区放大问」会给出不同的份量：2026-11-03 午餐米饭整图估 200–250 g、放大估 330 g，差 130 g ≈ 150 卡。
处理：**在确认清单里同时写出两个数并明说差多少**（「05 米饭：整图 200–250 g / 放大 330 g，你平时一碗多少？」），让他凭常识拍板。
不要自己取中间值——那等于把一个可问的问题变成一个不可发现的错误。
差得越多越要单独点出来，因为主食克数直接决定碳水与热量整档。
