# 2026-10-28：复用历史餐次 + 应酬酒精 + 漏报配料

一天里踩齐了四类新问题，都不是「算错数」，而是**口径与数据性质**问题。

---

## 一、复用餐次：抄错了行，是行和自检抓住的

### 场景

用户：「午饭你参考昨天晚饭记吧 **复制粘贴就好了** 也是外食的」
随后改口：「**午餐换成昨天中午那餐吧**」。

即 2026-10-28 午餐 = 2026-10-27 午餐（9 人合菜，1/9 分摊，**1043.6 卡**）。

### 事故

我给健康助理的「10-27 午餐 11 行逐列清单」里，**前两行填的是 10-27 晚餐的菜**：

```
我给的： 杭州卤鸭 123.3      ← 晚餐行
        酱黄瓜拼萝卜 10.9   ← 晚餐行
        杭式三鲜 165.5 …以下都是午餐行

正确的： 招牌花雕鸡 140.3    ← 午餐行
        农家小炒肉 85.4     ← 午餐行
        杭式三鲜 165.5 …以下相同
```

**它是怎么被抓住的**——按我给的那 11 行逐列相加：

| 列 | 11 行相加 | 合计行要求 | 差 |
|---|---:|---:|---:|
| 热量 | 952.0 | 1043.6 | −91.6 |
| 蛋白 | 52.76 | 69.80 | **−17.04** |
| 脂肪 | 58.65 | 61.61 | −2.96 |
| 碳水 | 53.03 | 52.06 | +0.97（方向还反了） |
| 钠 | 2882.2 | 2429.5 | +452.7 |
| 嘌呤 | 430.3 | 566.0 | −135.7 |
| 纤维 | 3.27 | 3.47 | −0.20 |

**七列全对不上，不是舍入。** 换回正确两行后 11 行相加 = **1043.5**，与合计 1043.6 差 0.1（舍入），七列全对上。

### 教训

- 总热量只差 **8.8%**，**看起来完全说得通**，没人会主动去查
- 唯一可靠的拦截方式是**强制逐列行和 + 与合计对撞**，而且要**自己用代码复算**，不能只信它自报的 ✓
- **两桌菜在同一天出现过（午餐 9 人 / 晚餐 7 人）时最容易串行**。写清单时逐行标注来源餐次

## 二、「沿用」必须标数据性质，不能只标数值

档案里写的是：

> **数据性质**：这是**沿用假设**，不是实测。回溯时不能把它当成「2026-10-28 中午实际吃了 1043.6 卡」。
> 前提：10-27 那组按 **9 人合菜、每人 1/9** 分摊。今日午餐若人数不同、或未剩菜，此数不成立。
> 用户指令原话：「午饭你参考昨天晚饭记吧 复制粘贴就好了 也是外食的」→「午餐换成昨天中午那餐吧」

并把这次行数据混淆的来龙去脉也写在午餐节顶部——**归档时如果只看结果不看过程，下次回溯会以为那天中午吃了卤鸭。**

## 三、口径标注 ≠ 实际算法（沙拉 39 vs 30.2）

我在任务书里写「蔬菜沙拉 薄荷 `shucaishala` **39 卡/100g**」。

而 2026-10-24 定稿的沙拉是 **30.2 卡**——那是用**成分表拆蔬菜**算的，不是薄荷条目：

```
生菜 110g × 12 卡/100g = 13.2
番茄  55g × 15 卡/100g =  8.25
黄瓜  55g × 16 卡/100g =  8.8
─────────────────────────────
                        30.25  ✓ 对上 30.2
```

**照 39 走会多算 55.6 卡。** 健康助理主动对出来并走了实数。

→ 复用时要它**报出算式**，不要只搬条目名。条目名可能是我随手写的备注，不是当初真正用的路径。

## 四、漏报配料：木姜子油

| 时点 | 他说的 | 我怎么处理 |
|:--|:--|:--|
| 第一轮 | 「没有沙拉酱加了大概一点点生抽和醋」 | 主值不計木姜子油 + 并列「若 3g」对照 |
| 补充 | 「**也加了木姜子油 就还跟以前一样的量**」 | 直接采用 3g 版，不解释 |

```
不含木姜子油：410.1 卡 / 44.62 蛋 / 2.87 脂 / 54.90 碳 / 613.6 钠 / 237.9 嘌
含 3g        ：437.1 卡 / 44.62 蛋 / 5.87 脂 / 54.90 碳 / 613.6 钠 / 237.9 嘌
```

**差 27 卡 + 3g 脂肪。** 当天脂肪已 121%，这一项直接决定晚餐脂肪是 2.9 还是 5.9。

→ 「以前有、这次没提」的项：**主值按这次原话，但必须并列给对照档**。
→ 反向：**别把「以前放油」自动算成本次也放**——那是默认高估。

## 五、应酬啤酒：不劝诫

原话：「我刚刚喝了3小口啤酒 **没有办法 这是应酬** 帮我补记录一下」。

```
啤酒（普通拉格 3.6%）50ml
  16.0 卡 / 0 蛋 / 0 脂 / 0.80 碳 / 2.0 钠 / 4.0 嘌
  酒精 50 × 0.036 × 0.789 = 1.42 g
三档：45ml 14.4 卡 ｜ 50ml 16.0 卡 ｜ 60ml 19.2 卡
```

- 占全天摄入 **0.62%**（16.0 ÷ 2564.4），**比估算误差 ±200 卡低两个数量级**
- 尿酸：嘌呤只 4mg，但**酒精抑制尿酸排泄**——一句话点到，**不展开、不给「下次少喝」**
- 任务书里写死「不许劝诫」。他自己说了「没有办法」，再教育一遍是冒犯

## 六、排名断言自相矛盾（1252 vs 976.4）

健康助理原话：「今天 835.3–976.4，是你**记录以来的最高值**（此前最高是 10-25 的 1252）」。

**976.4 < 1252，这句话自己打架。** 实际排名：

```
10-25  1252.1  ← 最高
10-27  1105.8
10-28   835.3  ← 今天，排第三（上界 976.4）
```

→ 排名断言一律 `grep -hn "全天合计" ~/health/diet/2026-*.md` 自己排序。

## 七、饮品配方三档：NFC vs 糖浆

「青苹果美式 350ml」不是标准品，三档如下：

```
A 果汁版（NFC 苹果汁）｜ 73.0卡 0.3蛋 0.1脂 17.9碳 5.5钠 5.5嘌 0.34纤
B 糖浆版            ｜ 84.4卡 0.3蛋 0.0脂 21.1碳 9.4钠 6.4嘌 0.00纤  ← 「连锁惯例」推测
C 果肉版            ｜109.6卡 0.4蛋 0.0脂 27.0碳 13.6钠 6.0嘌 0.40纤
```

拼算：A = 咖啡 200ml（2 卡/100ml）+ NFC 汁 150ml（46 卡/100ml）。

**关键不在 36.6 卡的热量差，在糖的类型**：A 的 17.9g 是果糖（随果汁带纤维和钾），B 的 21.1g 是添加糖。

他中途补：「**我看到的是nfc苹果汁做的**」——**这类信息他手上有实物，问一句比按惯例猜准。**
