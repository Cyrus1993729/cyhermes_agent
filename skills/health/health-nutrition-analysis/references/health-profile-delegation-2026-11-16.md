## 一、profile 隔离的真相：它是读 skill 的，读的是**自己那份**

```
主 profile skill ： ~/AppData/Local/hermes/skills/health/health-nutrition-analysis/   ← 我读的，它不读
健康助理的 skill ： ~/AppData/Local/hermes/profiles/health/skills/health-analysis/      ← 它读的
                  ~/AppData/Local/hermes/profiles/health/skills/meal-photo-analysis/  ← 它读的
```

🔴 **纠正一条旧认知**：早前记的「它不读 skill，新规则只能写进任务书」是**错的**。
它有自己的 skill 目录，`meal-photo-analysis/SKILL.md` 就是它每次核算走的 SOP。
→ **长期规则的落点是 `profiles/health/skills/{health-analysis,meal-photo-analysis}/`**，
任务书只承担**本次**的特殊要求。两边都要写（skill = 长期，任务书 = 本次），但**别只写任务书**——
下次新会话一压缩就没了。

## 二、派活任务书的七要素（缺一项它就会自己发挥）

1. **用户原话逐字**（尤其菜名与克数），并明写「以他这句话为准，不许拿识别结果覆盖」
2. **餐次 + 日期 + 文件是新建还是追加**（当天已有早餐章节时要写「追加不覆盖」，否则它可能重写整份）
3. **口径疑点逐个点名**，但只点「注意什么」，不替它认菜：
   - 只给了可食部（酱大骨 80g）→ 要求声明酱汁浮油是否计入
   - 重油菜（鱼香肉丝）→ 别套瘦肉丝清炒低油条
   - 碳水类蔬菜（藕）→ 别按绿叶菜算
   - 熟重 vs 生重（紫米饭、蒸红薯）→ 明确按哪个
4. **六项齐 + 来源标签**：热量/蛋白/脂肪/碳水/纤维/钠，有钙、嘌呤照旧
5. **不算赤字**；累计必须写「截至 HH:MM，仅含已报餐次」
6. **落盘后从磁盘读回验证**（脚本 + 逐行独立复算），验证原文贴回执
7. **`-Q` 模式硬约束**：`execute_code` 与 `python -c/-e` 会被 BLOCKED；正确姿势是先 `write_file` 落 `.py` 再 `terminal: python <文件>`

## 三、照片流程的红线（2026-11-16 我又踩了一次）

SKILL.md 写的是「收到餐食照片，主 Hermes 一律不许自己识图」——**这次我第一动作就调了 `vision_analyze`**，
虽然没把结论写进任务书（后半段守住了），但**第一动作错了**。

🔴 **即使他已经把菜名、克数全报齐了，照片也只能交给它用 `recognize.py` 跑核对**：
照片的价值就是**独立复核**，我认了等于复核对做废。

正确顺序永远是：**只做一件事** → 把【图片路径原样】写进任务书 → 它跑 `recognize.py` →
**识别结果原样摆给用户** → 他对完再核算落盘。

### 这次的实际结果（说明为什么值得走这道）

`recognize.py`(minimax-m3) 对他口述的五样菜，判出来是：酱大骨→红烧猪蹄(conf 0.62)、
鱼香肉丝→没认出来(最接近「凉拌三丝」conf 0.28)、清炒藕片→凉拌藕片 195g、
清炒菠菜→蒜蓉空心菜 180g、紫米饭 230g(他报 120g)。
→ **五样里四样对不上**。它按口述算、把五处出入摆给他，他回「**按我说的存档即可**」。
→ 结论：照片是**提问清单生成器**，不是事实来源；他一句「按我说的」就关掉全部待确认。
   别为了「模型读不清小字」死磕（他的原话偏好），摆出来让他改或让他关掉。
