# 带骨菜口径 + 跨天口径串线（2026-10-23 实测）

一个食堂羊蝎子锅 + 一次「沿用昨天早餐」的口径失误。两件事都属于**同一类问题：行值和合计不是一套数**。

## 一、羊蝎子 7 块的口径推导

### 起点：他的一句话

> 「今天中午食堂吃的羊蝎子锅，我吃了这样大小的羊蝎子 7 块（**可食用部分挺少的**），还吃了 1 块豆腐，**没有蔬菜**，另外还有 150g 杂粮饭」

### 薄荷条目的陷阱

`basic`「羊蝎子」`fdfe349d`：

| 字段 | 值 |
|---|---|
| calory | 203 kcal/100g |
| protein | 19.0 |
| fat | 14.1 |
| carbohydrate | 0.0 |
| natrium（钠） | 81 |
| units | `[{unit:"块", weight:"70.0", eat_weight:"70.0", calory:"142.1"}]` |

**这组数就是「羊肉(肥瘦)」的纯肉值**（对照：羊肉(生) 嘌呤 109、脂肪约 14g/100g 同档）。
它的 `units` 把「一块」直接写成 **70g 可食**，等于假设**骨头上全是肉**。

🔴 **照它算：7 块 × 70g = 490g 可食 → 995 kcal、93g 蛋白、69g 脂肪。一顿食堂午饭出一斤肉，不可能。**

### 正确算法

```
可食 = 块数 × 每块毛重 × 出肉率
     = 7 × 100g × 35% = 245g
```

### 让他选档的问法（关键）

**不要问「出肉率多少」**——他没有这个概念。问**他能凭手感判断的**：

> 「7 块加起来，平均每块能剔出的肉大概是小半颗鸡蛋（25g）／大半个鸡蛋（35g）／还是一整颗鸡蛋（50g）？」

**他的回答：「出肉 35% 我觉得比较合适」** —— 一次就锁定。

### 三档敏感性（必须一起给）

| 每块出肉 | 7 块合计 | 午餐热量 | 午餐蛋白 | 午餐脂肪 | 午餐嘌呤 | 早+午脂肪 |
|---|---:|---:|---:|---:|---:|---:|
| 25g | 175g | 582 | 43.4 | 28.0 | 252 | **40.1（60%）** |
| **35g（锁定）** | **245g** | **724** | **56.7** | **37.8** | **328** | **50.0（75%）** |
| 50g | 350g | 938 | 76.6 | 52.6 | 442 | **64.8（97%）** |

**最高档会把当天脂肪吃到 97%，晚饭就没有油脂空间了** —— 这才是三档必须给他看的真正原因。

## 二、第二张「手持食物照」怎么用

他补发了一张**筷子夹着那块肉**的照片，一句话都不带 —— 目的是给尺寸参照。

```python
vision_analyze(
    image_url=...,
    question="以画面里那把塑料勺（勺头宽约4cm）和普通筷子（长约22cm）作参照，
              估算被夹起那块肉的长、宽、厚各多少厘米；骨头占多少体积比例？",
    region=[100,100,900,900],   # 裁到那块肉
)
```

**测得：长 8–10cm、宽 6–8cm、厚 2–3cm**（中心估计 9×7×2.5）。
按这个体积 + 骨孔 + 骨后不可见部分反推，每块毛重约 100g、出肉 30–40g —— **与他选定的 35% 互相印证**。

### 🔴 但 vision 会给出一个相反的数字

它同时报了「骨头体积只占 **5–10%**、可见附着肉约 **90%**」。
**这与带骨脊骨的真实情况矛盾**——它只看得见朝上的那一面，骨头在下面。

**判据（沿用 `edible_g` 规则）：**
- **照片用来定「块头」（长宽厚）** ✅
- **照片不能用来定「出肉率」** ❌ —— 以他说的「可食用部分挺少的」为准

## 三、汤汁口径（沿用 10-22）

> 「另外多少还是会沾到一点汤汁（我没有喝汤 也没有用汤汁泡饭 只是吃的时候多少会挂一点汤汁）」
> 「没有喝汤」

→ **汤按 0 计**，报告里一句话注明「汤汁未计入」即可。
同 2026-10-22「酸汤肥牛（我只吃了肥牛 150g 左右，沾少量汤汁）」那条规则。
**别再追问他「挂了多少毫升」——那是他判断不了的，也影响不了结论。**

## 四、嘌呤与其他配菜

| 条目 | 采用值 | 依据 |
|---|---|---|
| 羊蝎子 | 表1-2「羊肉(生) **109** mg/100g」 | 炖煮后部分嘌呤溶进汤；不喝汤则实际**不高于**此值 |
| 杂粮饭 150g | 18 mg/100g → 27.0 | 沿用 10-22 口径（薄荷无杂粮饭嘌呤条目） |

**午餐定稿：724.4 kcal ｜ 蛋白 56.67 ｜ 脂肪 37.84 ｜ 碳水 39.61 ｜ 钠 207.2 ｜ 嘌呤 328.1**

## 五、口径串线事故（我自己犯的）

### 事故

新建 `diet/2026-10-23.md` 时，早餐三样写「与 2026-10-22 完全一致」，于是：
- **合计行**：直接照抄 10-22 的 `295.6 / 15.30 / 12.14 / 32.43 / 385.6 / 14.9`
- **行值**：另按一套 mg/100g 重算 —— 红薯 **28.8**（对 24mg/100g）、牛奶 **5.0**

结果：**三行相加 = 嘌呤 34.3，合计行 = 14.9**，差 19.4mg。蛋白/脂肪/碳水也有 0.04–0.10 的取整差。

### 健康助理的处理（它是对的）

> 「我按『数字照抄』写入了 28.8 和 14.9，**并在表下加了一段明确说明，没有擅自改成一致**。
> 你要哪个口径，说一声我改。」

**它没有替我把矛盾抹平——这正是它最该做的事。** 该修的是我的任务书。

### 修正

行值整体改回 10-22 那套（红薯 **1.65 / 0.17 / 21.24 / 32.4 / 14.4**、茶叶蛋 **6.85 / 4.55 / 222.0**、牛奶 **0.0**），
三行相加 = `14.4 + 0.5 + 0 = 14.9` ✅ 与合计行一致；全天嘌呤随之从 342.9 改为 **343.0**。

### 规则

1. **「沿用上一轮口径」= 行值和合计一起整块 copy**，不许一半旧一半新
2. **收尾必做**：每张子表的行和与合计行各算一遍，对不上**就地改**
3. 不要留「⚠️ 本表存在行和与合计的差异，已如实记录不修正」——**他只要一个数，不要两套**
4. 报告「某值与旧值不同」时不用解释半天，直接说「是我两边取数混了，已按 10-22 口径统一」
