## 4. 🔴 「表1-2 米饭(蒸) 18」这条引用是错的（2026-10-30 查实）

**2024 版指南附录1 表1-2 里根本没有「米饭(蒸)」这一条。** 谷物类只有 `大米 44`、`粳米 31`，**都是生米值**。
（同一批不存在的条目：液态奶、蓝莓、小白菜、韭菜/韭黄 —— 全文各 0 次命中。）

**数值本身不算错，错的是出处标注**：
```
120 g 熟饭 ≈ 48 g 生米（吸水率约 40%）× 44 ÷ 100 = 21.1 mg  →  折 17.6 mg/100g（熟）≈ 18
```
→ 即「米饭(熟) ≈ 18 mg/100g」是**折算值**，可用；但 10-21 至 10-29 的档案一直标成
「**表1-2 直接查表**」，属**冒认出处**。再出现必须标 `‡ 折算（生米 44 × 40%）`。

## 5. 逐日嘌呤审计怎么做（2026-10-30 实操）

用户会直接要求：「核对今天记录的所有数据，重点核对嘌呤有没有明显错误，统计清楚有多少错误」。

**步骤**：
1. 读 `~/health/diet/YYYY-MM-DD.md`，把**每一个**食材/菜品条目连同克数抄出来（含无嘌呤列的餐次）。
2. 取当天实际用的薄荷 code：`~/health/tools/_*.py` 脚本会在
   `$LOCALAPPDATA/Temp/*.json` 存下 `two_step` 的原始返回（含 `purine`），直接读那个，不用重新付费查。
3. 逐项对表1-2，按 §3 规则补缺失条目。
4. **分档统计**，不要笼统说「有错」：
   - **严重错误**：记录填 0 / 近 0（<3mg）但应有 ≥3mg；或整项缺失
   - **偏低可接受**：偏差 ≤ ~20%（菜品含水/油料稀释造成的正常范围）
   - **核对无误**：逐项列出来，用户要看得到「哪些是对的」
   - **结构性缺陷**：整节没有嘌呤列 / 明细表没有嘌呤列 / 汇总表没有嘌呤行（**数是查不到的，不只是算错**）
5. 汇报固定顺序：**结论（错几项 + 低估多少 mg）→ 错误清单分档 → 核对无误项 → 结构性缺陷 → 附带发现 → 问是否改档**。

🔴 **关键教训：菜品级嘌呤不是「一律为 0」，而是「参差不齐，必须逐条判」。**
同一顿里 `fd34faae` 清炒菠菜 = 7.9 mg/100g（对得上表1-2 的 8）、`hongshaodoufu` = 39 mg/100g（只低 14%），
而 `jiuhuangchaodan` = 0.3 mg/100g（错，只覆盖蛋）。
**不能因为「薄荷菜品嘌呤不可信」就整顿跳过不查，也不能因为一条对就认为都对。**
