# 派活回执与口径纪律（2026-11-05/06 实跟）

> 适用：主 Hermes 把饮食/健康核算派给健康助理（`hermes -p health chat -c "Bot Chat" -Q --query-file`）之后，
> 怎么把回执交给用户、怎么判断该不该先落盘、以及哪些推定会被当场否决。

## 1. 回执必须逐项转述，不能压缩成摘要

🔴 **实踩**：午餐那轮我回了一句「午饭已落盘（合计 679 kcal / 蛋白 35.8g）」就去处理下一个请求，
用户直接说「**没有看到午餐的回执**」。

**规则**：健康助理回来多少项，就逐项转多少项。用户要的不是结论，是「每道菜各自算成什么」。

每项一行的最小字段集（缺一项就要补）：
`菜名 克数 ｜热量｜蛋白｜脂肪｜碳水｜纤维｜钠｜钙｜嘌呤〔数据来源标签〕`

然后才是：本餐合计 → 今日累计 → 对照 profile.md 的剩余额度 → 红黄绿。

**例外**：用户明确说「只告诉我结论/简单点」时才可压缩；默认不压缩。

## 2. 「记一下」= 已授权落盘；没说 = 先出稿等确认

| 用户说法 | 动作 |
|---|---|
| 「让健康助理记一下…」/「记一下」 | 直接落盘，回执里给出落盘字节数 + 读回验算 |
| 只描述吃了什么，没有「记」字 | **先出核算稿，不落盘**，末尾明写「待确认稿，未写入档案」 |
| 「估算完以后发给我确认」 | 先出稿；且要给**保守/主值/宽松三档**，不许只给一个数让他猜 |
| 「改一下」/指出某个数不对 | 改档案 + 同时改露出的合计/全天表 + 说明改动前后差值 |

## 3. 「口」→ 克必须写依据，且用他的历史口径

他用「口」报量时，不要给一个孤立数字。标准做法：
- 先翻他自己档案里的历史口径（如 2026-11-04「包菜 2 口 = 30 g」→ 素菜 15 g/口）
- 再按食材形态调整（薄肉片 12 g/口、菌菇 10 g/口、块状肉 20 g/口）
- **把换算依据写在回执里**，让他能一眼判断「4 口肉片大概对不对」
- 同时给三档，因为「口」本身就是最大不确定项

## 4. 🔴 菜名含「肉 + 菜」时，禁止用「家常比例」推定

**实踩（2026-11-06）**：菜心炒牛肉 220 g，用户说「牛肉占比高」。健康助理自行按「家常肉菜比 1:1–1.5:1」
推定 60/40 并落盘，用户随后更正为 **80/20**——晚餐嘌呤因此从 237.67 涨到 273.31，全天从 495.83 涨到 531.47。

**规则**：
- 菜名里同时有肉和菜、用户又没给比例 → **必须问一句「肉占几成」**。
- 「占比高」三个字**不算给了比例**。
- 他不答就先出稿、不落盘；确实需要默认值时按 **80%** 记（他实际给的就是 80%），不要退回「家常做法通常…」。
- 写进档案时留痕：「原按 X% 推定，用户 YYYY-MM-DD 更正为 Z%」，方便日后复核。

## 5. 派活任务书里引用 references 文件名，必须核对全名

**实踩**：任务书里写成 `boochie-entry-selection-pitfalls`，正确是 **`boohee-entry-selection-pitfalls.md`**（b-o-o-h-e-e，薄荷拼音）。
健康助理照实报「找不到这个文件」，白白占了它一轮注意力。

**做法**：写任务书前先 `skills_list`/`skill_view` 或直接 `ls references/` 确认全名；
拿不准就只写口径要求、不写文件名，让它自己去目录里找。

## 6. 让它可以「主动报异常」，但必须核实再转述

**实踩（正面案例）**：落盘晚餐时，健康助理主动报「早餐节在验算前被别处改过，燕麦纤维由表1-2 改成 USDA 口径」。

核实过程（可复用）：
1. `grep` 档案看改动留痕有没有「用户要求修正」之类的时间戳说明
2. 查对应 profile 的 `state.db`：
   ```sql
   SELECT role,tool_name,timestamp FROM messages
   WHERE content LIKE '%<关键字>%' ORDER BY timestamp ASC
   ```
   `messages` 的时间列是 **`timestamp`（epoch 秒）**，用 `datetime.datetime.fromtimestamp()` 还原。
3. 本次结论：改动是当天 08:47 用户亲口要求（原话「钢切燕麦的纤维含量改一下」），**不是误改**。

**转述纪律**：它报的异常先按上面核实；核实不了就说「核实不了」，不要原样传给用户造成恐慌。
**它的自报也要打折**：`信它不如信磁盘`——所有落盘结论都必须有「读回验算」结果支撑。

## 7. 顺手要修的档案缺陷

落盘后顺带检查文件头的 `> 状态：` 行。本次发现档案已三餐齐全，头部还写着
「进行中（仅早餐已入档；午餐/晚餐/加餐均未报）」——**头部状态行会腐坏**，每轮落盘后对一眼。
