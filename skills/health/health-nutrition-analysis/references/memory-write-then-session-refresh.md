# 给健康助理写记忆后，怎么让它真正生效

2026-11-04 实测。给 `profiles/health/memories/MEMORY.md` 加条目**只是第一步**，不刷新会话它读不到。

## 症状

改了 MEMORY.md（磁盘 8 条），派活问它「你 memory 里有没有 XX 条」，它答「没有，现有 7 条」——
**它看到的是会话创建时的 system prompt 快照**，磁盘改了也不重读。

⚠️ 危险之处：此时你给它下任务，它仍可能按格式正确输出（因为任务书里写了），
**看起来像学会了，其实没进持久记忆**。下次不写任务书就退回原样。

## 必须做三步验证

1. **确认磁盘写进去了**
   ```bash
   python -c "t=open(r'C:/Users/Administrator/AppData/Local/hermes/profiles/health/memories/MEMORY.md',encoding='utf-8').read(); print(len(t), t.count(chr(10)+'§'+chr(10))+1)"
   ```
   注意：文件 size 是**字节**（中文 3 字节/字），上限 2200 是**字符**。1018 字符 ≈ 2131 字节。

2. **确认新会话能读到**（不动老会话的验证方式）
   ```bash
   hermes -p health chat -c "临时自检" --create-if-missing -m deepseek-v4.1-flash -Q --query-file <任务书>
   ```
   让它**原文抄出**那条 memory。抄不出来 = 没写对。
   验证完删掉：`hermes -p health sessions delete <id> --yes`
   （**删会话要带 `-p health`**，不带会报 `Session not found`）

3. **真跑一次不带提示的任务**
   任务书里**不写格式要求**，只让它按「自己 memory 里定的规矩」输出。
   输出对了才算真学会。

## 老会话刷新流程（方案 A）

```bash
# 1. 先导出备份（会话可能几百条，删了就没了）
hermes -p health sessions export --session-id <id> --format jsonl \
  "C:/Users/Administrator/health/_archive_botchat_<日期>.jsonl" --no-redact

# 2. 删
hermes -p health sessions delete <id> --yes

# 3. 重建（-c 名字不存在会 fail loudly，必须加 --create-if-missing）
hermes -p health chat -c "Bot Chat" --create-if-missing -m deepseek-v4.1-flash -Q --query-file <任务书>
```

代价：丢掉对话上下文。**可接受**——健康助理本来就靠读 `~/health/` 档案反推口径，
memory / skills / diet / reviews 全在磁盘上。2026-11-04 实测重建后行为正常。

## 方案 B（不推荐，但存在）

不动会话，等上下文压缩时 Hermes 会重建漂移的 system prompt（日志：
`Compaction rebuilt a drifted system prompt ... memory/skills growth`）。
但压缩阈值 50%，可能等好几天，期间每次都可能按旧规矩来。

## 判断该不该删会话

- **改的是 memory / skill 里的硬规则** → 必须刷新，否则规则形同虚设
- **只是一次性任务口径**（某餐的克数、某天的安排）→ 不用动，写在任务书里即可

---

## 🔴🔴 重建会话的副作用：对话里才有的约束会蒸发（2026-11-04 当天踩）

删会话解决了「读不到新 memory」，**同时制造了一个更隐蔽的问题**：
老会话里那些**从没写进 memory、也没写进 profile.md 的口头约束，全部消失**。
新会话只能去读 `profile.md`——而 `profile.md` 可能是**几个月前的旧状态**。

**当天实况：**

- 重建后让它分析早餐，它建议「400 ml 全脂奶换成脱脂/低脂奶」和「加一勺乳清蛋白粉」
- 这两条他**早就明确否过**：家里是**全脂纯牛奶**（「一律按全脂算，勿建议脱脂」）；
  家里**没有蛋白粉**，他对蛋白粉还有心脑血管顾虑
- 根因：`profile.md` 第 164 行是指南原文「低脂/脱脂奶 300 mL/天」，
  第 269–285 行还留着 10-18 那段「计划用脱脂奶冲乳清蛋白粉」的方案——
  **新会话把它当成了现行计划**

### 重建后必须做的「约束回收」

1. **先盘点**：把你记忆里的用户硬约束列出来（家里有什么、吃什么档、明确拒绝过什么、
   买不买某类东西），逐条问新会话
2. **用是非题验证，不要用开放题**：
   ```
   2. 他早餐喝了 400 ml 全脂纯牛奶。按你 memory 的规矩，应该建议他换成脱脂/低脂奶吗？只答「该」或「不该」。
   3. 他早餐蛋白只吃了 23.66 g。按你 memory 的规矩，可以建议他加一勺乳清蛋白粉吗？只答「可以」或「不可以」。
   ```
   **答错的条目就是漏掉的约束，补进 memory 再重建一次。**
3. **验证分析质量时，任务书里不要提示答案**：写「按你 memory 里定的规矩来」即可，
   **别把格式或约束写进任务书**——写进去就测不出它到底学没学会。
   （当天第一次重发分析时我顺手写了「不要给需要买东西的方案」，等于把答案漏给了它，
   撤回重发才是干净的测试。）

### 🔴 重建后的任务书必须自带全部基线（否则它算不出来）

新会话**没有上下文**：它不知道当日目标、不知道今天已经记了哪几餐、不知道档案在哪。
老会话里这些都是上下文里现成的，重建后必须**每次显式写进任务书**：

- **日期**（「2026-11-04（周三）」）—— 它不会自己推断今天是哪天
- **档案路径** + 已有小节（「已有 `## 早餐` `## 午餐`，**只能追加，前两餐一个字都不要动**」）
- **当日目标四个数**（热量 / 蛋白 / 脂肪 / 碳水）
- **该餐的已知口径**（例：茶叶蛋 50 g 去壳卤汁不计；牛奶按全脂）
- 标清楚 `profile.md` 里哪些是「实际口径」、哪些是旧计划

🔴 **漏了当日目标，它会去 `profile.md` 取旧基线**（2000/110/250/62），
「离目标差多少」那一整段就全错；漏了「已有小节」提示，它可能把早餐整节重写。

→ 重建会话后的第一单，可以**先跑一份「基线卡」任务书**让它把基线读进上下文，再派具体活。

### profile.md 的正确改法

**指南原文不要删**（那是出处，删了以后没法追溯），而是在旁边钉「实际口径」，并让过期的旧方案失效：

```markdown
> 🔴 **实际口径（日期，优先级高于上面这条指南原文）**
> 上面「低脂/脱脂奶 300 mL/天」是**指南引用**，不是他的实际选择。
> **他家里喝的是全脂纯牛奶，核算一律按全脂算，且不要建议他换成脱脂/低脂。**
```

旧方案整节标作废：标题加 `~~删除线~~ ❌ 已作废（日期）`，正文首行加失效声明，
**下面原文保留作历史记录**——不要整段删，他当初的决策过程也有参考价值。

### 🔴 主 Hermes 转发前的踩线检查（每单都要做）

健康助理的建议**不能原样转发**。转发前对着他的实际处境过一遍：
**这条建议落到他身上，是不是要买东西 / 换品牌 / 换品类 / 让他多做一个动作？**

- 踩到「家里没有的东西」→ 拦下来
- 踩到「他明确拒绝过的方向」→ 拦下来
- 拦下来要说清楚**哪条踩线、为什么、其余几条能不能用**，而不是整篇退回

这个检查是**主 Hermes 的职责**——健康助理看不到你记忆里的那些约束。
当天两版分析里，第一版 5 条建议有 2 条踩线，第二版 5 条全干净，差别就在这一层。
