## 1. 根因：规格匹配 ≠ 配方匹配

同一个品牌、同一个品名，为什么会有 9 条？因为它们是不同用户按不同批次、不同产品线、不同填写习惯录进去的：

- 「瓶 1500 g」「份 3000 g」— 明显是按大包装/整箱口径填的
- 「无规格」— 用户随手填，没有 units
- 「份 450 g」— 反而可能是凑数

**净含量对得上，只说明这条的 units 字段撞对了，不说明它用的是同一个配方。**

尤其 `Na 4984`、`Na 4749` 这两个值——接近 5% 的纯盐含量，对发酵酸汤来说高得离谱。
一个可用的常识筛子：**贵州酸汤传统上是「以酸代盐」（苗侗地区缺盐的产物），
发酵型红酸汤本身含盐不高；但标着「复合调味料」的会额外加盐和味精。**
所以 1000–2500 是合理区间，4500+ 基本是脏数据。

## 2. 正确流程（已固化进 SKILL.md）

1. **库里查得到 ≠ 查得对。** 命中多条时，先把全部候选列出来给用户看，**不要自己挑一条就当结论**。
2. **跨度 >2 倍时，直接判定「库数据不可用」**，走「查不到」路径，请用户拍包装背面。
3. 用户提供标签后 → 用 `vision_analyze` 读（**这不受「禁止主 Hermes 认菜」那条约束**，
   那条针对的是餐食照片，不是商品标签）。
4. **跑标签自洽校验**：
   ```
   1.5×4 + 4.7×4 + 5.2×9 = 71.60 卡
   298 kJ ÷ 4.184        = 71.22 卡
   偏差 +0.53% ✓ 没读错格
   ```
5. **写进 `~/health/fooddb/custom_foods.json`**，来源标「标签值 / A 级」，
   备注点名取代哪几条旧条目。
6. **回读验证**：
   ```python

   FoodDB().calc("玉梦 红酸汤", 20)                          # → 14.24 卡 / na 426.00
   ```

## 4. 值得单独记住的一条饮食结论

用户「把肉挑出来吃、不喝汤」，只拿到酸汤钠的 **1/10**（426 / 4260），
**挡掉 3834 mg，相当于 1.92 倍的日推荐上限。**

炖菜的盐九成在汤里。**「少喝汤」比「少放盐」有效得多**，而且不改变菜的口味。
这条可以直接对用户讲，他认。

## 5. 附着比例怎么估（本次新方法，可复用）

用户说「没怎么喝汤，把牛肉挑出来吃」时，**不能按汤量比例算**。要分两路：

- **表面挂汁**：250 g 牛肋条约 8–10 块，总表面积 450–550 cm²，挂汁膜 0.3–0.5 mm，
  理论 14–27 g，**挑起来会滴落，实际入口 40–50% → 6–13 g**
- **炖煮渗透**（大头）：1.5 h 小火，牛肉含水 ~60%，整锅汤汁盐浓度 ~1.2%，
  90 min 达到平衡的 55–70% → 肉内盐 1.0–1.3 g → **Na 400–520 mg**

两路相加占总调味钠的 **6.5%–8.4%**，取 **10%** 作为保守档。

三档换算（本例）：5% → 钠 613.81｜**10% → 931.37**｜15% → 1248.93。
**热量三档只差 15 卡，这一项只影响钠。**
