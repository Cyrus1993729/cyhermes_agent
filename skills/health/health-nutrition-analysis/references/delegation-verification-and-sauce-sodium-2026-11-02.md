## 1. 🔴 生抽钠的**成品值锚点**（同一天被算错 10 倍）

健康助理把「生抽 5 g」算成 **35 mg 钠**（相当于 700 mg/100g，少了十倍）。实际普通生抽是
**6000–7000 mg/100g**，5 g 应为 **300–350 mg**。少算的 290 mg 把晚餐钠从 839 压到 549，
于是「全天钠只超 66 mg（103.3%）、这单是钠最干净的一顿」这个结论**假成立**——修正后是 2356（117.8%，超 356）。

**速查表，直接抄，别再换算：**

| 用量 | 普通生抽 6500 mg/100g | 薄盐生抽 4250 mg/100g |
|--:|--:|--:|
| 5 g | **325 mg** | 213 mg |
| 7 g | 455 mg | 298 mg |
| 10 g | 650 mg | 425 mg |
| 15 g | 975 mg | 638 mg |

**为什么已有规则还会踩**：本 skill 只在「拆原料的三个必须」里写了定性的「油盐糖酱油必须单独列」，
**没有给成品数值** → 管线照样会随手填一个数量级错误的值。**锚点必须给到「5 g = 325 mg」这个粒度。**

判据：任何拆原料路径里出现 生抽 / 老抽 / 酱油 / 蒸鱼豉油 / 蚝油 / 豆瓣酱，先自问「这一勺多少钠」，
再往下算。外卖菜里它常常是**本餐钠的最大单笔，比主料本身还高**。

## 2. 派活输出被截断 → 去 health profile 自己的 `state.db` 取全文

`hermes -p health chat -c "Bot Chat" -Q --query-file ...` 的后台回执**只保留最后约 2000 字符**，
逐项营养表经常整段被截掉（本次晚餐评估的四个菜表全没了）。
**不要让它重述**（又一轮十几分钟）。直接读它自己的库：

```python
import sqlite3, os
p = os.path.expanduser("~/AppData/Local/hermes/profiles/health/state.db")
con = sqlite3.connect(f"file:{p}?mode=ro", uri=True)
row = con.execute(
    "select content from messages where role='assistant' order by rowid desc limit 1"
).fetchone()
print(row[0])
```

- 表 `messages`；关键列 `content` / `role` / `session_id` / `timestamp`（epoch）/ `reasoning_content`。
- **用 `mode=ro` 只读打开**，不碰 WAL；主 Hermes 并行读不冲突（实测与后台进程并存无问题）。
- 顺带能拿到 `reasoning_content`——它常在那里写「我用的哪个 code、为什么换条目」，
  比回复正文更早暴露口径偏差。
- 这条也适用于任何「子 profile 输出被截断」的场景，不限健康域。

## 3. 目测克数会被他报的**实数覆盖** —— 必须回改重算，不能只在回复里改口

本次午餐实测流程（值得照抄）：

1. 出识别清单，**明确标出哪几项是我目测的**（红烧肉 160 g / 鸡块可食 110 g / 萝卜丝 170 g）。
2. 他回：「红烧肉 120g 红烧鸡块可食用大概80g 红烧萝卜丝80g」。
3. **回档案把每一行克数 + 合计 + 供能比 + 自检 + 嘌呤表 + 小计表全部重算**（−278 卡、脂肪 −23 g、钠 −252 mg），
   不是在回复里说一句「按你说的改了」。
4. 档案里**保留两代数字并注明覆盖关系**：「克数由他报实数覆盖目测值：160→120」。他回看时要能看出改过什么。
5. 拆分项要标明是估算：80 g 红烧萝卜丝 → 白萝卜 70 + 肉丝 10（按 7:1 拆分，**总量以他给的 80 g 为准**）。
6. 改完跑 `verify_diet_tables.py <档案绝对路径>` 并复述重算行。

**教训**：目测值只是给他改的草稿。他一报数，目测值就作废——包括它派生的一切合计。

## 4. 同一道菜两档口径都要摆（薄荷菜品条 vs 拆原料）

外卖 / 食堂菜评估时，**别只给一个数**：

- **薄荷有菜品级条目** → 可以用作主值，但必须同时给**拆原料档**做对照，
  因为外卖油量普遍高于库里的标准配方。
- 实例：番茄炒蛋 `fanqiechaodan` = **84 kcal/100g**（脂肪 5.96），275 g = **231 卡**；
  拆原料（蛋 100 + 番茄 150 + 油 20 + 糖 5）= **366.5 卡**（133 kcal/100g）。**差 135 卡**。
- 判据：他不说油多重时，**主值取拆原料**（外卖重油），并写明「要是不油可以换菜品条口径」。
- 同理 `清炒菠菜 fd34faae` = 42 kcal/100g，生菠菜 `bocai` = 28 —— 「烫」还是「油淋」差这一档。

## 5. 「打算吃」的评估：档案零改动，措辞用条件式

外卖下单前 / 购物车截图问「这样吃行不行」时：

- **不进档案**。派活任务书里写死：「不许新增/修改晚餐小节、不许计进全天合计」。
- 措辞用「如果点这单」「假设吃下」，全程条件式。
- 它这次遵守了，并且**主动报了档案的 md5 与行数**证明没动过——这个自证动作值得保留，
  以后验收「有没有偷偷落盘」时直接看这句话。
- 评估交付形态：四菜逐项表 → 全天合计与逐项占比 → 适配/不适配分开讲 → 微调档（**按影响大小排序，每档标省下多少卡/多少钠**）。
  微调档要具体到「番茄炒蛋备注少油少糖」「米饭减半」「粉丝只吃一半底汁不喝」这种**下单时能勾选的开关**，
  不要写「少油少盐」这种空话。

## 6. `verify_diet_tables.py` 报 ✗ 多数是**预期**，不是错

正确调用：**直接传档案绝对路径，没有 `--help`**（它把 argv[1] 当路径，传 `--help` 会抛 FileNotFoundError）。

```bash
python "C:/Users/Administrator/AppData/Local/hermes/skills/health/health-nutrition-analysis/scripts/verify_diet_tables.py" \
       "C:/Users/Administrator/health/diet/YYYY-MM-DD.md"
```

它会因**「—」占位格**判「N 行不是数值」并标 ✗ —— **这是设计允许的**（未收录字段不许填 0 冒充）。
判据只看**它重算出的数值数组是否与合计行逐项相等**：

```
[✗] 晚餐｜6行/8列
     重算 [743.0, 40.13, 35.28, 69.53, 5.44, 575.61, 253.24, 213.38]   ← 与合计行一致即 PASS
     ❌ 钙: 有 1/11 行不是数值（「—」引起，预期）
```

⚠️ 它**不覆盖**「全天合计表」「敏感性表」「对照表」——这些要另外读回磁盘手核。

## 7. 两轮核算的差额必须**逐项归因闭合到 0**

「整盘评估值」→「他实际吃法」的重算，不能只给新总数。**每一分差额都要能归到具体项上：**

| 项 | 整盘口径 | 实际吃法 | 差额归因 |
|---|---:|---:|---|
| 热量 | 1004.70 | **743.00** | 粉丝 −123.55 ＋ 蒜蓉油 15→4 −99.00 ＋ 生抽 5→2 −1.95 ＋ 虾 120→80 −37.20 |
| 钠 | 839.49 | **575.61** | 生抽 −195.00 ＋ 虾 −66.08 ＋ 粉丝 −2.80 |

**归因表加总到差额才算数；加不上就是漏项或换了条目。** 这条也是回头回答「吃法和整盘到底差多少」的唯一可靠口径。

### 「这个我不吃 / 不蘸汁」的正确处理

- **不吃的整条删掉记 0**，不是估小、不是打折。他把炸面丝给了同事，误按 50 g 计会多算 225 卡。
- **不蘸汁 → 油和酱油只算「表面附着」**：蒜蓉油 15 g → **4 g**、生抽 5 g → **2 g**。
  理由是盘里那层油跟着粉丝和汤汁走，只有挂在虾壳上的入口。
- **「只挑菜、撇汁」→ 按无额外调味记**，钠只取食材自带值。
- 反向也成立：**别把「食材包着油」当成「没吃油」**——表面附着要留一档，不是归零。

## 8. 照片里拿不准的异物：**先问，别猜着算**

本次照片角落有个「浅绿色椭圆物」，被识别成青团/绿豆糕——实际是**勺子底部**。

- 在确认卡里**单列一行问他**，成本一句话；算错的成本是整餐返工。
- 他答「是勺子」后，把档案里「未食用待补」那句改成「**经确认为勺子底部，非食物**」，别留悬案。
- 同一条适用于任何「照片里像个食物但没把握」的东西（装饰菜、垫盘菜、别人碗里的）。

## 9. 收尾口径

- 早餐/午餐小节**一个字都不许改**，新餐只能**追加**小节；每份派活任务书都要写这条。
- 全天合计**只在最后一顿记完后**才出；中途只给「早+午小计」并标明「晚餐未报，不推算全天、不出赤字」。
- 每张表都要有 `### 主 Hermes 独立复核` 段：列出**调了哪些条目 code、复算了哪些列、哪些 ✗ 属预期**。
- 口径修正要**留痕**：写错过的数（如生抽钠 35→325、对虾 101.5→基围虾熟 174.0）在档案里留一行「修正记录」，不要静默改掉。
