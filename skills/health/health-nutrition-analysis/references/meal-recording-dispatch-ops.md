# 餐食记录派单：子 profile 调度 + 口述优先 + 口径沿用

> 2026-11-17 全天（早餐/午餐/加餐四轮派单）实测总结。适用场景：用户发一句「让健康助理记一下我的午饭 / 加餐」，
> 或连发多餐要求「今天截止目前的汇总」。

## 一、派单姿势（每轮都一样，别现编）

```bash
# 1) 任务书写到文件（长 prompt 一律 --query-file，不要 $(cat)）
#    文件名带日期+餐次：query_<餐次>_<YYYYMMDD>.txt

# 2) 后台跑，输出重定向到 temp，notify 收尾
cd ~ && hermes -p health chat -c "Bot Chat" -m deepseek-v4.1-flash -Q \
  --query-file "C:/Users/Administrator/AppData/Local/hermes/cache/query_lunch_20261117.txt" \
  > "$LOCALAPPDATA/Temp/health_lunch_20261117.txt" 2>&1
```

- **必须 background=true + notify=true**。一轮识图+核算+落盘要 **6–9 分钟**，前台 `sleep 240` 会直接撞 280s 超时。
- 想看进度就 `wc -c <tempfile>`：刚启动 ~94 字节（只有 `↻ Resumed session ...`），>1KB 基本是出结果了。
- 它是**会话保留**的（同一个 session id 反复 Resumed），上下文里已经有前几轮的档案口径，不用每轮重复贴数据。

## 二、任务书必备七块（缺一块它就会自创口径）

1. **用户原话一字不改**（引号括起来，标注「已吃≠打算吃」）
2. **图片路径原样**（照片核对场景；让它用 `recognize.py`，明确写「主 Hermes 没有认菜」）
3. **明细清单**：每项标克数来源 `他说 / 估算 / 档案沿用`
4. **口径红线**：未报餐次写「未报」不填 0、不出赤字、不拿 TDEE 差额当当天额度、他报的克数默认可食部
5. **额度纪律**：R0 先看结果 / R1 不走 detail / R2 付费上限＝样数
6. **回执格式**：逐项一行＋合计＋参数备注＋来源标签，禁 markdown 表格，禁压成摘要句
7. **工具姿势**：`-Q` 下 execute_code / `python -c` 都被 BLOCKED → 先 write_file 落 .py 再 `python <file>`

## 三、🔴 主 Hermes 自己别识图（本轮又踩了一次）

2026-11-17 我在读 skill 之前先调了 `vision_analyze` 看午餐照片 —— **这正是 skill 明令禁止的**。

## 四、🔴 菜名冲突：他说了算，且不许让他二次拍板

2026-11-17 午餐：识图把「面条/素鸡/酸菜牛肉」认成「汤粉/圆饼/梅干菜扣肉」。我把三处冲突列成确认卡发给他，
他回一句：**「午饭 一切都以我说的为准」**。

教训：
- 他报的菜名跟他拍的照片冲突时，**他的口述即为事实**，识图纠正一律作废；
- 第二轮任务书要显式写「上一轮的 N 处冲突作废，是面条/素鸡/酸菜牛肉」，否则它会沿用错条目；
- **不要在第二轮再让他逐项点选克数**——他说「以我说的为准」就是让你按他的数落盘，剩下差额单列成「不同档位差异」让他事后自己看。

## 五、🔴 没报克数时：先找前例沿用，别另立口径

他讲「**还是** 150g 蒸红薯 一个白煮蛋 250ml纯牛奶」这类话，意思是「和我前几天吃的一样」。
任务书要写死顺序：

1. 先读 **前几天同餐段的 diet 档案**，沿用同一条目 code 和同一克数口径；
2. 再查 `piece_weight.json` 的个/根/只可食重（如白煮蛋 60 g 毛 / 52.8 g 可食）；
3. 都没有才用薄荷 units 档位估，并标注估算。

⚠️ 回执要说明「用的是 11-12／11-15／11-16 同一口径」，他才知道没换算法（他原话：「算法别变了」）。

## 六、固定口径（他家的，别问也别建议改）

| 项 | 口径 |
|---|---|
| 纯牛奶 | **全脂**，250 ml 按 250 g 算；绝不用脱脂条、绝不给脱脂建议 |
| 白煮蛋 | 1 个 = 可食 52.8 g（`piece_weight.json`），煎蛋 1 个 = 可食 52 g 但条目已是「含油」口径，不另加油行 |
| 面条 | 「一碗」先给大碗（熟 300–350 g，碗径 19–20 cm）/小碗（熟 200–250 g）两档，**给区间不取中值** |
| 碱面/小麦面 | 用 `miantiao_fuqiangfen_zhu`「煮面条」107；**禁用「面条(生)」301**（干面口径会翻倍） |
| 汤汁 | 他没说喝 → 不计，别按汤碗毛重全算 |

## 七、转贴回执的规矩

- **原样搬明细，禁止压成摘要句**（踩过：午餐回执被摘要，他说「没看到回执」）。
- 但**它的自我矛盾要指出**：2026-11-17 它写「素鸡是第二大钠源」，按 41.3% 明明是最大钠源——
  数字没错、措辞错了，回执里必须点出来，不能跟着错。
- 它的自报（「已写入 12,821 bytes / ALL PASS」）**必须自己复核**：`ls -l ~/health/diet/<date>.md` + grep 合计行。
  本轮实测文件确实存在且合计行对得上，但这一步不能省。
- 它有时会自己填一个莫名其妙的时间戳（本轮写「截至 11:25」，实际 16:07 写入），回执里单列一行让他核，
  不要替他改成默认值。

## 八、连续多餐的节奏

早餐→午餐→加餐是**三轮独立派单**，每轮都要求「追加写入 + 重出当日汇总」。
**每轮都咬死「早餐/午餐那几段一个字都不许动」**，否则它会重排整份档案；它也会自动备份 `_bak_<MMDD>_pre_*.md`。
