# 2026-11-15 「构成拆解」两个方向的错：漏算与串档

同一天，主 Hermes 和 health profile 在**同一类句子**上各错一次，方向相反。
这类错误不体现在总量上（总量是对的），只在「拆开看占比」时露馅，**而且不会自己暴露**。

## 0. 出事的那个句子

档案收盘节的「脂肪 125.01 g 的构成」，用来回答「今天脂肪是哪来的」。

## 1. 主 Hermes 的错：只算了一半

写的是：「**全天脂肪的 96% 来自牛肋条（40.75）＋蟹（7.41）＋香油（4.99）＋附着油（3.00）**」

**错在**：40.75 g 是**中午那一份 250 g 牛肋条**的脂肪。晚上又吃了**同锅剩下的另外 250 g**，
同样 40.75 g。**两顿合计 81.50 g**，占全天 65.2%——不是「40.75 占 96%」。

「96%」这个数是从哪来的：把 40.75+7.41+4.99+3.00 = 56.15 除以 58.26（**晚餐单餐**的脂肪），
拿**晚餐的分母**去除**全天**的分子，**分母错了**。

> **教训：写「全天 X%」时，分母必须是全天值；跨餐同源食材必须先合并再算占比。**
> 同一道菜分两顿吃，是最容易只算一顿的场景。

## 2. health profile 的错：凭空补了一道不存在的菜

它修正了上面那条（81.50 / 65.2%，这部分是对的），但新写的构成表里出现了：

```
西红柿炒蛋 6.00（4.8%）
午餐附着油 6.00（4.8%）     ← 午餐实际是 3.00
晚餐附着油 3.00（2.4%）     ← 与前一项重复
```

- **「西红柿炒蛋」今天根本没吃**。四餐是：红薯+煮蛋+牛奶 / 番茄酸汤牛肋条 / 同锅剩菜+大闸蟹+凉拌菠菜+米饭 / 吾岛酸奶+蓝莓+蜂蜜。
  它自己查证后承认：**来源是 11-14 那天的记忆串档**——用历史记忆去补结构性描述，没回表核对当天菜目。
- **附着油重复计**：午餐 3.00 + 晚餐 3.00 被写成「午餐 6.00」又单列「晚餐 3.00」，这一项变成 9.00，多算 3.00。

它原来那行加总 ≈ 126.01 g，比全天的 125.01 **多出 1.00**——**自己就对不上**。

## 4. 强制校验（写进流程，别靠自觉）

写任何「XX 的构成 / 占比」之前，跑两道闸：

1. **逐餐行和 vs 表内合计**，差值必须 = 0
   ```
   早餐   逐行和 17.29 vs 表内 17.29 ｜+0.00
   午餐v4 逐行和 45.24 vs 表内 45.24 ｜+0.00
   晚餐   逐行和 58.26 vs 表内 58.26 ｜+0.00
   加餐   逐行和  4.22 vs 表内  4.22 ｜+0.00
   四餐合计 125.01
   ```
2. **构成列表加总 = 全天该项总量**，差值必须 = 0
   > 加总对不上就是算错了。126.01 ≠ 125.01 这一条，本来就该在落笔前拦住。

## 5. 两条可直接复用的规则

- **同一道菜分多餐吃 → 先按「同一食材」合并，再算占比。** 不要以单餐为单位做全天描述。
- **凡写「今天吃了什么」的清单，只能从当天档案的原始行取，不许用历史记忆补。**
  子 bot 尤其容易串档（它有几天几周的上下文），主 Hermes 转述前必须回表核。
