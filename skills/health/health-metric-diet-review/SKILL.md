# 体检指标与饮食核算

## 一、铁律（用户明确要求过）

1. **只看原始指标 + 指南参考值，不引用第三方 App 的判断标签。**
   用户原话：「糖尿病前期等都是蚂蚁阿福给我的判断，你只要关注具体指标就好了。」
   → 给数字、给指南条文、给逐项对照，把「归哪一档 / 要不要用药」留给医生。
2. **任何 App 给的合计，一律自己重算。** 实测「蚂蚁阿福」（京东健康）出过两次错：
   - 宏量营养与总热量自相矛盾：98g蛋白 + 210g碳水 + 24g脂肪 = 1448 kcal，它却报 910 kcal（差 538）
   - 把脂肪 24g（0.30 g/kg，不到安全下限 0.6 的一半）评价为「落在正常范围里」
   - 反推技巧：用它的总热量 − 蛋白热量 − 脂肪热量，再 ÷4 得到「隐含碳水」，
     和它自己列的碳水来源比对，就能定位到底哪个数字是错的。
3. **所有算术走工具**（execute_code），不心算。
4. 输出定位是**营养建议，不替代医生**；用药、复查时点、ASCVD 危险分层一律交回医生。
5. 复查节奏提醒：出现胸闷/胸痛/气短/活动耐量下降，立即就医。

## 三、指南参考值速查

**血脂** —《中国血脂管理指南 2023》(参考水平仅适用于 ASCVD 低危人群)
- 降脂目标值：低危 LDL-C <3.4｜中/高危 <2.6｜极高危 <1.8 且降幅>50%
- 指南强调：参考水平只适用低危人群，实际目标须按 ASCVD 危险分层定

**尿酸** —《中国高尿酸血症与痛风诊疗指南 2019》/《多学科专家共识 2023》
- 高尿酸血症诊断：非同日 2 次空腹 >420 μmol/L
- 药物起始阈值：≥540；或 ≥480 且合并高血压/脂代谢异常/糖尿病/肥胖等
- 治疗目标：无合并症 <420｜有合并症 <360
- **肥胖者减重速度：每月 1.5~3.0 kg（= 每周 0.35~0.70 kg）** ← 反推安全热量缺口的关键数字

**血压** —《中国高血压防治指南》/《国家基层高血压防治管理指南 2025》
- 诊室：非同日 3 次 ≥140/90｜家庭自测：≥135/85
- 家庭自测方案：连续 5-7 天，早晚各 1 次，每次 2-3 遍，取**全部读数**平均值
- 诊室≥140/90 而家庭<135/85 → 白大衣性高血压
- 🔴 **但 ABPM（24h 动态血压）是诊断金标准，家庭自测只是「有益的补充」。**
  瑞金医院 2020 年 1067 人研究（《诊断学理论与实践》）：家庭血压诊断白大衣/隐匿性
  高血压**灵敏度仅 43%~86%**（特异度 91%~99%）。
  → **对不愿天天自测的用户，直接推荐 ABPM**：他零操作、更准、挂复查时一起办即可。
  详见 `references/health-data-collection-devices.md`。

**糖代谢** —《中国2型糖尿病防治指南 2020》
- 糖尿病切点：HbA1c ≥6.5%；空腹血糖 ≥7.0；OGTT 2h ≥11.1
- 糖尿病前期：空腹血糖受损 6.1-7.0｜糖耐量减低 OGTT 2h 7.8-11.1

**高尿酸膳食指导** — WS/T 560-2017 + 共识2023
- 能量：超重/肥胖 + 轻体力 20-25 kcal/kg；碳水 50-60%；蛋白 1 g/kg（10-20%）
- 蔬菜 ≥500g/天｜低脂/脱脂奶 300mL/天｜鸡蛋 1个/天｜膳食纤维 25-30g｜饮水 ≥2000mL（尿量 2000-3000mL）

## 五、核算流程

1. 先问/确认**生重还是熟重、带壳还是可食部**——这是最容易错的一步。
   ⚠️ **蛋白粉要问「蛋白重」，不是「勺重」。** 用户答「满一勺 30.4 g」时那是**粉重**，
   必须看包装的「每 100 g 含蛋白质 __ g」：纯乳清 70-80% → 30.4 g 粉 ≈ **21-24 g 蛋白**；
   增肌粉（mass gainer）可能只有 20-30% → **6-9 g 蛋白**，差 3 倍以上且含大量麦芽糊精。
   **不要拿勺重当蛋白重去算。**
2. 逐项列表算，最后和 App 报的数逐项对比，标出偏差方向。
3. 再算四个衍生指标：嘌呤负荷、果糖负荷、饱和脂肪占比、膳食纤维。
4. 最后对照目标给「差多少、补什么、按什么顺序补」。

### 🔴 输出格式：每样食物标数据来源 + 字段必须给齐（2026-10-31 用户纠正）

用户原话：「以后每样食物营养素后面都跟一个数据来源（薄荷库/缓存/…），
另外今天早饭没展示嘌呤」→ 紧接着补一句「也没展示钠等等」。

**这两条是硬要求，不是偏好。** 之前只报「热量/蛋白/脂肪/碳水」四项就被抓了。

**① 每样食物的营养素后面跟来源标签**（方括号，写在该行末尾）：

| 标签 | 含义 |
|:--|:--|
| `〔薄荷·缓存〕` | 命中本地 `cache.json`，本次**没花钱** |
| `〔薄荷·实时〕` | 本次付费 `detail()` 抓的 |
| `〔薄荷·免费〕` | `public_detail()` 免费接口 |
| `〔自建成分表〕` | `fooddb.py` 那 2393 条 |
| `〔表1-2〕` | 《中国食物成分表》标准值推算（薄荷缺失项，**尤其嘌呤**） |
| `〔标签换算〕` | 他给的产品营养标签 |

**② 必给字段**：热量、蛋白、脂肪、碳水、纤维、**钠**、**嘌呤**（他尿酸 454，必看）；
有值的糖、钙、饱和脂肪也带上。**推算值单独标，不许写成薄荷值。**

```
蒸红薯 150g
97.5 卡｜蛋白 1.8｜脂肪 0.1｜碳水 22.6｜纤维 3.4｜钠 61.9 mg〔薄荷·缓存〕
嘌呤 28.5 mg〔表1-2 推算：甘薯(红心) 19.0×1.5〕
```

③ 同一行的数据来源不同时要分开写（如「薄荷·缓存；嘌呤=表1-2」），
   并在合计行下面给一行**来源图例**。落盘的 `diet/YYYY-MM-DD.md` 逐项表也要有「来源」列。

🔴 **别用「占额度 xx%」的预算式语言**评嘌呤/钠——他要的是趋势，不是每顿饭的小数点。
**「占今日目标 23.4%」同样禁止**（2026-11-04 又因这句被退回一次）。

🔴 **禁止用 markdown 表格出回执。** 2026-11-04 健康助理交付的是「食材 | 克 | 热量 | 蛋白 | 脂肪 | 碳水」六列表格，
被当面退回：「健康助理给的回执没按约定好的格式来」。
**「表格」和「每样食物一块」是两种格式，前者会被退**——他要的是一样一行、
数值和来源标签贴在同一个块里，不是横向铺开的账本。

🔴 **格式规则光写在 skill 里不够，必须同时进 health profile 的 MEMORY.md。**
skill 是给主 Hermes 看的，真正出回执的是 health profile 的代理，**它只认自己 memory 里那条**。
2026-11-04 实测：格式要求早就写在本节（10-31 定的），但健康助理的 memory 里从来没有，
于是一年照旧出表格。**规则落在 bot 的 memory 才算生效**；写完还要走「新会话抄原文 + 不带提示真跑」两步验证，
流程见 skill `health-nutrition-analysis` 的 `references/memory-write-then-session-refresh.md`。

派活给 health profile 的任务书模板与验证清单见 `references/nutrition-output-format.md`。

⚠️ **这条格式要求当天被纠正过两次**：先是早饭漏了嘌呤和钠，打完补丁之后午饭又漏了「每样食物的数据来源标签」，
用户原话「你这个午餐没有按照我们刚刚商量好的标准格式给我呀，比如说数据来源是哪里等等」。
→ **写完先自查三件**：① 每样食物都有来源标签？② 纤维/钠/嘌呤三列都在？③ 合计下面有来源图例？
「极简」指的是不要长篇分析，**不是**可以省字段和来源。

### 🔴 有包装营养标签就一定用标签，且必须读到净含量（2026-10-31 实踩，同一天错两次）

**① 包装照片里的营养表经常要转方向、放大才读得出，整图直接问模型会编。**
优形沙拉鸡胸肉的包装背面（旋转 90°、反光、被裁切）先被识别成「蒙牛酸奶 685 g」——
品牌、品类、净含量全是编的，只有 4.8 g 碳水 / 1.8 g 脂肪 / 684 mg 钠碰巧对。
**结果整份档案按薄荷「生鸡胸 118 kcal」算了，钠漏记 15 倍（44.8 vs 684）。**
他一句「鸡胸肉你也按照我发你的图里的来呀，图里有鸡胸肉的营养元素表」才纠回来。

正确读法（PIL，比整图提问准得多）：旋转 90°/270° 各转一遍 → 2× LANCZOS 放大 → 横向分三带裁切 →
逐带问模型「逐字读，看不清就写看不清」→ 定位到营养表那一带再单独放大一次读数字。

**② 读到营养表 ≠ 读全了，净含量必须单独找。** 纠正完营养表又漏了「净含量 180 g」，他补发一张才看见。

规则：
- 他给产品照片 → 先假设「图里可能有营养表」，**先放大读，再决定要不要查库**。读到就跳薄荷，零付费。
- 读表时必须同时抓 **净含量**，并与他口述克数**显式核对**；不一致就单独列出来问他，
  **不要擅自按净含量改**（他这次报 100 g、包装 180 g，按 100 g 记并挂了一条待确认）。
- 自洽校验：`蛋白×4 + 碳水×4 + 脂肪×9 ≈ 能量 kJ ÷ 4.184`，差 >3% 说明有一格读错，回去重读。
- 两次读数不一致时（本例 533 vs 538 kJ），裁到那一行再读第三遍，别取平均。
- 🔴 **净含量在三块区域都读不到时（照片根本没拍到那一栏）的兜底**（2026-11-01 山姆卤汁牛腱）：
  ① 先用**外部资料 + 除法**推一个自洽值（大袋 450 g、独立小包装、经销商标注「单包约 15 g」→ 450÷30=15 g）；
  ② 主值照推出来的算，但**必须给低/主/高三档敏感性**，并在档案里写明「不是包装读数，是推的」；
  ③ **单独问他一句**（「大袋多少克、里面几小袋？」——这是他能直接看的），
  他确认后立刻把主值标成「已确认」，三档降级为「仅备查，不采用」。
  ④ 别因为读不到就拿品类均值顶（牛腱 760 mg 钠/100 g，用「牛肉干」均值会差一截）。
- 「即食/调味肉制品」和「生鲜肉」是两个口径：鸡胸 生 → 即食，钠 44.8→684 mg、碳水 0.6→4.8 g，
  **热量差得不多但钠差一个数量级**，用错条目整天的钠账就废了。

### 🔴 派活被打断 → 档案会「半新半旧」，验收要覆盖下游小节

2026-10-31 一次性派活中途被打断，落地结果是：**「午餐」节已改成标签值，「全天合计」整节还是旧数**
（967.03 / 钠 1595.62 是生鸡胸时代的数）。档案看起来完整，其实自相矛盾。

**验收义务（比「重算一遍」更进一步）**：
1. 不只看它说改了哪一节，**把所有依赖这次改动的下游小节逐个读回来**
   （改午餐 → 必须核「全天合计」的热量/蛋白/脂肪/碳水/钠/嘌呤六项都等于 早餐＋午餐）。
2. 硬校验：`全天热量 == 早餐小计 + 午餐小计`，一行算式对不上就是没同步。
### 🔴 派活的运行机制：后台 + 落日志 + 短窗轮询（2026-11-01 定型）

派给 health profile 的一次 `-Q` 调用**实测要 100–300 秒**（多条目查库+拆原料会更久），
前台调用一旦被打断就会留下半新半旧的档案。固定姿势：

```bash
# 1) 后台跑，输出直接落日志
hermes -p health chat -c "Bot Chat" -Q --query-file "C:/Users/.../_task_xxx.md" \
  > ~/health/records/_out_xxx.log 2>&1   # terminal(background=true, notify=true)

# 2) 轮询：每 15s 查一次 PID 是否还在，单次 execute_code 不要超过 ~250s
powershell -c "Get-Process -Id <pid> -ErrorAction SilentlyContinue | Select-Object -First 1 Id"

# 3) 读完 log，再自己 read_file 档案复算，最后删 _task_*.md 和 _out_*.log
```

- 🔴 **`execute_code` 单次上限 300s**：一次 cell 里死等 300s 会 `Cell timed out` 并**丢掉 kernel 状态**

### 🔴 他自己给出的归因，要用「历史中位数」拆半核（2026-11-01）

| 他的说法 | 当天实际 | 倍数 | 判定 |
|:--|--:|--:|:--|
| 钠会少很多 | 1791.7 | 2.08× | ✅ **成立** |
| 嘌呤会少很多 | 264.1 | 0.93× | ❌ **不成立**，比平时还低 |

再做一步反事实：把午餐换成中位数 →

→ 真实杠杆是「钠由加工品＋酱油驱动、嘌呤由单餐肉量驱动」，**不是「在外面吃」**。

**附一条反例**：10-30 他在食堂「正常吃」的那顿午餐钠 **2106.8**，比「外面对付」的还高。
→ **看点了什么，不看在哪吃。**

### 🔴 「超的算不算多」——总量类指标不看占比（2026-11-04）

他会用「我吃了这么多，超一点应该算少吧」给超标项找缓冲。原话：

> 「虽然钠和嘌呤还是比建议的超了一点，但超的应该在我这么多饮食里边应该也算少的是不是？」

**这类问题必须拆两层答，而且两层常常一层成立一层不成立：**

1. **先分餐次**——他问的「今晚」和「全天」答案可能相反。
   2026-11-04 实测：晚饭钠 769.20 / 嘌呤 188.36 都在线内（**这顿成功**），
   但全天钠 3529.10 / 嘌呤 604.96 双破——**破在午餐**（占全天钠 62.2%、嘌呤 57.6%）。
   「一顿拖垮一天」和「一天都吃咸了」是两种结论，前者改一处就够。
2. **再答占比**——钠、嘌呤是**总量类指标，生理上不存在「摊薄」**：
   钠的开压是剂量-反应、肾脏排钠限速；嘌呤决定尿酸生成的是绝对 mg。
   能被归一化的只有**脂肪供能比、蛋白 g/kg、钠钾比**这类分母本身被设计进去的指标。
   **反直觉的一点**：吃得更少（热量低）不会让占比好看，只会更难看——
   2026-11-04 钠密度 2.073 mg/千卡，是他自己口径 0.964 的 **2.15 倍**。

**不要顺着说「还好」。** 数据说成功就说成功（那天蛋白 128.83/129 确实成功），
失守就说失守（钠折盐 8.82 g，超 3.82 g）。「总体还行但要因人而异」这种和稀泥会被嫌。

⚠️ **但必须分清“带病指标”和“健康指标”**：不是所有超标都同等严重。
他尿酸 454（离药物门槛 480 差 26）、舒张压压线 90、主动脉弓胾化、脂肪肝——
**钠是这几样共同的放大器，也是他完全能自己控制的一项**，它比嘌呤更值得当回事。

### 🔴 条目 `units` 字段决定它是不是「你吃的那种做法」（2026-11-13 用户质疑炸蛋）

用户问「一碗加辣椒油的螺蛳粉 + 一个炸蛋 + 一个虎皮鸡爪多少卡」，第一轮用
`fd8fd709`「炸蛋」224 卡/100 g、units「个＝56 g」→ 125.44 卡。用户当场质疑：

> 「你确定一个炸蛋只有125大卡吗？我想问的是外面螺蛳粉的炸蛋那么圆圆的一个多少
> 而不是说把一个鸡蛋做成炸蛋，他有多少？」

**判断一个条目匹不匹配，看两件事：`units` 的定义 + 折算出的「额外油量」。**

| 条目 | 每100g热量 | 脂肪 | units | 折一颗蛋的**额外油** |
|:--|--:|--:|:--|--:|
| `fd8fd709` 炸蛋 | 224 | 19.0 | 个＝56 g | **5.82 g** ← 煎蛋/浅炸量级 |
| `hebaodan_youjian` 煎蛋 | 195 | 15.0 | 个＝60 g | 4.18 g |
| `fdac7eb9` 安井 虎皮炸蛋 | 610 | 59.6 | 份＝450 g | 28.56 g ← 裹面糊冷冻预制 |
| `fd737607` 海霸王 虎皮炸蛋 | 654 | 64.4 | 份＝90 g | 31.24 g ← 同上，一个 90 g 就 588 卡 |

深油锅炸到蓬发的蛋**库里没有对应条目**，必须拆项：蛋液 56 g（≈80 卡）＋ 吸油量。
同理：螺蛳粉 `fd3ab954` 134 卡/100 g、units「份 445 g」，脂肪只 6.1 g/100 g（445 g 才 27 g）——
它到底是不是含炸腐竹/花生/红油的整碗，要靠**用条目自己的脂肪数反算配菜装不装得下**来判断，
不要凭「感觉偏低」就断言是清汤口径（下节）。

#### 🔴 油炸食品的重量账：`成品重 − 原料重 = 吸油量` 是错的，漏了失水

**正确公式：`成品重 = 原料重 + 留住的油 − 失水`。**
第一轮拆项时用「成品 71 g − 蛋液 56 g = 吸油 15 g」反推，被 GPT 核对抓出：
56 + 15 − 0 = 71 要求**一滴水都没失**，深炸不可能；实际 56 + 15 − 10 = 61 g。
**炸得鼓 ≠ 变重**——蓬发是内部孔洞，不是重量增加。所以既不能由「圆圆蓬发」推成品 71 g，
也不能凭炸前炸后重量差算吸油量。

可用的吸油率参考：台湾教育部委托编写的油脂教学手册把清炸「炸蛋」吸油率列为
**约 15%**（原料重 × 吸油率），56 g → 8.4 g 油 → 约 156 卡。
**但那是教学参考，不是螺蛳粉店蓬发炸蛋的实测**，只能当区间下沿。

### 🔴 数字被质疑时的二次核对流程（2026-11-13 定型）

## 十、餐后血糖：本用户的核心矛盾与削峰手段优先级

完整推导与文献原文见 `references/postprandial-glucose-and-lipid-evidence.md`。

**「空腹正常 + 糖化偏高」的判读模板**

- 空腹血糖 = **瞬间快照**；HbA1c = **过去 2-3 个月的加权平均**，
  且**不是等权**：0-30 天占 **50%**、31-60 天 25%、61-90 天 25%
  （Tahara & Shima 1995，半衰期约 34.6 天）
- 换算：`eAG(mg/dL) = 28.7 × A1c − 46.7`，再 `÷18.0182` 得 mmol/L
  （5.0%→5.4｜6.0%→7.0｜**6.3%→7.44**｜6.5%→7.8 mmol/L）
- 若空腹 5.0 而 A1c 6.3%（eAG 7.44）→ 反推白天均值必须 ≈8.7 →
  **问题全在餐后，而常规体检只查空腹，结构性看不见** → **OGTT 2h 是第一优先检查**
- **加权权重还能用来隔离「非典型时期」**：他 2026 年 9 月放纵（含 9/26-10/5 每天 2-3 杯奶茶）
  占总权重 **50.8%** → 这次 6.3% 有一半来自非典型时期，**不代表常态**。
  但结论不是「那没事了」：血糖调节正常者连喝 10 天全糖奶茶 A1c 通常也只到 5.3-5.7
  → **放纵期是「暴露」不是「造成」**。

|:--|:--|:--|
| 每天早晚量血压并手动录入 App | 「每天都要量，量完还要手动输，还要早晚各一次，这我做不到呀」 | 把**采集**和**录入**两步都压在用户身上 |
| 每月截图手表关键指标 | 「那个曲线他又不标坐标系的，你压根都看不出来内容呀」 | **无坐标轴的曲线截图无法 OCR 出数值**——数据源本身不含可读数字 |

**修正后的原则：**
1. **优先选「用户零操作」的源**（ABPM 是典型：去医院戴一天，他一次都不用动手）
2. **设备自带的存储/同步要先用尽** —— 带蓝牙的血压计测完自动进 App，
   「手动录入」这一步就不存在。别在还没用尽设备能力时就要求人工补位
3. **只接受带具体数值的页面**，不接受无坐标轴的曲线截图
4. **频率跟着生理变化的尺度走**：糖化本身就是 2-3 个月均值、血脂尿酸复查周期 3 个月
   → 全量导出 **3-6 个月一次**足够；每月申请只会拿到大量重复 + 每次等 7 天
   **更关键：每天投喂数据会淹没信号。健康助理要的是趋势，不是脉搏。**

### 闸门 3：这条路是「探路」还是「已验证」？

**不确定包含范围时，明说是探路，并让用户只做一次**，拿到结果再决定要不要继续。
本会话对「隐私中心数据副本」就是这么说的：公开资料只明确含运动记录，
「睡眠/心率这些日常数据在不在里面」**我不确定** → 所以第一次是探路。

⚠️ **用户自己认可的那条路才值得投入。** 他明确说「隐私中心就是比较麻烦，
但是它确实是数据比较真实完整的能导出来」——
**他愿意为完整性付麻烦，不愿为便利反复操作。** 这两者的区别是本节的题眼。
