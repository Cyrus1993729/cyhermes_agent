# 体检指标与饮食核算

## 一、铁律（用户明确要求过）

1. **只看原始指标 + 指南参考值，不引用第三方 App 的判断标签。**
   用户原话：「糖尿病前期等都是蚂蚁阿福给我的判断，你只要关注具体指标就好了。」
   → 给数字、给指南条文、给逐项对照，把「归哪一档 / 要不要用药」留给医生。
2. **任何 App 给的合计，一律自己重算。** 实测「蚂蚁阿福」（京东健康）出过两次错：
   - 宏量营养与总热量自相矛盾：98g蛋白 + 210g碳水 + 24g脂肪 = 1448 kcal，它却报 910 kcal（差 538）
   - 把脂肪 24g（0.30 g/kg，不到安全下限 0.6 的一半）评价为「落在正常范围里」
   - 反推技巧：用它的总热量 − 蛋白热量 − 脂肪热量，再 ÷4 得到「隐含碳水」，
     和它自己列的碳水来源比对，就能定位到底哪个数字是错的。
3. **所有算术走工具**（execute_code），不心算。
4. 输出定位是**营养建议，不替代医生**；用药、复查时点、ASCVD 危险分层一律交回医生。
5. 复查节奏提醒：出现胸闷/胸痛/气短/活动耐量下降，立即就医。

## 三、指南参考值速查

**血脂** —《中国血脂管理指南 2023》(参考水平仅适用于 ASCVD 低危人群)
- 降脂目标值：低危 LDL-C <3.4｜中/高危 <2.6｜极高危 <1.8 且降幅>50%
- 指南强调：参考水平只适用低危人群，实际目标须按 ASCVD 危险分层定

**尿酸** —《中国高尿酸血症与痛风诊疗指南 2019》/《多学科专家共识 2023》
- 高尿酸血症诊断：非同日 2 次空腹 >420 μmol/L
- 药物起始阈值：≥540；或 ≥480 且合并高血压/脂代谢异常/糖尿病/肥胖等
- 治疗目标：无合并症 <420｜有合并症 <360
- **肥胖者减重速度：每月 1.5~3.0 kg（= 每周 0.35~0.70 kg）** ← 反推安全热量缺口的关键数字

**血压** —《中国高血压防治指南》/《国家基层高血压防治管理指南 2025》
- 诊室：非同日 3 次 ≥140/90｜家庭自测：≥135/85
- 家庭自测方案：连续 5-7 天，早晚各 1 次，每次 2-3 遍，取**全部读数**平均值
- 诊室≥140/90 而家庭<135/85 → 白大衣性高血压
- 🔴 **但 ABPM（24h 动态血压）是诊断金标准，家庭自测只是「有益的补充」。**
  瑞金医院 2020 年 1067 人研究（《诊断学理论与实践》）：家庭血压诊断白大衣/隐匿性
  高血压**灵敏度仅 43%~86%**（特异度 91%~99%）。
  → **对不愿天天自测的用户，直接推荐 ABPM**：他零操作、更准、挂复查时一起办即可。
  详见 `references/health-data-collection-devices.md`。

**糖代谢** —《中国2型糖尿病防治指南 2020》
- 糖尿病切点：HbA1c ≥6.5%；空腹血糖 ≥7.0；OGTT 2h ≥11.1
- 糖尿病前期：空腹血糖受损 6.1-7.0｜糖耐量减低 OGTT 2h 7.8-11.1

**高尿酸膳食指导** — WS/T 560-2017 + 共识2023
- 能量：超重/肥胖 + 轻体力 20-25 kcal/kg；碳水 50-60%；蛋白 1 g/kg（10-20%）
- 蔬菜 ≥500g/天｜低脂/脱脂奶 300mL/天｜鸡蛋 1个/天｜膳食纤维 25-30g｜饮水 ≥2000mL（尿量 2000-3000mL）

## 五、核算流程

1. 先问/确认**生重还是熟重、带壳还是可食部**——这是最容易错的一步。
   ⚠️ **蛋白粉要问「蛋白重」，不是「勺重」。** 用户答「满一勺 30.4 g」时那是**粉重**，
   必须看包装的「每 100 g 含蛋白质 __ g」：纯乳清 70-80% → 30.4 g 粉 ≈ **21-24 g 蛋白**；
   增肌粉（mass gainer）可能只有 20-30% → **6-9 g 蛋白**，差 3 倍以上且含大量麦芽糊精。
   **不要拿勺重当蛋白重去算。**
2. 逐项列表算，最后和 App 报的数逐项对比，标出偏差方向。
3. 再算四个衍生指标：嘌呤负荷、果糖负荷、饱和脂肪占比、膳食纤维。
4. 最后对照目标给「差多少、补什么、按什么顺序补」。

**嘌呤估算**（mg/100g）：虾 150、红肉 105、鱼 105、鸡 60、豆腐 40、蔬菜 25、谷薯 20、蛋奶 ~0
阈值：高尿酸者 <400/天，有痛风史 <200。

**果糖**：西瓜 3.5、苹果 5.5（g/100g）。阈值：脂肪肝/高TG <25-30 g/天。
⚠️ 果糖危害主要针对**添加糖/含糖饮料**，不是天然水果——
《共识2023》明确把**西瓜**列在「可食用含果糖较少的水果」里（同列樱桃、草莓、菠萝、桃子）。
不要因为果糖就把水果妖魔化，这是我犯过的归因错误。

## 六、已被证实的关键风险（针对这位用户）

1. **快速减重 → 尿酸↑**：酮体与尿酸竞争肾排泄，是诱发痛风急性发作的经典场景。
   指南给的安全速度是每周 0.35-0.70 kg（每月 1.5-3.0 kg）。
   实测他一天吃 1370 kcal → 每周减 1.16 kg，超上限 1.7 倍。
2. **低脂高碳 → TG↑**：极低脂饮食会升高甘油三酯。他 TG 3.27 已高，
   补热量必须同时补「不饱和脂肪 + 蛋白」，**不能只加主食**。
3. **低脂 + 快速减重 → 胆结石风险↑**（胆囊收缩减少 + 快速减重）。
4. **蛋白来源决定尿酸走向**：乳制品促进尿酸排泄；虾贝/红肉/内脏是嘌呤大户。
   蛋白总量可以到 1.4-1.5 g/kg，但来源必须换成奶、蛋、豆腐、白肉。
5. 指南实用技巧：**海产品、肉类煮后弃汤可显著减少嘌呤**（虾汤肉汤别喝）。

## 十、餐后血糖：本用户的核心矛盾与削峰手段优先级

完整推导与文献原文见 `references/postprandial-glucose-and-lipid-evidence.md`。

**「空腹正常 + 糖化偏高」的判读模板**

- 空腹血糖 = **瞬间快照**；HbA1c = **过去 2-3 个月的加权平均**，
  且**不是等权**：0-30 天占 **50%**、31-60 天 25%、61-90 天 25%
  （Tahara & Shima 1995，半衰期约 34.6 天）
- 换算：`eAG(mg/dL) = 28.7 × A1c − 46.7`，再 `÷18.0182` 得 mmol/L
  （5.0%→5.4｜6.0%→7.0｜**6.3%→7.44**｜6.5%→7.8 mmol/L）
- 若空腹 5.0 而 A1c 6.3%（eAG 7.44）→ 反推白天均值必须 ≈8.7 →
  **问题全在餐后，而常规体检只查空腹，结构性看不见** → **OGTT 2h 是第一优先检查**
- **加权权重还能用来隔离「非典型时期」**：他 2026 年 9 月放纵（含 9/26-10/5 每天 2-3 杯奶茶）
  占总权重 **50.8%** → 这次 6.3% 有一半来自非典型时期，**不代表常态**。
  但结论不是「那没事了」：血糖调节正常者连喝 10 天全糖奶茶 A1c 通常也只到 5.3-5.7
  → **放纵期是「暴露」不是「造成」**。

|:--|:--|:--|

## 十一、🔴 主矛盾优先 —— 不要在次要变量上做优化

**本会话踩过的坑（用户当场纠正）**：我建议把「贝贝南瓜」换成「普通南瓜」以降 GI，
用户反问「我保持现在的贝贝南瓜不就是可以保证我碳水摄入够吗？你判断一下我现在的身体状况，
吃它是不是也可以」。重算后确认**我排错了优先级**：

```
他的目标：2000 kcal / 蛋白 129g / 碳水 220g / 脂肪 67g
他实际吃：1370 kcal / 蛋白 116g / 脂肪  31g
缺口：    热量 −630       脂肪 −36g
→ 【核心矛盾是「吃得不够」，不是「吃得太精」】
```
我为了把 GL 从 28 降到 11，让他把早餐碳水砍掉一半、热量再往下走 ——
**在小变量上用力，在主矛盾上失分。**

**规则：**
1. **动手前先算「目标 vs 实际」的缺口**，缺口最大那一项才是要优化的变量。
2. 用户对「我现在的做法不也可以吗」式的反问，当作**优先级质疑**处理 ——
   停下来重算主矛盾，不要重复论证原建议。他用直觉质疑且常正确。
3. GL 只用来分档（高 ≥20 / 中 11-20 / 低 <11），**不要为了让 GL 掉档而牺牲总摄入**。

**GL 速查**（GL = 碳水 g × GI）：
白米饭 200g = 41.5｜白粥 400g = 31.7｜贝贝南瓜 200g = **28.0**（白米饭的 67%，但比燕麦高一倍）｜
蒸红薯 200g = 25.3｜燕麦 40g 干 = 13.2｜蒸山药 200g = 12.6｜普通南瓜 200g = 8.0

⚠️ 贝贝南瓜碳水 20g/100g，与白米饭 25g/100g **只低 20%**，有纤维/钾/β-胡萝卜素但
**不是低 GI 粗粮**；普通南瓜碳水 5.3g/100g，更接近**蔬菜**而非主食（换掉它会连带把主食拿掉）。
想真降 GI 用燕麦/糙米/藜麦/山药；**燕麦要买传统燕麦片/钢切燕麦（GI≈55），
不要即食燕麦/麦片饮（GI 常 >70）**。

## 十二、🔴 数据采集方案的设计原则（本会话连被否掉三条后的教训）

用户会主动提「想把某个设备的数据接进来给你」。**提方案前先过三道闸门**，
否则会连出数个不落地的方案（本会话实测）。设备事实与路径见
`references/health-data-collection-devices.md`。

### 闸门 1：这个数据能闭合哪个**未决问题**？

**按「能回答什么」排序，不要按「能拿到什么」排序。**

本会话错误：我按 WATCH 5 能导出什么列了一串（静息心率/HRV/睡眠/血氧/ECG），
而用户实际卡住的是三个问题：

```
① 餐后血糖到底多高   → 手表答不了（要靠 OGTT / CGM）
② 血压到底是不是真高 → 手表答不了（要靠 ABPM / 血压计）
③ 家族史有没有遗传   → 手表答不了（要问他父母）
```

手表能给的那几项，对他的处境全是「有了更好、没有也行」：血氧正常；
**无胸痛无胸闷故 ECG 无指征**；静息心率/HRV **没有临床决策价值**
（不会因为它高一点低一点就改变该做什么）。
→ **数据源的边际价值 = 它能闭合几个未决问题，不是它能吐多少字段。**

### 闸门 2：用户的**执行成本**是多少？

**任何需要用户持续手动操作的数据管线，默认不成立。** 本会话被当场否掉两条：

| 我提的方案 | 用户原话 | 真实问题 |
|:--|:--|:--|
| 每天早晚量血压并手动录入 App | 「每天都要量，量完还要手动输，还要早晚各一次，这我做不到呀」 | 把**采集**和**录入**两步都压在用户身上 |
| 每月截图手表关键指标 | 「那个曲线他又不标坐标系的，你压根都看不出来内容呀」 | **无坐标轴的曲线截图无法 OCR 出数值**——数据源本身不含可读数字 |

**修正后的原则：**
1. **优先选「用户零操作」的源**（ABPM 是典型：去医院戴一天，他一次都不用动手）
2. **设备自带的存储/同步要先用尽** —— 带蓝牙的血压计测完自动进 App，
   「手动录入」这一步就不存在。别在还没用尽设备能力时就要求人工补位
3. **只接受带具体数值的页面**，不接受无坐标轴的曲线截图
4. **频率跟着生理变化的尺度走**：糖化本身就是 2-3 个月均值、血脂尿酸复查周期 3 个月
   → 全量导出 **3-6 个月一次**足够；每月申请只会拿到大量重复 + 每次等 7 天
   **更关键：每天投喂数据会淹没信号。健康助理要的是趋势，不是脉搏。**

### 闸门 3：这条路是「探路」还是「已验证」？

**不确定包含范围时，明说是探路，并让用户只做一次**，拿到结果再决定要不要继续。
本会话对「隐私中心数据副本」就是这么说的：公开资料只明确含运动记录，
「睡眠/心率这些日常数据在不在里面」**我不确定** → 所以第一次是探路。

⚠️ **用户自己认可的那条路才值得投入。** 他明确说「隐私中心就是比较麻烦，
但是它确实是数据比较真实完整的能导出来」——
**他愿意为完整性付麻烦，不愿为便利反复操作。** 这两者的区别是本节的题眼。
