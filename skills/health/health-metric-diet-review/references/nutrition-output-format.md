# 健康助理派活：任务书模板 + 输出格式 + 验证清单

主 Hermes 不做健康判断，只把活派给 health profile。派活的成败几乎全在**任务书**上。

## 一、调用方式

```bash
hermes -p health chat -c "Bot Chat" -Q --query-file "C:/Users/Administrator/health/_task_xxx.txt"
```

- **长 prompt 必须走 `--query-file`**，不要 `$(cat file)` 塞进命令行。
- 路径给**正斜杠的 native 风格**（`C:/...`），MSYS 的 `/c/...` 传给它认不出。
- `-c "Bot Chat"` 是 bot 的 canonical 会话；**找不到同名会话是 fail loudly（exit 1）**，
  要程序化兜底得加 `--create-if-missing`（详见 skill `hermes-context-partitioning`
  的 `references/canonical-bot-chat-compaction.md`）。
- 跑完把临时任务书删掉，别在 `~/health/` 里留垃圾。

## 二、任务书模板（口述记录一顿饭）

```
【任务】记录今天的早餐并落盘。日期：YYYY-MM-DD（周X）。

【他口述吃了什么】（原话：「……」）
- 食物 + 克数（逐条列）
- 有歧义的口径在这里钉死（例：牛奶按**全脂纯牛奶**，不许按脱脂/低脂）

【做法】
1. 走「口述直录」：跳过识别和确认卡，直接 boohee.two_step(菜名, 克数, context="早/午/晚")。
2. 薄荷付费调用上限 = 样数。用完仍查不到就用自建成分表并标注来源，不许伪装成薄荷数据。
3. 写进 ~/health/diet/YYYY-MM-DD.md，按固定结构。
4. 写完**从磁盘读回来验算**：蛋白×4 + 碳水×4 + 脂肪×9 要等于总热量，对不上就重算。
5. 查不到或置信度低的项单独点出来，不许悄悄吞掉。

【返回给我】只回极简结果：逐项热量/蛋白/脂肪/碳水 + 合计 + 一句话点评。不要贴整份档案。
```

**任务书里必须写死的三件事**：口径（全脂/生熟/去壳）、付费上限、落盘路径。
这三样一旦含糊，回来的数就是错的，而且看不出错在哪。

## 三、输出格式（用户 2026-10-31 纠正，硬要求）

- **每样食物的营养素后面跟来源标签**：`〔薄荷·缓存〕`/`〔薄荷·实时〕`/`〔薄荷·免费〕`/
  `〔自建成分表〕`/`〔表1-2〕`/`〔标签换算〕`。
- **字段给齐**：热量、蛋白、脂肪、碳水、纤维、钠、**嘌呤**；有值的糖、钙、饱和脂肪也带。
  只报「热量/蛋白/脂肪/碳水」四项会被当场退回来。
- **推算值单独标**，不许把 `表1-2` 的嘌呤写成薄荷值。

## 四、验证清单（不能只信子实例的自报）

1. `read_file` 打开 `~/health/diet/YYYY-MM-DD.md`，**逐项复算**（克数 × 每100g 原值）。
2. 加总核对：各分项之和 = 合计行。
3. 算术自检：蛋白×4 + 碳水×4 + 脂肪×9 ≈ 总热量（±5%）。
4. 落盘文件里该有：薄荷 code、来源列、数据质量提示、`仅含已报餐次` 的标注。
5. 回复用户前**自己再过一遍数字**——他拿 App 核对条目，错一个数会被当场抓。
