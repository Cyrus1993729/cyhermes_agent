# 把健康/饮食核算派给健康助理 bot

> 🔴 **铁律：主 Hermes 不做任何营养核算。** 一切饮食、热量、营养素、体检指标相关的计算与判断，**一律派给 health profile 的 bot**，主 Hermes 只负责：抓食材/菜谱信息 → 写任务书 → 跑命令 → **原样转述它的回执**。

用户 2026-11-17 当场所确认：「这些你都是应该就跟饮食有关的，你都都应该交给健康助理这条目前应该是执行的对吧？」——是的，这是常驻规则。

## 一、派活命令

```bash
hermes -p health chat -c "Bot Chat" -m deepseek-v4.1-flash -Q \
  --query-file "<任务书绝对路径>" > "$LOCALAPPDATA/Temp/health_<主题>_<日期>.txt" 2>&1
```

- `-c "Bot Chat"` 是**保留会话**，它记得前面几轮的口径，不用重复交代背景
- **任务书必须落成文件再用 `--query-file`**，不要用 `$(cat f)` 或长 heredoc
- 用 `terminal(background=true, notify=true)` 跑，别前台干等（一次派活常 2–5 分钟）
- ⚠️ **同一个 `Bot Chat` 会话不要并发派活**——会串。要并行就排队串行，或另开会话名（会丢上下文，不推荐）

## 二、任务书八段（缺一段就会出偏差）

复制 `templates/task-brief.md` 改。八段固定是：

1. **任务一句话** + 是「只核算」还是「要落盘」
2. **日期与档案现状**：`~/health/diet/YYYY-MM-DD.md`、字节数、mtime、**已有小节标题全列出来**
3. **用户原话逐字**（标明未改写）——它要靠原话判断口径
4. **食材/数据表**：每样标「他说」还是「估算」，包装照片给绝对路径（让它自己走 `recognize.py`，**别用主 Hermes 的识图结果**）
5. **核算口径**：分份方式、用油、调料、生熟重、哪些乘几分之一
6. **禁止项**（见下节，每次都写）
7. **交付格式**：逐项一行＋字段齐＋来源标签＋数据完整性＋换算过程
8. **收尾必须自报边界**：调 `stat` 报字节数/mtime 证明哪些文件没动

> 写任务书时**别把自己的机制推测塞进去**。本次踩过：把「2 个番茄吃一半」误标成与档案矛盾，它顺着照办——**主 Hermes 的判断错误会被它自动继承**。拿不准就并列两种可能让它判。

## 三、禁止项清单（每次都带上）

```
- 本轮只核算，不写任何文件（diet/ reviews/ profile.md skill 全不许动）
- 收尾自报「本轮没有写任何文件」+ stat 回读字节数/mtime 作证
- 不写劝诫（禁止「建议您」「要注意」）
- 不评价食谱/饮食好坏，他问什么答什么
- 「打算吃/要吃」≠已吃 —— 尚未发生的餐只做推演，绝不进当天合计
- 库内没有的就写「无法判定」，不许用均值/估算硬填
- 先看 boohee quota.json，额度紧张走全免费路径
```

## 四、两段式入档（他的硬规矩）

```
① 核算稿（不落盘）→ 主 Hermes 原样贴回执
② 他说「写 / 存档 / 你肯定要写进档案呀」→ 才派第二轮写入
③ 写入后重出当日汇总（见下）
```

**「记完即重出当日汇总」**：只加晚餐不重算汇总 = 没记完。写入轮的汇总小节标题时间戳要跟着更新。

**新餐次要独立成节**：多加一顿就新建 `## 加餐2（口述直录）`，**已存在的加餐/晚餐小节一个字不许动**（否则没法对账）。

## 五、主 Hermes 必须独立复核（不能只听它说）

回执里的「已写入 ✓」是自报，不是事实。**每次写入后自己跑一遍**：

```bash
cd ~/health && stat -c '%n %s %y' diet/YYYY-MM-DD.md profile.md
grep -n "^## " diet/YYYY-MM-DD.md
python tools/verify_diet_tables.py diet/YYYY-MM-DD.md | tail -8
```

两三秒的事，能抓住「汇总没更新」「只改了标题没写表」「profile 被顺手改了」这类问题。

## 六、回执转述要求

- **原样贴，禁压成摘要句**（踩过：午餐回执被摘要，他说没看到回执）
- 它给的来源标签（`〔薄荷·实时〕`/`〔表1-2 ‡〕`/`〔估算〕`/`〔标签换算〕`）、算术自检、数据完整性、边界自查**全部保留**
- Telegram 长文会被网关自动分段，不用担心 4096 上限
- 🔴 **记账/核算回执一律不建 md、不发 MEDIA**（他 2026-11-17 当场质问「你为啥突然做了个 md 文档呢」）。只有他明确要一个文件时才建档

## 七、已知工具坑

| 坑 | 症状 | 处理 |
|:---|:---|:---|
| `verify_diet_tables.py` 餐次正则 | 只认 `早餐\|午餐\|加餐\|夜宵`，出现「晚餐」「加餐2」时整行被跳过 → 累计块**误报 FAIL** | 正则用 `加餐[0-9]?\|晚餐[0-9]?`；餐次列表改成 `[k for k in rows if k != '累计']` 才是根治 |
| skills 下同名校验器副本 | `skills/health/health-nutrition-analysis/scripts/` 里那份是旧的，跑到会误报 | 以 `~/health/tools/` 那份为准 |
| 库值异常不是录入错误 | 豆制品维生素E 报 17.8 mg/100g，看着像错，其实忠实抄自成分表 | 有出处就不改数，走覆盖层排除：`fooddb/anomaly_registry.json` + `tools/anomaly_fix.py`。**改缓存是假修**（薄荷每次实时拉） |
| 报 FAIL 先判是不是校验器缺陷 | 各表都 ✓ 但累计块 ✗ | 用同一份文本独立复算一遍，确认是校验器问题再报给用户 |

## 八、播报节奏

- 接活先应答（收到 + 怎么拆），再动工具
- 派活后说清「我给它划了哪几条线」，比干等有用
- 结果回来**原样贴**，末尾附「我自己占的是什么」
- 悬而未决的事（目标要不要改、要不要写入）每次收尾列一行，别让它飘着
