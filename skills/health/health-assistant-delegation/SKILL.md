# 把健康/饮食核算派给健康助理 bot

> 🔴 **铁律：主 Hermes 不做任何营养核算。** 一切饮食、热量、营养素、体检指标相关的计算与判断，**一律派给 health profile 的 bot**，主 Hermes 只负责：抓食材/菜谱信息 → 写任务书 → 跑命令 → **原样转述它的回执**。

用户 2026-11-17 当场所确认：「这些你都是应该就跟饮食有关的，你都都应该交给健康助理这条目前应该是执行的对吧？」——是的，这是常驻规则。

## 一、派活命令

```bash
hermes -p health chat -c "Bot Chat" -m deepseek-v4.1-flash -Q \
  --query-file "<任务书绝对路径>" > "$LOCALAPPDATA/Temp/health_<主题>_<日期>.txt" 2>&1
```

- `-c "Bot Chat"` 是**保留会话**，它记得前面几轮的口径，不用重复交代背景
- **任务书必须落成文件再用 `--query-file`**，不要用 `$(cat f)` 或长 heredoc
- 用 `terminal(background=true, notify=true)` 跑，别前台干等（一次派活常 2–5 分钟）
- ⚠️ **同一个 `Bot Chat` 会话不要并发派活**——会串。要并行就排队串行，或另开会话名（会丢上下文，不推荐）

## 二、任务书八段（缺一段就会出偏差）

复制 `templates/task-brief.md` 改。八段固定是：

1. **任务一句话** + 是「只核算」还是「要落盘」
2. **日期与档案现状**：`~/health/diet/YYYY-MM-DD.md`、字节数、mtime、**已有小节标题全列出来**
3. **用户原话逐字**（标明未改写）——它要靠原话判断口径
4. **食材/数据表**：每样标「他说」还是「估算」，包装照片给绝对路径（让它自己走 `recognize.py`，**别用主 Hermes 的识图结果**）
5. **核算口径**：分份方式、用油、调料、生熟重、哪些乘几分之一
6. **禁止项**（见下节，每次都写）
7. **交付格式**：逐项一行＋字段齐＋来源标签＋数据完整性＋换算过程
8. **收尾必须自报边界**：调 `stat` 报字节数/mtime 证明哪些文件没动

> 写任务书时**别把自己的机制推测塞进去**。本次踩过：把「2 个番茄吃一半」误标成与档案矛盾，它顺着照办——**主 Hermes 的判断错误会被它自动继承**。拿不准就并列两种可能让它判。

> 🔴 **「档案已有小节」必须实读，不许凭印象写。** 2026-11-18 踩过：任务书里写「早/午/加餐/晚餐四段已入档」，当天档案根本没有晚餐节（16:43 时只有早餐/午餐/加餐）。写任务书前**先跑一遍** `grep -n '^## ' diet/YYYY-MM-DD.md`，把实际小节标题和行号原样抄进任务书第二段。这次 bot 没顺着错话建空节、反而如实写「晚餐未报」，是运气不是流程——机制性错误它一般会照办。

## 三、禁止项清单（每次都带上）

```
- 本轮只核算，不写任何文件（diet/ reviews/ profile.md skill 全不许动）
- 收尾自报「本轮没有写任何文件」+ stat 回读字节数/mtime 作证
- 不写劝诫（禁止「建议您」「要注意」）
- 不评价食谱/饮食好坏，他问什么答什么
- 「打算吃/要吃」≠已吃 —— 尚未发生的餐只做推演，绝不进当天合计
- 库内没有的就写「无法判定」，不许用均值/估算硬填
- 先看 boohee quota.json，额度紧张走全免费路径
```

## 四、两段式入档（他的硬规矩）

```
① 核算稿（不落盘）→ 主 Hermes 原样贴回执
② 他说「写 / 存档 / 你肯定要写进档案呀」→ 才派第二轮写入
③ 写入后重出当日汇总（见下）
```

**「记完即重出当日汇总」**：只加晚餐不重算汇总 = 没记完。写入轮的汇总小节标题时间戳要跟着更新。

**新餐次要独立成节**：多加一顿就新建 `## 加餐2（口述直录）`，**已存在的加餐/晚餐小节一个字不许动**（否则没法对账）。

## 五、主 Hermes 必须独立复核（不能只听它说）

回执里的「已写入 ✓」是自报，不是事实。**每次写入后自己跑一遍**：

```bash
cd ~/health && stat -c '%n %s %y' diet/YYYY-MM-DD.md profile.md
grep -n "^## " diet/YYYY-MM-DD.md
python tools/verify_diet_tables.py diet/YYYY-MM-DD.md | tail -8
```

两三秒的事，能抓住「汇总没更新」「只改了标题没写表」「profile 被顺手改了」这类问题。

### 验证它自称的「纯插入 / 只加没删」——数 diff 行

它说「只新增 96 行、删除 0、修改 0」时，**别信措辞，去数**：

```bash
cd <skill 目录>
wc -l SKILL.md SKILL.md.bak_<时间戳>
diff SKILL.md.bak_<时间戳> SKILL.md | grep -c '^<'; true   # 删除/修改行数（应为 0）
diff SKILL.md.bak_<时间戳> SKILL.md | grep -c '^>'        # 新增行数
```

⚠️ `grep -c` 匹配为 0 时**退出码是 1**，串在 `&&` 后面会把后半截命令吃掉 → 必须 `; true` 收尾，或拆成两次调用。2026-11-18 就因为这个坑只跑出一半。

同时 `grep -n '<新节标题>'` 确认新节落在它说的那一行；`stat` 确认被它声称「没动」的定稿文件字节数/mtime 真的没变。

## 五之二、越界红线：主 Hermes 连「顺手看一眼」都要克制

用户 2026-11-17 当场查岗：「另外你检查一下这个是你做的还是健康助理做的，这个工作流程不能乱啊。」

**越界过的三件事（都别再犯）：**

| 越界动作 | 为什么不行 | 正确做法 |
|:---|:---|:---|
| 自己改 `~/health/tools/verify_diet_tables.py` 的餐次正则 | `tools/` 是健康域的文件，改法该由它自己定、自己备份、自己报 diff | 任务书里只写症状（「『加餐2』那行被跳过导致累计块误报 FAIL」），让它改 |
| 自己去 `health/` 里 grep 历史标签数据 | 检索到值之后「用哪一档、怎么判」是它的事 | 只说「你档案里 2026-10-26 有他拍的袋背标签，自己核」 |
| 自己跑核算/折算 | 铁律 | — |

**允许主 Hermes 动手的（仅此一项）**：跑 `stat` / `grep '^## '` / `verify_diet_tables.py` 做**只读复核**——那是「验它有没有撒谎」，不是「替它干活」。

## 六、回执转述要求

- **原样贴，禁压成摘要句**（踩过：午餐回执被摘要，他说没看到回执）
- 它给的来源标签（`〔薄荷·实时〕`/`〔表1-2 ‡〕`/`〔估算〕`/`〔标签换算〕`）、算术自检、数据完整性、边界自查**全部保留**
- Telegram 长文会被网关自动分段，不用担心 4096 上限
- 🔴 **记账/核算回执一律不建 md、不发 MEDIA**（他 2026-11-17 当场质问「你为啥突然做了个 md 文档呢」）。只有他明确要一个文件时才建档

## 七、已知工具坑

| 坑 | 症状 | 处理 |
|:---|:---|:---|
| `verify_diet_tables.py` 餐次正则 | 只认 `早餐\|午餐\|加餐\|夜宵`，出现「晚餐」「加餐2」时整行被跳过 → 累计块**误报 FAIL** | 正则用 `加餐[0-9]?\|晚餐[0-9]?`；餐次列表改成 `[k for k in rows if k != '累计']` 才是根治 |
| skills 下同名校验器副本 | `skills/health/health-nutrition-analysis/scripts/` 里那份是旧的，跑到会误报 | 以 `~/health/tools/` 那份为准 |
| 库值异常不是录入错误 | 豆制品维生素E 报 17.8 mg/100g，看着像错，其实忠实抄自成分表 | 有出处就不改数，走覆盖层排除：`fooddb/anomaly_registry.json` + `tools/anomaly_fix.py`。**改缓存是假修**（薄荷每次实时拉） |
| 报 FAIL 先判是不是校验器缺陷 | 各表都 ✓ 但累计块 ✗ | 用同一份文本独立复算一遍，确认是校验器问题再报给用户 |
| 它自报「已写入」但表格没落盘 | 写入脚本只 `append` 了修订节，正文表格替换没写回 → 表内合计与实际行不符 | 每次写入后必跑 `verify_diet_tables.py`。它会抓到，这就是第 5 节「独立复核」存在的理由 |
| 回执正文写的「N 行」和表格实际行数不符 | 2026-11-18 它写「16 行」、实际表格 14 个数据行（13 项食材＋米饭，盐行只计钠） | **以表格和校验器的 `N行/11列` 为准**。复核时点出这个笔误，**不要按 prose 去改数**；数字没受影响就不必让它返工 |

## 八、他发过的包装标签 = 最高优先级，比库条目高

2026-11-18 踩过：早餐钢切燕麦，让它用薄荷品牌条 `fd35efe2`（纤维 12.5），他当场纠正：

> 「刚切燕麦的营养素含量我之前有发给过你呀，你参考一下之前的就好了。」

——他自己 2026-10-26 拍的**家雀 钢切燕麦**袋背标签（纤维 16.2）一直躺在 `diet/2026-10-26.md` 里。

**任务书必须加这一条：**

```
先用他自己历史档案里搜到的实物标签（在 ~/health/diet/ 里搜食材名），搜不到再用库条目。
用库品牌条替代之前，必须在回执里明说「他自己没发过这个的标签」。
同一食材发过两版标签 → 按档案里记的最终版，档案里已标作废的旧版跟着作废。
```

## 九、标签缺项不许长期记 0

「标签未标」≠「含量为 0」。写成 `钙 0.00` 就是把它当 0 记账，等于这个食材的钙被永久记没。

他的要求（2026-11-18 原话）：「存之前找个靠谱的钙数据补充进去 别让钙数据一直缺失」／「钾的数据如果缺 也一样处理」。

**做法：**

1. 去权威外部源找**同类**参考值：**USDA FoodData Central（给 FDC ID ＋ 条目英文名）** > 中国食物成分表 > NLC
2. 回执写清：来源、ID、条目原名、数值、单位、「每 100 g 干重」
3. 🔴 **必须写成「外部参考值，非包装标签值」**——自建条目 remark 和档案行两处都要写
4. 多源跨度大时**列区间，不挑一个凑数**；判为偏离值要能给出物理理由
   （例：NLC「燕麦片」钙 186 mg/100g，是整粒的 3.4 倍——切割/压片不会增加钙，物理上不成立 → 判偏离值不采用）
5. 查不到就留空并说明为什么查不到，不许估算顶格

## 十、他固定买的东西做成自建条目，别每次翻旧档案

`~/health/fooddb/custom_foods.json`（**list**，每条一个 dict：`foodCode` / `foodName` / `energyKCal` / `protein` / `fat` / `CHO`（净碳水）/ `dietaryFiber` / `Ca` / `K` / `Na` / `remark` / `_source`）。

已建：`CUSTOM-JIAQUE-STEELCUT-OATS` 家雀钢切燕麦（383.1 / 13.1 / 8.8 / 净碳水 54.4 / 纤维 16.2 / 钠 6 / 钙 45.5 / 钾 350）。

**建档流程**：先备份 `custom_foods.json` → 读几条看结构**别自创格式** → 写入 → **回读打印整条** → 用新条目重算一次并与档案逐项对照（证明「条目建了，也真用上了」）。

补录矿物质后要给已入档的当天档案写**修订注记 R1**（`## 📌 修订 R1（…）`，追加式，原值全留在 R1 里），且表格里的列要同步改——否则表内加总对不上合计，校验器直接报错。

## 十一、播报节奏

- 接活先应答（收到 + 怎么拆），再动工具
- 派活后说清「我给它划了哪几条线」，比干等有用
- 结果回来**原样贴**，末尾附「我自己占的是什么」
- 🔴 **回执到了一条都别压。** 2026-11-18 踩过：加餐回执早就算完了，我为了等另一条线上的学习任务一起报，压了半个多小时，他直接说「你现在把加餐反馈发给我」。**每条回执独立成条、到了立刻贴**，不要攒批、不要等别的事收尾。
- 悬而未决的事（目标要不要改、要不要写入）每次收尾列一行，别让它飘着

## 十一之二、模糊单位（口／个／根／碗）的处理口径

他只说「一根香蕉」「两碗饭」这种量词时，任务书里要**明确要求三档区间并列**，不要让它闷声取一个中值。

好的回执长这样（2026-11-18 加餐原始回执）：

```
采用    units「根 150 g 毛重 / 88.5 g 可食」（中号档），与 piece_weight.json 同值，去皮口径
换成其他档会差多少（供你核）
        小根 64.9g  → 热量 60.36｜纤维 0.78｜碳水 14.28
        大根 123.9g → 热量 115.23｜纤维 1.49｜碳水 27.26
差值量级：本份热量 60.36–115.23（极差 54.87 卡）、纤维 0.78–1.49
```

关键点：**给区间 + 说明取哪一档 + 标〔估算〕**，他才能凭自己的信息判断对不对。

## 十二、运动记录（健康域不止饮食）

他报运动（「打了 60 分钟羽毛球双打」「跑了 5 公里」）也是健康域，**同样派给健康助理**，主 Hermes 不自己算消耗。

**落点**：`diet/YYYY-MM-DD.md` 里新建 `## 运动（口述直录 ＋ MET 换算）`，**插在「今日汇总」之前**，然后重出当日汇总（餐次 ＋ 运动一起）。

**任务书必须点名的四项：**

1. **MET 给数值 ＋ 出处 ＋ 档位说明**——不接受闷声取一个数。库里不区分单/双打这类情况，要它明说「该 code 是合并档，没有单独的双打系数」。
2. **体重基准取自 `profile.md` 现行工作口径**，与 BMR/TDEE 同口径，回执里写明多少 kg、取自哪一段。
3. **净消耗 vs 总消耗**：档案例行口径取**净增量** `(MET − 1) × kg × h`，不是 `MET × kg × h`。要说清扣掉的是同时段静息代谢。
4. **时长是他自估 → 给区间**（如 45/60/75 分钟各多少卡），**主值仍用他说的时间**，别取中值。

**运动只改能量账户一项**：TDEE 基线 → 基线＋净增；**钠、嘌呤、纤维这些不随运动变化**，回执里要写明这两项账面数不动。运动消耗一律标〔估算〕，不许标成实测。

详细案例（MET 表、公式、运动节为什么不做成 11 列营养表）见 `references/exercise-and-leftovers-logging.md`。

## 十三、剩菜 / 隔餐结转：等量沿用，不许重算

他隔天吃剩菜时（「昨天剩下的另一半，今天都吃掉了」）：

- 昨天档案里记的如果已经是「整锅的一半」，**今天吃另一半 = 等量 ×1，直接沿用昨天那张已核定的表，克数一个都不许自己再调**
- 昨天那些〔估算〕的调料克数（生抽/盐/花雕酒/胡椒/蒜）**沿用昨值，不许重新估一个**——两轮估出两个数就对不上账了
- 🔴 **昨天写过修订注记（R1）的字段，今天必须带上**。2026-11-17 R1 补的是猪肉丝钾 228.75 mg，今天这锅剩菜等量重来，漏了就是同一个漏犯第二次
- **派活前先核有没有重复计算**：`grep` 今天已入档餐次里有没有这锅的食材名（番茄/香干/娃娃菜…），证明剩的那半份是完整的。这属于只读复核，**允许主 Hermes 做**
- 他提醒「食材不止这两样」时，任务书要把**整锅清单全列出来**，并写明「『等等』＝清单其余项，不许自己加也不许漏」
- 配的主食（150 g 白米饭这类）是另吃、不在锅里，**不跟着半份一起折半**

## 十四、推演轮与评估轮（他没吃 / 他已经吃了）

### 推演轮（「假设我一会儿再吃 X，能补够吗」）

- 只读不落盘，任务书明写「不进今天合计」，四餐＋运动一个数不许动
- 模糊量三档并列（见十一之二）
- 🔴 **他实际吃的常常和推演的不一样。** 2026-11-18 推演的是「蓝莓 80 g ＋ 1 个蛋」，实际报的是「**黑莓** 40 g ＋ 蜂蜜 3 g ＋ **2 个**蛋」。
  → **写入轮任务书必须显式写死这条：「上一轮推演作废，本轮只按他实报的算，不许沿用推演里的任何数字」**，并点名易混的食材（黑莓 ≠ 蓝莓 `lanmei`）。不写这条，它会顺手把推演的条目搬进档案。
- 他问「能不能补够」时，要给**三档份量各自的结果**，别只给中档一个数——他常自己取极端档来判断「连最大档都不够」。

### 评估轮（「这顿值不值得 / 划不划算」）

🔴 **这是最容易附和的场景：他在为自己已经吃下去的东西找自洽理由。任务书必须写「一条都不许附和，数据说什么就说什么」。**

他的典型四条论证与对应拆法（2026-11-18 实例，可直接套）：

| 他说 | 怎么核 |
|:---|:---|
| 「补了蛋白」 | 算占缺口的百分比；再把七项（热量/蛋白/脂肪/碳水/纤维/钠/嘌呤）按**偏离目标的幅度排队**，看他说那项排第几。他会以为最缺的是蛋白，实际那天排第 3（嘌呤 +118%、脂肪 +26.6% 在前） |
| 「虽然脂肪超了，但我今天有热量赤字」 | 🔴 **把赤字拆成「含运动」和「不含运动」两版**：含运动 431.99，不含运动只剩 85.49，运动占 80.2%。再说「脂肪目标 67 g」的出处是 **2000 卡 × 30% ÷ 9**（供能占比换算），**赤字看总量、脂肪目标看结构，是两件事，赤字抵不了占比** |
| 「鸡蛋维生素多」 | **先查库内有没有维生素字段**。`jidan_junzhi` 有 VA/VE/B1/B2/B3/C，**VD、胆碱、B6、B12、叶酸全无**——而「鸡蛋维生素多」的印象恰恰靠这几项。没有就写「无法判定」，禁止用印象填。另：档案表格只有 11 列，**没有维生素列**，只能说这顿的绝对量，说不了全天占比 |
| 「钠嘌呤超得不多」 | 逐项算偏离百分比，并**拆归因**：这顿带来多少 vs 这顿之前就已经多少。那天钠超 4.88%（成立），嘌呤 654.74/300 是 2.18 倍（不成立）——**但嘌呤这顿只贡献 6.36 mg，是午餐 338 ＋ 晚餐 247 背的**。要把他混在一起的两件事分开讲 |

🔴 **「按偏离百分比排队」只能回答「离他档案里的目标多远」，不能当成健康风险排序。**
2026-11-18 拿 GPT-6.1-Sol 复核时它明确指出这是方法硬伤：**百分比消掉了单位，消不掉生理差别**——
蛋白是**要够**的量、钠是**要限**的量、纤维是**至少要到**的量（纤维 26.39 > 25 通常是好事），
三者不能塞进同一张「离目标越远越坏」的榜里。用它回答「他以为最缺的那项实际排第几」没问题，
**但转述时必须补一句「这只说明偏离档案目标多少，不等于危害按这个顺序排」**，否则他会拿这个排序去做取舍。

**必给一张「吃」vs「不吃」并排表**（逐项指标 ＋ 含运动/不含运动两行能量差），让他自己看代价落在哪，比任何结论句都有用。

**收尾只判这顿的账，不给明天的方案、不写劝诫**——他问的是「这顿划不划算」，不是要处方。

## 十五、拿评估结果去问外部模型（GPT 复核）

他常把健康助理的结论再丢给 GPT 验一遍（2026-11-18：「你把这件事儿整理一下去问一下gpt看看他的意见」）。
调用姿势见 `codex-cli`，这里只记**健康域专属的三条喂料要求**：

1. 🔴 **必须把 `profile.md` 第三节「关键指标速查」的异常项整块喂进去。** 2026-11-18 漏喂，GPT 把
   「缺少血尿酸、痛风史、血脂时，宣布『嘌呤第一严重、脂肪第二严重』依据不足」写进了判断前提——
   而这三样本机全有：**尿酸 454 μmol/L（离药物门槛 480 只差 26）、LDL-C 4.37、TG 3.27、TC 6.91、HbA1c 6.3%**。
   少了这块，它的「这顿值得」是给一个不存在的人判的。同时带上**减重期尿酸预警**（酮体与尿酸竞争同一排泄通道，
   能量差为负时尿酸可能不降反升）。
2. **把目标值的出处一并给它**：129 g ＝ 1.6 g/kg，是**目标值不是红线**；嘌呤 300 mg 是**临床惯例、不在食养指南里**
   （档案里特意标过「别说成指南」）。不写它会自己猜，然后在「不确定」清单里反问。
3. **把健康助理的原结论完整贴给它**（不要摘要），并明写「**你可以否定提问方（我）和本地健康助理的任何结论**」。

**交付前必做**：把它列的「我不知道但影响判断」清单**逐条回本机档案查**——2026-11-18 它列了 5 项，
其中 4 项 `profile.md` 里就有答案，而查出来的结果**反转了它的结论**。查到什么要单独成段告诉他
「它没看到的本机硬事实，会把结论往哪个方向拉」，不能把它的结论原样递上去。

它反驳健康助理的每一条都要逐条复算（2026-11-18 它抓对了「160.29 卡把全天超额当成了本顿新增」
「7.5 倍是从 2.38 g 小基数起算，供能占比其实只从 34.6% 升到 36.9%」「赤字不能因为来自运动就作废」）。
完整案例见 `references/evaluation-rounds.md`。

## 十六、收盘轮（「今天就到此为止」）

他说「别的不会再吃了 / 可以收盘了」时，派一轮**收盘轮**，它比写入轮多两件事：

1. **`diet/YYYY-MM-DD.md` 的汇总改成收盘态**：标题从「截至 HH:MM，**仅含已报餐次**」改成「**收盘 · 全天完整**」＋写入时间；头部状态行同步；把「本表不是收盘数」的免责换成「已是收盘数」。**此前各节一个数都不许改。**
2. **新建 `reviews/YYYY-MM-DD_当日饮食评价.md`**（这一天唯一的评价文件）。

**评价文件先看昨天那份的版式**，照结构写，别另起一套。2026-11-18 实测的八节结构可直接复用：

```
一、全天八项 ＋ 钾的最后落点（目标 / 方向 / 偏差量 / 能量账户）
二、分餐结构
三、偏离最大的三项（谁贡献的 / 能不能靠别的餐抵消）
四、必须一起读的硬约束（尿酸 454／血脂四项／减重期尿酸预警）
五、与昨日对比
六、当天运动的影响（只改能量账户）
七、数据来源与口径
八、一句话
```

🔴 **「能不能靠别的餐抵消」这一节很有价值**，值得每次都要求：把嫌疑餐次全删掉重算一遍，看会不会仍然超。2026-11-18 那一轮：把早/加餐/加餐2 三顿全删，嘌呤仍 585.20 mg＝1.95 倍 → 证明它确实是午餐＋晚餐背的，不是某顿的锅。

**收盘轮的两条硬约束**：
- 评价文件可以写**事实性归因**（哪顿贡献了什么），但**不许写「以后该怎样」**、不许劝诫
- 运动对账面项的影响要写清：**钠/嘌呤/脂肪/纤维不会因为打球变小**，只有能量账户变

## 十七、口径修订轮：让 bot 改它自己，别替它改

他让我「把这次学到的固化下来」时，先做**归属判断**（他的原话：「你看一下是安排你自己做还是安排给健康助理做」）：

| 学到的是什么 | 归谁 |
|:---|:---|
| **判断方法/取舍逻辑**（跨域复用，属于主 Hermes 的认知） | **我自己做**，写成 skill（如 `verdict-reasoning`） |
| **域内事实与评估口径**（尿酸多少、先查哪几项、怎么加权） | **派给它**，写进 `health-nutrition-analysis` |

两边都要动，但动的东西不同——**别把「怎么下结论」教给一个只该出数的 bot，也别把它的领域事实抄进我的通用 skill**。派完要告诉他这个分工，别让他猜。

**口径修订轮的任务书写法**：
- 明确写「这一轮**不改任何饮食档案**」——当晚已收盘的 `diet/`、`reviews/`、`profile.md` 都是定稿
- 明确写「**今晚的数字一个都不许重算**，数全对，错的是结论方法」——否则它会顺手返工数字
- 要它写成**下次能照着执行的检查清单**，不是写成「这次学到了什么」的检讨书
- 要它自己备份、自己报 diff、自己回读贴出新增原文
- 🔴 **它改的是主 profile 下的 skill 目录**（`AppData/Local/hermes/skills/health/health-nutrition-analysis/`），不是 `~/health/`——复核时去对的地方找，别断言「没改」
