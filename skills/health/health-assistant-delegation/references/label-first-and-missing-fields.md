## 一、案发经过（两次纠正）

**纠正 1：用库品牌条替代了他自己发过的标签**

早餐「钢切燕麦 75 g」，健康助理用薄荷品牌条 `fd35efe2`「惠宜 钢切燕麦」
（375 / 12.5 / 7.5 / 总碳水 72.5 / 纤维 12.5），并声明「库内无标准 exact 条，用品牌条替代」。

用户原话：

> 「另外刚切燕麦的营养素含量我之前有发给过你呀，你参考一下之前的就好了。」

实际数据就一直在他自己的档案里：

```
diet/2026-10-26.md 第 22 行
  「家雀 钢切燕麦 ｜ 净含量 600g ｜ 配料：燕麦 ｜ 保质期 12 个月 ｜ 产品标准代号 GB19640」
diet/2026-10-26.md 第 48 行
  家雀 钢切燕麦 | 包装标签 | 383.1 | 13.1 | 8.8 | 54.4 | 16.2 | 6
```

**换源后差异（75 g 干重折算）**：热量 +6.08、蛋白 +0.45、脂肪 +0.97、**纤维 +2.77**、钠 +4.50、钙 −30（旧条有 40、标签未标）。
纤维 12.5 → 16.2 g/100g 是差得最多的一项。

**教训**：
- 在 `~/health/diet/` 里先搜食材名（`search_files` 搜「钢切燕麦」一行就出来了），再决定用不用库条目。
- 「库内无 exact 条」不等于「没有权威值」——**他自己的实物标签永远比库条目优先**。
- 同一食材可能发过两版标签：2026-10-26 后的档案里写明「前一版（1661kJ / 11.9 / 8.4 / 67.5 / 纤 17）作废」。

## 二、这三条口径必须挂在燕麦条目上（历史已定，勿重议）

```
① 干重口径，不折生熟（钢切煮熟后约 100 卡/100 g，按熟重算会低估一半以上）
② 标签的「碳水 54.4」是净碳水，不含膳食纤维
③ 纤维 16.2 单列，不重复计入碳水
④ 标签自身不自洽：13.1×4 ＋ 54.4×4 ＋ 8.8×9 ＝ 349.20 vs 383.1 → −8.85%
   （能量按总碳水算、碳水栏写净碳水）→ 保留原值不修正
```

**混口径警告**：若一餐里燕麦用净碳水、其他食材用总碳水，表内「碳水」列就是混口径，
算术自检会落在 +8% 附近。**必须在回执里点名说清**，或统一换成总碳水再自检。

## 三、缺项补录：钙与钾（USDA FoodData Central）

用户原话：「可以 按它说的存一下 存之前找个靠谱的钙数据补充进去 别让钙数据一直缺失」／「钾的数据如果缺 也一样处理」。

### 采用的来源

```
来源    USDA FoodData Central · Foundation Foods
FDC ID  2346397 ｜ NDB# 100282
条目原名「Oats, whole grain, steel cut」（8 样本均值，2022-10-28 发布）
钙      45.5 mg / 100 g 干重
钾      350  mg / 100 g 干重
```

### 交叉核对与偏离值判断（★ 这段最有价值）

```
USDA SR Legacy · NDB 20038「Oats」        钙 53.8 mg（84 mg／156 g cup）｜钾 429 mg
中国营养学会 NLC「燕麦片」                  钙 186 mg｜钾 214 mg
```

**为什么没选 NLC「燕麦片」钙 186**：
1. 那是「燕麦片」，不是钢切；
2. **186 是整粒的 3.4 倍——切割/压片不会增加钙，物理上不成立** → 判偏离值。

→ 做法是**把区间和每个来源全部列出来**，说明选哪个、为什么，**绝不挑一个凑数**。

**残留不确定度**：45.5 vs 53.8（SR Legacy），75 g 折算只差 6.23 mg，对总量级无影响。

### 写法（两处都要）

- 条目 `remark` 里：`⚠️ 钙 45.5 与钾 350 不是包装标签值 —— 标签未标钙、也未标钾，这两个数是同类品外部参考值（FDC 2346397 …）`
- 档案行里：来源列补一句 `钙 45.5／钾 350 为外部参考值，不是标签值`

## 五、补录矿物质后如何改已入档的当天档案

钙是**表格里的列**，不能只在修订节里说明——表内 34.13＋6.20＋7.25＋107.00＋29.57＝184.15
若合计还写 150.02，校验器直接报错。正确做法是**两件一起**：

1. 追加 `## 📌 修订 R1（钙/钾补录 · …）· YYYY-MM-DD HH:MM`，写明「原值 → 新值」和漏的原因
2. 同步改表格里的钙列 / 合计 / 逐项累计块 / 汇总表 / 结构提示，**原值全部保留在 R1 里**

本次实际变化：

```
燕麦 钙   0.00（未计）→ 34.13 mg（75 g 干重）
燕麦 钾   未取       → 262.50 mg（75 g 干重）
早餐 钙   150.02     → 184.15
早餐 钾   528.37     → 790.87
其他六项（热量/蛋白/脂肪/碳水/纤维/钠）＋嘌呤：一个数不变
```

副作用提醒：补进燕麦钾之后，钾的第一大来源从「香蕉」变成「燕麦（33.2%）」，
档案里的「结构提示」段要跟着改，否则会自相矛盾。

## 六、写入脚本只 append 不落盘的坑

第一次写入脚本只把 R1 追加进文件，正文表格替换改在了内存 `txt` 里但没写回。
校验器立刻显示「合计 150.02」与实际行不符才被发现。

**结论**：写入轮的收尾**必跑** `verify_diet_tables.py`，它是唯一能抓住「自报已写入但只写了一半」的机制。
