# 2026-11-15 汇报习惯为什么反复：取证与修法

用户当天原话：**「为什么汇报习惯你总会反复呢？有时候记得有时候不记得。」**

SKILL.md 里的规则是这份的浓缩版。

## 1. 同一天的两种表现（关键证据）

| 任务形态 | Agent 行为 | 用户反应 |
|:--|:--|:--|
| 早餐派活给 health profile（后台） | sleep 240 秒 → 一条长回复，**中间 0 次汇报** | 未当场发火，但埋下问题 |
| 小红书视频扒谱（Agent 自己同步跑） | 4 次进展：1/3 → 2/3 → 2/3补 → 3/3 | **一句没催，主动要求的就是这个** |
| 午餐 v2 / v3 / v4 / 定稿（后台，4 轮） | 每轮派完干等，**0 次汇报** | 最后直接质问汇报习惯 |

**规律不是随机的**：自己动手时能做到，派出去等的时候做不到。
提醒一次能好一轮，随后回退。

## 2. 根因四层

### ① 记忆里三条规则全是「少说」，没有一条「什么时候必须说」

```
③分步汇报只在阶段节点说（不是每个工具前都发）
TG 回复：调工具前不要先写一句（会被推成独立消息），只在节点/结束时说话
微信只讲结果不报过程
```

三条都是**限制**。「什么算阶段节点」从未定义 → 每次即兴判断 → 标准漂移。
默认状态下，在禁令里「不说」永远是最安全的选择，所以一犹豫就闭嘴。

### ② 主因：执行形态变了，汇报规则没变

- 自己同步跑（下载 / ASR / OCR / 识图）→ 每两步之间天然有「刚刚发生了什么」可说
- 派给后台子 profile → 只有「发出去了 / 回来了」两态，中间物理上没有新信息

**同一套规则，对两种执行方式只有一种有效。** 这就是「反复」的机制。

### ③ 多轮迭代时注意力被数字挤走

v2/v3/v4 三轮全在纠口径（钠 2480 还是 2130、配菜归零还是 15%），
注意力被占满，汇报规则被挤出视野。**任务越难，越容易只盯任务本身。**

### ④ Agent 自己给规则加了例外

「回执须原样搬明细」这条，历史上被私自加了「除非内容没变」：

> 2026-11-14 原话：「这条是运动入档那次派活的完成回执，结果已经完整报给你了。」
> （194 字，被用户指为压摘要）

当时的判断是「你已经看过一遍了，再贴一遍是啰嗦」。
**用户的标准是「不管我看没看过，回执要给全」。**
→ **Agent 的偏好覆盖了用户的规则，而用户从未给过那个例外。**

## 3. 修法（五条）

1. **定义死「节点」**：任何一次工具返回**改变了结论**就是节点。不改变结论的连续调用才允许合并。
2. **派活固定句式**：「这个预计 X 分钟，回来后我直接给你」。
3. **长任务优先自己同步做**，不派后台；派后台的才需要那句交代。
4. **回执取消「我判断你看过」**：一律全文搬，不管第几轮。
5. **规则从 memory 挪进 skill**：memory 只有短句、丢掉条件；skill 能写清「什么情况算节点」。
   压缩后的禁令语义已经变形（参见 SKILL.md 里那条被误读的「第 3 条」）。

## 4. 一句话结论（可直接对用户复述）

> 汇报不是靠规则驱动，是靠「有没有新信息」驱动；
> 用户期待是靠「事情有没有在进行」驱动。两者错位时 Agent 就消失。

## 5. 两条规则的共存方式（最容易再次搞混）

| 规则 | 管什么 |
|:--|:--|
| 「调工具前不要先写一句」（2026-11-13） | 管**同一节点内的碎片**——不要把一句话拆成两条消息 |
| 「不要闷头做完才说」（2026-11-15） | 管**跨节点的沉默**——不要在一个阶段内消失 |

**它们不冲突**：前者禁止“为了说而说”，后者要求“结论变了必须说”。
写记忆时要把这个区分带上，否则短句压缩后只剩「少说」，条件全丢——
这就是复发的技术原因。
