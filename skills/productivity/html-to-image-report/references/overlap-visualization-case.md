# 「时间重叠可视化」实测案例（2026-11-10，Dayflow 周工作日历）

用户要「这周工作安排以图片形式发给我」→ 第一版做了七天议程卡片 + 重叠卡片标橙，
他回：「时间重叠的安排要在图里显示出来」。**标橙不算显示出来。**

| 周三 | H地块营销招标流程讨论 09:30–11:30 | 地下会所… 09:30–17:30 | 09:30–11:30 | 120 |
| 周三 | 同上 | 与合约沟通软装、门锁招标、电梯颜色 11:30–11:45 | 11:30–11:45 | 15 |

关键观察：**7 对全部由同一条 8 小时长跨度事项造成**（09:30–17:30「地下会所多功能室设计
灵感收集」，周二周三各一条）。图注必须点明成因，回复末尾给收口建议
（「要不要把它拆成具体时段，重叠就自动消除」）——否则用户只看到一片红。

判定用严格交集 `max(start) < min(end)`；09:30–10:00 与 10:00–10:30 首尾相接**不算**。
当周周二有十几条首尾相接的排程，全部未被误标，说明口径可用。

## 版面演进

**v1（被否）**：只有七天卡片，重叠卡片标橙 + 一行「主业 · 时间重叠」。问题：
- 没说是和哪一条重叠；
- 没说重叠多久；
- 没有全局视角，看不出当天是「被一条长事项罩住」。

**v2（被接受的三块结构）**：
1. 顶部「时间重叠可视化」时间轴（每个有重叠的日期一行，宽 1520，08:00–23:00 映射 1350px）；
2. 中间七天议程卡片（重叠事项红框 + 逐条 `⟷ 对端全名（窗口，N分）`）；
3. 底部逐对明细表。

## 踩过的排版坑（都靠代码判据抓出来）

| 现象 | 数值 | 根因 | 修法 |
|:--|:--|:--|:--|
| 画布被撑破 | `scrollWidth=1598` vs 画布 1520 | `.dayrow{margin-left:64px}` 与子元素 `left:px(...)` 两段偏移叠加 | 坐标相对 `.trail` 自身算，容器 `left:0;width:AW`；`AW = 1520-56-2-40-74 = 1350` |
| 短条文字出界 | 30 分钟 ≈ 45px | 无条件渲染 `<span>` 标题 | `w>=104` 才写字，否则纯色块 |
| 斜纹压字 | 视觉模型报「文字被斜纹压住」 | 斜纹框覆盖整行且带内部文字 | 斜纹 `z-index:1` 且内部不放字；分钟数另起一行 `.olab{top:82px}` |
| 对端名称被截断 | 卡片出现「地下会所多功能室设计…」 | 为省版面用 `short2()` 截到 10 字 | **删掉截断**，卡片写全名（完整回执优先，明细表重复不算冗余） |

## 视觉模型的可靠性

`vision_analyze` 对最终图报了两轮「文字互相压住、斜纹压在文字上」。
实际用 `scrollHeight>clientHeight+1` / `scrollWidth>clientWidth+1` 全量扫，结果
`clip:[]`、`overflow:[]`、`docW==1520`。
→ 视觉模型只用来看「中文有没有乱码/方块」；压字与越界一律以 DOM 数值为准。
（SKILL.md 原有这条结论，本案例再次确认。）

## 取数环节：`client items` 的输出要先拆包

本流水线的第 1 步（取数落盘 JSON）在这个数据源上有个坑：`client items` 的 stdout 不是干净的
JSON 数组，而是**数组 + 换行 + 一行诊断 JSONL**：

```
[...事项...]
{"requestId":"","operation":"items","attempt":1,"durationMs":3503,"totalMs":3503,"status":200,"recoverable":false}
```

直接 `json.loads` → `JSONDecodeError: Extra data: line 2 column 1`。用 `raw_decode`：

```python
raw = open(path, encoding='utf-8').read()
obj, idx = json.JSONDecoder().raw_decode(raw.lstrip())   # obj 就是事项数组
trailing = raw.lstrip()[idx:]                             # 诊断行，丢弃
```

诊断行的 `durationMs`/`status` 可用来判断是不是真拿到了完整回执（本次 3503ms / 200）。
同理，用 terminal 把客户端输出重定向到文件时，**不要把 stderr 混进来**当成数据。

## 截图链路（一次成功的组合）

用**独立命名 session**（如 `session="week-render"`）重新 `new_tab("file:///D:/Workspace/xxx.html")`，
`wait_for_load()`，先用 `page_info()` 确认 `url` 是目标文件、`pw/ph` 是画布尺寸、
`document.body.innerText` 有内容，再
`cdp('Emulation.setDeviceMetricsOverride', width=1520, height=<document.scrollHeight>, deviceScaleFactor=2)`
+ `capture_screenshot()`。

若 `page_info()` 报 `url: about:blank`，说明这一跳没真正导航 —— 重新 `new_tab` 或换命名 session 再来，
**绝不把空白截图当成品发出去**。
