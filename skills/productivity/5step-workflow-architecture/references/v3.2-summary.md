# 审查层 v3.2 架构摘要

> 完整方案：`Desktop/审查层重构方案_v3.2.md`
> Opus 评分 8.5/10 | Codex 评分 ~9.3/10（修5处后）

## 核心架构

```
④ 审查（重构后）
  
  触发判据：交付物 + 高风险/不可逆/高爆炸半径 → 双审
           低风险/探索/草稿 → 单审或跳过

  Codex（正向重建） + Opus（反向证伪）并行双审（都审6维，主责错位）
    ↓
  接地校验（三模式：present_text / omission / external_evidence）
    ↓
  归并（CORROBORATED / INDEPENDENT / CONFLICT）
    ↓
  分歧路由（事实类 → 系统处理 ｜ 价值类 → 上抛用户 ｜ 不确定 → 默认上抛）
    ↓
  事实类收敛：交叉质证 → crux压缩 → 主动补证据 → 千问盲审决胜
    ↓
  自动修复 ≤3轮（全量6维重审 + 停滞+回环双模震荡检测）
    ↓
  3轮失败/震荡 → 上抛
```

## 关键参数

| 参数 | 值 |
|---|---|
| Codex 模型 | GPT-5.6-sol（ChatGPT Plus 会员） |
| Opus 模型 | Claude Code CLI --model opus（Claude Pro 会员） |
| 千问角色 | 盲审第三模型，仅证据持平时决胜 |
| 修复轮数 | ≤3轮 |
| 成本熔断 | 30分钟 或 20万 token |
| 影子毕业 | ≥100 任务 + 0 critical 误报 + 召回率 ≥70% + 接地率 ≥95% |
| Codex 调用 | 不带 pty（已修 bug），代理 7897，sandbox danger-full-access |

## 通过门禁

- 存在已接地 critical → 不得通过
- 存在已接地 high → 必须修复后重审通过
- 未决 high/critical 冲突 → 上抛
- 熔断/证据不可用/审查独立性不足 → 上抛
- critical 绝不静默放行

## 作者≠审查者

| 场景 | 补位 |

| Opus 参与生成 | Codex + 千问 |
