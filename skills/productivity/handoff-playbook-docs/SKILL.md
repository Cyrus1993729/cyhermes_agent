# 可交接文档（给外部 agent / 同事去部署）

## 什么时候用

- 用户说「总结一下我们的做法」「写个文档我发给朋友」「让他的 agent 把这套搭起来」
- 交付物是**方法与流程**，不是当天结果
- 读者不在本机、看不到你的代码和配置

**不适用**：当天的分析报告、日报周报、只给自己看的笔记（那些走各域技能的回执规范）。

## 🔴 铁律：写成「照着能搭起来」，不是「听起来有道理」

2026-11-17 一份「饮食记录方法论」文档被连续退回两次，两次原因相同：

| 退回 | 用户原话 | 缺的是什么 |
|---|---|---|
| 第一次 | 「你好像没有告诉他成品的库从哪里找对吧」 | 数据源：哪个库、免费接口/付费接口、key 怎么申请、额度多少 |
| 第二次 | 「我后来的这些要求你有检查过你写的这个分享文档包没包含吗？」 | 失败分支：库里查不到时怎么拆解 |

**共同根源**：Agent 按「方法论」的抽象层次写（原则、纪律、反模式都写了），
而用户要的是**可执行细节**——读者拿着文档就能把系统跑起来。

一句话自检：

> **把文档丢给一个没看过你源码的 agent，它能不能一路做完不回来问你？**
> 不能 = 没交付。

## 交付前四件套（缺一不可）

```
□ 数据源：地址 / 鉴权方式 / key 怎么申请 / 额度与限流 / 降级源
□ 失败分支：查不到、超时、多条冲突、字段缺失 —— 各怎么办
□ 配置与占位符：哪些值要按环境替换（{BMR} {API_KEY} {路径}）
□ 冒烟步骤：先跑什么可以确认通了
```

写「失败分支」时把**三种结果都写全**，例如「查到且适用 / 查到但不适用 / 查不到」，
每种配一句**必须留痕的口径说明**。只写「查不到就拆原料」等于没写。

## 需求覆盖核对（交付前最后一道）

用户逐条点名过要求时，抄成清单逐条打钩，**并指出落在哪一节**——不凭印象说「包含了」：

```
① 数据从哪来/怎么接     → 第 8.0 节 ✅
② 数据缺失怎么办       → 第 5 节 ✅
③ 库里没有这道菜怎么办 → 第 8.7 节 ✅（第一版漏了，已补）
```

**输出**：`需求覆盖 N/N ✅` 或 `漏 X 项 ⚠️ → 补齐后再发`。

## 隐私 / 密钥扫描（对外分享前必跑）

用户会明确要求「不要包含我的个人信息」。交付前真跑一次，不靠印象：

```bash
grep -nE "<姓名>|<用户名>|Administrator|<体检指标数值>|<API key 前几位>|<带用户名的绝对路径>" 交付物.md
# 命中数必须为 0
```

- 带用户名的路径 → 换成 `{HERMES_HOME}/...` 这类占位符
- 体检/身体/财务数据 → **写阈值逻辑，不写具体数值**（「要盯嘌呤/糖 → 必须走付费路径」而不是「他尿酸 454」）
- **真实 key 一律不写进文档**，只写「怎么申请、签名规则、有效期、额度」；顺带提醒读者别共用别人的 key
- 改完再扫一次，把命中数一起报给用户（「隐私重扫 0 命中」比「已脱敏」可信）

## 建议的文档骨架

```
0  设计目标 + 三条不可妥协的底线（其余都可以简化）
1  架构：谁负责什么、边界在哪（为什么这么分）
2  输入分流：什么情况走哪条路
3  人机契约：确认卡 / 回执的格式（强调「可整段复制编辑」）
4  口径固化：模糊量怎么变成可复现数值
5  异常与缺失处理（最重要，最容易被写漏）
6  核心引擎/算法（只讲「为什么用统一的」）
7  校验与留痕
8  数据源：地址 / 鉴权 / 额度 / 降级 / 冲突   ← 最常被漏
9  产物结构（文件长什么样）
10 反模式清单（都是踩过的，读者最容易抄错的地方）
11 落地清单：按顺序的 N 步，标出哪几步不做完别往下走
12 占位符清单
```

## 写作口径（本用户）

- 纯文本 + 代码块，**不要 markdown 表格堆砌**；能打钩就打钩
- 每个关键数字后面跟一句「实测/踩过」，让读者知道不是拍的
- 反模式清单里每一条写清**当初错在哪、结果多严重**（「一顿早饭因此烧掉 23 次额度」比「不要盲批」有效十倍）
- 交付时正文先说「文档多大、多少节、最值得先看哪两节」，再给 MEDIA 路径

## Pitfalls

### 先发大纲就结束回合 = 换了个方式沉默

2026-11-17 实际发了「我按下面 10 块写，先跟你把结构说清楚再动手」→ **回合结束** → 用户回「？」。
**应答句和第一个工具调用必须在同一回合里**（应答是开工宣言，不是请求许可）。

### 长链自干会触发「假死」判断

读技能库 → 查接口 → 起草 → 补章节 → 自检，15+ 次工具调用全程零句人话，
用户无法区分「在跑」和「卡死」。**切节点报**：读到关键定义(1/3) → 开始写(2/3) → 自检(3/3)。

### 只给 MEDIA 路径不给正文

用户要的是**能直接转发/粘贴的内容**。正文至少给出：交付了什么、结构是什么、最值得先看哪几节。
