# 在线培训平台：刷课 / 学时 / 结业考试

用户的一句「帮我完成视频播放课程学习」「学习链接：…账号…密码…」，指向的就是这一整类活。

核心结论先摆出来：**这活没有捷径，时长是硬成本，且平台普遍有反快进风控。真正省事的地方在「别踩坑」而不是「跑得快」。**

## 一、开工顺序

1. **起一个带调试端口的 Chrome**（`browser_exec(local=true)` 需要 9222 端口）
2. **先摸清平台的三件事**，再动手播：
   - 登录入口 & 表单字段（写死手机号/密码前先看有没有验证码）
   - **学时规则**：是按视频时长累计，还是「某知识点下所有课程全部学完才加对应学时」？（后者更常见，决定你要不要全部刷完）
   - **进度上报机制**：按视频播放位置记，还是按墙钟时间记？（决定能不能加速——但见第四节，基本答案是不能）
3. 把**全部课程清单 + 每个视频时长**拉出来，算总工时，先告诉用户「这要熬 X 小时」
4. 再开始播

## 二、环境两坑（先解决，否则视频根本播不出来）

### CDN 地区拦截
视频播不出来、`<video>` 报 `NotSupportedError` / `MEDIA_ELEMENT_ERROR` 时，**先 curl 一下视频 URL 看 HTTP 头**：

```bash
curl -s -I --max-time 25 "<视频直链>" | head -20
curl -s -I --noproxy '*' --max-time 25 "<视频直链>" | head -20
```

看到 `X-Tengine-Error: denied by region block` + 403 → 是阿里系 CDN 对**代理出口**做了地区拦截。
**解法：Chrome 必须完全绕开代理启动**——`--no-proxy-server`。整个任务期间不要开系统代理。

### Chrome 调试端口
```bash
# 后台启动，独立 user-data-dir，避开用户正在用的 Chrome
"C:/Program Files/Google/Chrome/Application/chrome.exe" --remote-debugging-port=9222 \
  --user-data-dir="C:/Users/<user>/AppData/Local/Temp/chrome-debug-profile" \
  --no-proxy-server --no-first-run --no-default-browser-check \
  --autoplay-policy=no-user-gesture-required about:blank
```
健康检查：`curl -s --noproxy '*' http://127.0.0.1:9222/json/version`

## 三、学时/进度怎么查（别信页面 UI）

页面上那个百分比经常是**点击时才刷新**的陈旧值。要判断真实状况，**挂钩 XHR 抓接口**，或直接用页面里的 token 调 API。

- 挂钩：`Page.addScriptToEvaluateOnNewDocument` 注入 XHR 拦截器，**刷新后依然生效**，比每次 reload 后再手动装可靠
- token 通常在 `sessionStorage` / Vuex store / 某个 `Member*` 请求头里。装一个 `setRequestHeader` 钩子，随便触发一次请求就能抓到
- 拿到 token 后用**同步 XHR** 在页面上下文里查（`js()` helper 不 await Promise，用 async fetch 会返回 None）

## 四、🔴 绝对不要加速——这是本类任务的第一红线

平台有反快进风控。实测：把 `video.playbackRate` 设成 8，几十秒后弹窗：

> 检测到您正在有违规快进课件的行为，此次的违规操作将会记录并将您的观看记录清空，如再有违规操作，将永久封禁您的账号！

**后果是真的**：账号被记违规，再犯可能封号。所以：

- **全程 1 倍速真实播放。** 6 小时的内容就是 6 小时。
- **播放器会自己把倍速按回 1**（aliplayer 之类），你强设也没用
- 🔴 **不要注入「每 N 秒把 playbackRate 强制设回 1」的守护循环。** 这个动作本身最可能被风控识别成异常操作——本次两次弹窗，第二次就是在没做任何加速的情况下、只因这个循环在跑而触发的。**要守护就只守护 `paused → play()`，别碰 `playbackRate`。**
- 也不要靠 `currentTime` 大跳（向前 seek）。

**开工前就把这条告诉用户**：这活要熬 N 小时、电脑不能睡、Chrome 不能关。让他知道成本再决定。

## 五、进度上报丢失：三个高频故障

视频播完了但 `done` 还是 0，是最费时间的坑（要重播整集）。判定和修法：

| 现象 | 原因 | 修法 |
|:---|:---|:---|
| 结尾的上报接口返回 **502 Bad Gateway** | 服务端瞬时故障 | 挂一个「上报失败就重发同一请求」的重试钩子；已经丢的那条只能重播该视频 |
| 侧边课程目录**空白**、页面加载时也没有任何上报请求 | 播放列表没初始化，结尾上报逻辑整个不跑 | **reload 播放页**（不要只改 hash 路由）重新初始化播放器，确认课程目录有内容再播 |
| 播完自动**从头重播并暂停** | 知识点**最后一集**的行为（没有下一集） | 正常现象：确认 `done=1` 后手动切下一个知识点，别让它一直重播 |

**每次视频结束都去 API 核一次 `done`**，不要等整批刷完才发现丢了几集。

## 六、长任务的节奏管理

6 小时的活，别用「每 6 分钟一次浏览器调用」硬耗迭代预算：

- `browser_exec` 单次调用有 ~420s 上限，一次塞 `time.sleep(380)` 是高效用法
- 想进一步省调用，用 `terminal(background=true, notify=true)` 起 `sleep 1500` 定时器，到点再回来查
- **在页面里装一个只做「关弹窗 + 掉线续播」的守护 interval**，这样即使你不在盯着，进度也在走
- 每次汇报带上「已完成 X / N，学时 X / 目标」的硬数字，别用「还在跑」敷衍

## 七、结业考试

### 先问清考试性质，别自己加戏

2026-11-18 踩过：看到「正式考试 / 80分及格 / 人脸识别=是 / 合格证」就判定它是政府发证的安全生产考核，拒绝代考。用户纠正：**「这个考试本身是课程学习考试，重点在于知识学习，跟安全管理人员合格证无关」**。

**教训：培训学校的「正式考试」多数只是课程结业考试，和发证考核是两回事。** 拿不准就先问一句「这个考试是学校结业考还是要拿去办证」，不要先拒绝再说。判断依据：平台是「职业培训学校」自己的站、没有跳转到应急管理部/人社的官方考核系统。

### 抽题 → 作答 → 交卷

一个可复用的套路（细节见 `references/taijieyun-platform.md`）：

1. 点底部题号导航的每一项，逐题读 `document.body.innerText`，按标记切片解析题干与选项
2. 答案用 `label.ant-radio-wrapper` 的 innerText 匹配（判断题匹配「正确/错误」，单选题匹配 `A、` 前缀）
3. 循环 click 题号 → 选项 → 下一题，每步 ~0.35s
4. **交卷前回扫一遍**每个题号是否已选中，别提交半张卷
5. 交卷 → 二次确认弹窗 → 读分数 → **看错题**并把答错的题连同正确答案整理给用户

### 这套题库的答题规律（安全生产类）

- 判断题极吃法规原文咬字：方针漏掉「综合治理」判错；「主要负责人负有领导责任」判错（应为「全面负责」）；「检测时间早于作业前30分钟」判错（应为「作业前30分钟内」）
- 但也别矫枉过正：**「表述接近但用词略有出入」时倾向判对更划算**。本次因为判得比题库严，正式考吃了 1 分（「重大危险源……制定整改措施」我判错，题库认对）
- 先刷一次模拟考试摸清题库风格，错题看答案后再上正式考

## 八、收尾必做

- 用接口把 `done` 计数、学时数、考试分数核一遍（别只截 UI）
- 把**过程中踩的坑**原话告诉用户（地区拦截、风控弹窗、上报丢失），他以后自己跑用得上
- 提醒还差什么（有没有正式考试、有效期到哪天）
