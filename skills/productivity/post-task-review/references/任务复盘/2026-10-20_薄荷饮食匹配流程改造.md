# 任务复盘：薄荷饮食匹配流程改造（两步分工 + 大模型语义匹配）

- **日期**：2026-10-20
- **任务目标**：把「菜名 → 薄荷条目」的字符串精确匹配升级为大模型语义匹配，
  并在过程中解决薄荷付费额度被一顿早餐烧掉 23 次（上限 50/天）的问题。

---

## 实际流程（偏离预期的点）

**预期**：改个匹配函数，半天收工。

**实际**：分成了四个独立阶段，每个阶段都发现前一阶段有漏。

1. **额度诊断**（用户先提的）→ 查出根因不是「选词差」，是**盲批探测**
2. **两步分工**（用户提的方案）→ 免费锚定 code + 付费抓营养素
3. **语义匹配**（用户要求）→ 规则分级 + `llm_pick()`
4. **落实与验收**（用户要求）→ 发现**只改了 skill 正文没改触发条件**，等于没落实

**最大的偏离**：我原以为「改完工具就完事」，实际**工具改完只完成了 1/3**，
另外 2/3 是「触发条件」和「机制兜底」。

## 最终结果

**额度**：一顿 4 样 23 次 → 首次 4 次 / 缓存后 0 次。

**准确率**：8/8 全对（贝贝南瓜、蒸番薯、全脂牛奶、茶叶蛋、米饭、清炒菠菜、番茄炒蛋、凉拌牛肉）。

**落点**：6/6 全部到位（skill description、MEMORY 口述直录、MEMORY 额度纪律、
health-analysis 指针、skill 两步分工正文、旧描述清零）。

**机制兜底**（不依赖它记性）：
- `boohee.quota_now()` — 额度前后对比一次调用
- `two_step()` 输出自带 `warnings` — 嘌呤假 0 / 糖假 0 / 饱和脂肪假 0 / 做法词匹配到 basic

## 可优化点

1. **验收任务书不能写答案**
   第一次验收我在任务书里写了「用 `two_step()`，不要手写搜索循环」，
   **等于喂答案，验不出它到底学没学会**。
   第二次改成只给场景、一字不提工具名，才真正验出来（4/5，并暴露第 2 题的知识空白）。

2. **「改 skill」要分三件事，缺一不可**
   - 正文（内容对不对）
   - `description`（**会不会被加载**）
   - memory 指针（**什么时候想起来**）
   只改第一条 = 写了一本没人翻的说明书。这次差点就这么交差。

3. **端到端跑一次的价值 > 盯十遍代码**
   第 5、6 两个坑（做法词剥离、裸名降权漏洞），**代码看着都对**，
   是让健康助理真跑一次午餐才暴露的。它跑出来的 `菠菜(煮) 27.6kcal` 是我自己测不出来的。

4. **错误记录要标「实测日期」**
   「公开接口缺钙」这条错记录挂了整整一天才被发现。
   如果当初写成「2026-10-20 实测」，就不会被当成长期结论复用。
