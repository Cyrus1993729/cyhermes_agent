**Claude Code 含在所有付费档**，与聊天/网页共用同一个额度池（官方 FAQ 明写）。

## 二、🔴 决定性的一行：能不能程序化调用

- **Pro 没有 API access**（feature grid 里 `Monthly API credits` = No）→ 接不进 Hermes 主链路，只能 `claude -p` 子进程或人肉用界面。
- **Max $100 / Ultra $200 各附等额 API credits**（"$100 a month in API credits to build on the Claude Platform"）。这是「想要订阅额度 + 又想让程序调」唯一并存的档位。
- 付费档都能开 **usage credits**：撞限后**按标准 API 价继续用**（第三方报 $2,000/天兑换上限）→ 等于自动降级成按量付费。
- **Fable**：Max/Ultra 含在每周额度的 50% 内；**Pro 只能靠 usage credits**。
- **Opus 5.5**：Pro 起就有（Free 只有 Sonnet/Haiku 级）。

### SemiAnalysis 对照（2026-10-05，受控测试）

- Ultra 全用 Opus 5.5、agentic 负载（96.6% 缓存读）≈ **$11,726/月**
- 同上但 chat 负载 ≈ **$9,200/月**

## 五、换算公式（把订阅额度落到「我们能用多少次」）

```
单次成本 = (非缓存输入×4 + 缓存读×0.20 + 输出×20) / 1e6      # Opus 5.5
```
本机两个画像：
- **近 30 天**（6,470 非缓存 in / 128,780 缓存读 / 910 out）= **$0.0698/次** → 全量 8,315 次 = **$580.75/月**
- 全历史（4,800 / 114,850 / 863）= **$0.0594/次**

```
窗口内可用调用数 = 窗口美元等值 ÷ 单次成本
Pro: $12 ÷ $0.070 ≈ 172 次/5h   ← 与「最重一天 1,116 次」直接对撞
月可用调用数   = $673 ÷ $0.070 ≈ 9,600 次/月（名义值，实际受窗口卡死）
```

🔴 **别只报「$673 够 9,600 次」**：5h 窗口每天只放行约 1.85 个，重活日一天要撞 2–6 次。**窗口形状比总额更能决定能不能用。**

## 六、结论模板

1. 先声明**没有官方数字**，给实测区间 + 账号数 + 测量周。
2. 立刻补 `Monthly API credits` 那一行——**能不能接 Hermes 由它决定，不是额度**。
3. 用「5h 窗口 ÷ 单次成本」对上用户自己的最重一天，判断会不会撞墙。
4. 与聚合站对比时，用「每 $1 换多少目标模型额度」一栏：Pro **34×** vs Kilo 年付 1.5× / OpenDesign 年付 2.0×——但必须同时给出「订阅只能人肉兑现」这条限制，否则等于推荐了一个用户根本用不上的方案。
