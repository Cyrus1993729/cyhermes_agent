# 个股财报分析 + 解释股价反应（2026-08 龙湖集团案例沉淀）

场景：用户给一家公司（如龙湖 00960.HK）的财报/业绩预告，要求分析财务状况（对比往期、结合行业）、并回答"财报这么差为什么股价还涨"。

## 交付流程（已验证）

1. **数据收集（多期追溯）**：官方新闻稿/业绩会实录/财报 > 权威媒体 > 券商研报。用户明确要求"往期数据往前追溯几年"——至少覆盖峰值年（龙湖到 2021-2022）+ 最近 3 年 + 当期。半年报对比用 2024H1/2025H1/2026H1 同口径。
2. **材料组织（喂给 Opus 前）**：全部数据整理成表格，每项标注 **（已核实）**=官方/权威来源 / **（推算）**=由相邻年份披露推算。单独一节行业背景（全国商品房销售额、百强房企、政策），一节公司业务布局。**推算值必须能由材料内数字四则运算还原**（如 2024 末有息负债 = 2025 末 + 压降额）。
3. **Opus 分析调用**：`export HTTP_PROXY/HTTPS_PROXY` + smoke test → `claude -p --model opus --max-turns 3 --disallowedTools Read Write Edit Bash Glob Grep WebFetch WebSearch TodoWrite < prompt.txt`（prompt 内联全部数据材料，禁工具防它搜网）。要求输出：长周期趋势/半年报对比/行业定位/业务转型评估/风险清单/定性结论，中文。
4. **交付**：全文内联进回复（系统自动拆条），归档到 `D:\Workspace\output\YYYY-MM-DD_主题_Opus分析.md`。**归档大文件用首写+patch 追加分段**（单次 write_file >~8K tokens 会流超时——先 write_file 第一部分，再用 patch 以"文件末尾唯一行"为锚追加 2-3 次；grep 验证无重复）。
5. **用户追问深化**：如"分析现金流风险"→ 补搜专项数据（现金流量表、受限资金、到期债务分布、抵押率），同样整理成材料再发 Opus 专项分析。

## 关键分析框架：财报质量 ≠ 股价方向（回答"为什么股价还涨"）

当用户质疑"你分析压力大 / 财报差，为什么股价涨 / 机构都不这么认为"时，用以下框架（2026-08 龙湖股价 +6~8% vs 现金流风险中高 案例验证有效）：

1. **信用视角 vs 股权视角**：现金流/偿债分析是债权人视角（防守，看断裂点）；股价是股权视角（看"会不会死"）。区分时间窗——"12 个月违约风险低"和"2027-28 压力窗口"可以同时成立，市场只定价前者。
2. **预期差定价**：明星基本面恶化公司，利空被提前 price in 后，兑现日反而跌不动甚至反弹（龙湖 8/14 预告日 -1.2%、8/12 提前抢跑 +8.8%）。"没有超预期利空 = 没有下跌理由"。
3. **定价锚切换**：行业下行期市场从"利润"锚切到"存活"锚——正向经营现金流、境内信用债偿清、零违约记录这些"安全信号"比利润数字更值钱（民企地产尤其如此）。
4. **边际交易者决定股价**：被动指数/南下/事件驱动资金 ≠ 看报表的资金。股价不是"专业机构共识"的投票，是最后出价者的投票。
5. **银行信贷行为是最"唯物主义"的信用投票**：银行掌握现金流实况，若持续放贷（如经营性物业贷年新增 180 亿）说明短期信用被最懂内情的债权人认可。但注意动机可能是抵押品逻辑，要辩证。
6. **低估值容错**：PB 0.3 倍的公司，市场买的是"深度折价已覆盖尾部风险"，不是"看好基本面向好"。
7. **诚实声明**：分析中带假设（LTV、运营底仓现金），标"（推测）"并列出盲区清单（受限资金明细、利息是否已含在经营现金流、抵押资产占比等）——这些决定结论在乐观/悲观之间摆动，让用户自己判断信息完整度。

## 坑

- 用户对价格/数据准确性质疑多——涉及具体数字必须来自材料或"推算"标注，禁止凭记忆报价。
- 正式财报未出时（如只有业绩预告）要明示数据边界，预告出正式中报后可再让 Opus 更新。
- 别把"中高"风险读成"高危"——给三情景概率（基准/悲观/乐观）和触发条件清单，让风险判断可证伪。
