# Company Financial Analysis（上市公司财务深度分析）

单家公司基本面/信用深度分析工作流：数据搜集（多期追溯+行业结合）→ 数据分级 → 外部模型（Opus）深度分析 → 完整交付 + 归档。2026-08-26 龙湖集团两次分析（财报全盘 + 现金流专项）定型。

## 触发

- 用户要求分析某上市公司的财报/中报/年报/业绩/财务状况/现金流风险/债务风险
- 用户给了公司名 + 报告期（如"龙湖发布了最新的财报数据（26年中报）"）

## 用户偏好（本任务类，2026-08-26 用户明确纠正后定型）

1. **往期数据多往前追溯**：至少 4-5 年（含行业峰值期），如龙湖从 2021 年销售/利润峰值拉到 2026H1。只对比相邻两年会被批评"看不到长周期趋势"。
2. **分析必须结合行业变化 + 公司业务布局**：不能孤立看财务数字——行业总量（如全国商品房销售额腰斩）、同业位置（千亿房企名单）、公司战略转型（三航道）都要进分析。用户原话："分析财务状况时要结合行业变化和龙湖的业务布局"。
3. **对比要系统**：全年序列（峰值年→最新）+ 近三年半年报对比 + 最新预告/报告，三组都要。
4. 中文输出；交付物完整内联（禁"见terminal输出"）；归档 `D:\Workspace\output\YYYY-MM-DD_主题_模型.md`。
5. 用户重数据准确性：不能核实的数字要标注，禁止单源断言。

## 工作流（7 步）

### Step 1 数据搜集（多源，标注来源）
- **公司官网投资者关系页**（财务报告/公司公告/公司新闻）——港股公司公告时间线在官网公告列表
- **权威财经媒体**：新浪财经/证券时报/财新/每日经济新闻（业绩会实录常有官网没有的口径细节，如"剔监管现金短债 1.14 倍"）
- **第三方数据汇总**：moomoo 等现金流量表汇总页（快速拿多年经营/投资/筹资现金流序列）
- **注意财报节奏**：港股常有"业绩预告（如 8 月中）→ 正式中报（8 月底）"两步——预告只有利润区间+定性描述，正式报告才有分部明细；先预告后正式，两轮分析
- 行业背景数据：国家统计局/中指/克而瑞/财新的行业总量与结构数据（销售额峰谷、百强榜单、政策基调）

### Step 2 往期追溯 + 信息盲区预列
- 全年序列：峰值年（找行业/公司销售和利润双峰）→ 最新年度；近三年半年报对比；最新预告
- **主动列出"信息盲区"**（受限资金明细、减值计提、抵押率、表外负债等没披露的项）——交给外部模型时它会认为这是你已识别的风险点，输出质量显著提升

### Step 3 数据分级标注（关键，2026-08-26 验证有效）
每条数据标：
- `（✓已核实）` = 官方/权威来源直接披露
- `（推算）` = 相邻年份推算/算术推导（如 综合借贷 = 下一年 + 净压降）
- 把**材料内部矛盾点**明文列出交给外部模型验证（如"账面现金短债 1.85 vs 剔监管 1.14→反推非受限现金 180 亿"，验证后三组数字闭合才可采信）
- 时点矛盾要修正（如预告确认"2026 境内信用债已偿清"→原到期表 61 亿应修正为 36 亿）

### Step 4 Opus 深度分析
- 材料组织进 prompt 文件：用户诉求 + 输出要求（分节/数据支撑/标注推测/核心结论 3-5 条/风险清单）+ 材料一到 N（含行业背景、业务布局、管理层指引、已知矛盾、信息盲区清单）
- 调用姿势（详见 claude-code / claude-code-workflow）：
  ```bash
  export HTTP_PROXY="http://127.0.0.1:7897" HTTPS_PROXY="http://127.0.0.1:7897"
  timeout 60 claude -p "回复OK" --model opus --max-turns 1   # smoke test 先行
  timeout 580 claude -p --model opus --max-turns 3 --output-format text \
    --disallowedTools Read Write Edit Bash Glob Grep WebFetch WebSearch TodoWrite \
    < C:/Users/Administrator/hermes_output/<case>_opus.txt
  ```
  - 🔴 -p 沙箱无文件系统：材料必须内联进 prompt，不能给路径
  - 🔴 --disallowedTools 空格分隔不带引号；禁止 `--tools ""`（禁不住）
  - 输出要求写死：中文、每个判断带数据、材料外推断标"（推测）"、结尾核心结论+风险清单、不给买卖建议
- 后续跟进问题（如现金流专项）新建一个 prompt 文件，把上一轮结论作为"背景判断（可引用但需用本材料验证）"交进去，避免重复全盘分析

### Step 5 交付（完整内联 + 分段）
- 完整内联，禁止"见 terminal 输出"；开头 2-3 行结论前置
- 超长分段：每段 ≤3800 字符 + 段间跟一个工具调用（`terminal echo seg-N`）维持 run flush（帖 1-6 交付模式，同 trendradar-operations 补发姿势）
- 用户要"分析 XX 风险"这类深化：可以在交付后主动提出后续跟踪（先行指标列表、正式报告发布后更新）

### Step 6 归档
`D:\Workspace\output\YYYY-MM-DD_主题_模型.md`（memory 归档惯例）。**大文件拆分写入**（见 Pitfalls）。

### Step 7 后续跟踪
给出"关键观测指标 + 阈值"（Opus 输出的先行指标表直接复用）；正式报告发布后可再跑一轮 Step 1-4 更新。

## Pitfalls

1. 🔴 **大文件写入流超时（2026-08-26 实踩）**：单次 write_file 参数过大（>~8K tokens）会触发"stream timed out"且内容不落盘。**归档长文/长报告拆多次写入**：第一次 `write_file` 写头部 + 后续 `patch`（old_string=当前文件末尾一行原文，new_string=该行+追加内容）逐段追加。patch 的 old_string 必须用文件中真实存在的行（刚写入的末段），不要臆测标题。追加后 grep 计数验证无重复。
2. **业绩预告 vs 正式报告口径**：预告期数字（如"2026 剩余到期 61 亿"）可能被预告内容（"境内信用债已全部偿清"）推翻——交付前把时点修正写进分析，标注"修正后约 36 亿"。
3. **房企分析特有指标**（龙湖案例，详见 references）：剔受限现金短债倍数（账面 1.85 vs 剔监管 1.14）、预售监管资金=负债镜像不可偿债、抵押率（非抵押债务占比）、经营性物业贷 LTV 传导链（估值 -20% → 补抵押缺口可能超全部非受限现金）、利息覆盖倍数。分析房企/高杠杆公司必须把"受限资金/抵押率/监管资金"找全，账面现金短债会严重高估安全垫。
4. **材料给 Opus 时注明口径差异**（会计口径经营现金流 vs 管理口径含资本开支）：管理口径"连续三年为正"可能是砍资本开支买来的——把反事实检验（若维持旧资本开支强度会怎样）交给 Opus 算。
5. **信息盲区要主动承认**：Opus 会列出影响结论方向的待澄清项（如"经营现金流是否已扣利息 → 缺口 124 亿 vs 285 亿摆动"）——交付时标为"下次业绩会/IR 优先问"，这是分析可信度的加分项不是缺陷。
