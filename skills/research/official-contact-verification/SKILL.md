# 官方联系方式核实

用户说「帮我找 X 的联系方式」「我想咨询 X 几个问题」时，交付物不是一串号码，而是**一条能走通的路径**：谁是权威答复方、哪个号码是一手号、哪些号别打、开口问什么。

核心判断：**法定/政策类问题（注册地址、集群登记、扶持政策、备案状态），只有属地登记机关和载体产权方/运营方能给确定性答案。**中介、招商软文、第三方目录答不了，即使它们看起来最像「招商热线」。

## When to Use

- 「帮我找这个园区/公司/政府窗口的联系方式，我想咨询…」
- 用户贴截图/文章/名片，里面有联系电话，要判断能不能用
- 要问注册地址、住所托管、补贴申报、资质准入这类**必须落到具体窗口**的问题
- 同一地址出现多个机构名称，需要理清谁建、谁运营、谁管

## 渠道分级（先定级，再交付）

| 级别 | 来源 | 用法 |
|---|---|---|
| ✅ 一手 | 运营主体官网（页脚/联系我们/多页一致）、企查查工商登记电话、政府官网「联系方式」栏目 | 直接给，标注已核实 |
| ✅ 一手 | 政府官网政策原文、「一网通办/服务专区」入口 | 给链接，政策口径以原文为准 |
| ⚠️ 二手 | 政府新闻稿里提到的主体名（不含电话）、集团母公司总机 | 给，但说明「是总机，需转对口部门」 |
| ❌ 噪声 | 搜狐/网易号/写字楼信息网/招商名录的「招商热线」 | 明确点名让他别打 |

**关键：集团总机 ≠ 项目招商专线。** 交付时必须写清「这是 XX 公司总机，接通后要转 XX 部门」，否则用户打过去被踢皮球。

## 中介号识别（实证有效）

命中任意一条即降级为噪声号：

1. **同一号码被挂在多个不同楼盘/园区名下** —— 租售中介平台共用号。实测：`0512-6716-8381` 在搜狐/网易上同时是「南岸新地招商热线」「苏州国际科技园官方租赁电话」「颐高园区招商电话」。
2. 页面含「【中介勿扰】」「物业直租」「开发商出租」「网上咨询中心」「一对一专业讲解」「请提前预约看房」—— 售楼软文模板。
3. 号码只在聚合站/自媒体出现，**运营主体官网全站搜不到**。
4. 手机号+姓名只在「第三方目录」出现，且**搜号码全网零中文命中** —— 直接判不可用，如实告诉用户「查无出处」。

## 核实流程

① **先把主体关系理清。** 同一地址多个名称时，先查：谁拿的地、谁建的、谁运营的、谁招商的。政府新闻稿 + 运营方官网「发展历程」是最快的证据链。判断错这一步，后面所有渠道都会指错人。

   高德 POI 可用来验证「两个名字是不是同一栋」：`mcp__amap__maps_text_search` 搜出 POI → `mcp__amap__maps_search_detail` 看 `location` 坐标。实测「EGO苏州跨境电商产业园」POI 文字地址写「娄江大道1548号」，但坐标与「扬富路11号3号楼·苏州市跨境电商创新中心」几乎重合 → 同一片载体，POI 文案地址有误。**坐标可信度高于 POI 文字地址。**

② **每个号码至少两个独立来源交叉。** 目标形态：运营方官网多个页面一致 + 企查查/官方栏目佐证。只有单一来源就标「未核实」。

③ **搜号码反查。** 把候选号码原样加引号搜索（`"0512-xxxxxxx"`），看它被安在几个主体头上、出现在什么站点。这一步是剔除中介号最有效的手段。

④ **找权威答复方。** 政策/登记类问题，交付物里必须给出一个政府侧号码或线上入口，不能只给园区招商号。产业专班常驻的**专项服务中心**优先级最高——它既权威又免费（例：苏州市跨境电商一站式服务中心，市商务局/海关/税务/外管局专班入驻，每周三固定服务）。

⑤ **集团总机之外，去挖「项目子站」里的招商专线。** 运营方官网的「联系我们/关于我们」页通常只印集团总机，项目本身的招商热线印在**项目子站**里。做法：抓官网首页所有 `href` 找子站路径（实测 `sipurd.com/xdfwgc/index.html` = 南岸新地项目页，页脚写着「招商热线：+86-0512-66606111」），再抓该页 grep 号码与「招商」上下文。

   **用户追问「找不到 X 的联系电话吗」= 他相信有、要你再挖一层，不是让你复述上一轮的结论。** 一次没找到 ≠ 没有，换路径：项目子站 → 招商栏目 → 政府新闻稿 → 官方公众号 → 企查查年报电话。

   抓号码用 curl 落盘再 grep，比抽取器稳（政企官网对 `web_extract` 常超时，或返回别的页面内容）：

   ```bash
   curl -sk -m 40 -A 'Mozilla/5.0' 'URL' -o "$LOCALAPPDATA/Temp/pg.html" -w '%{http_code}\n'
   grep -oE '0?[0-9]{3,4}[- ]?[0-9]{7,8}|1[3-9][0-9]{9}' "$LOCALAPPDATA/Temp/pg.html" | sort -u
   grep -oE '.{0,25}招商.{0,40}' "$LOCALAPPDATA/Temp/pg.html"
   ```

   `http://` 打不开先换 `https://`。

⑥ **翻页兜底。** 官网首页/备案页打不开时（超时），用 `web_search` 搜「站内特征串 + 电话」——搜索引擎缓存描述常直接带出官网页脚的地址电话，往往比抓页面更快更全。号码命中多页一致即可采信。

⑦ **官方公众号/服务号是有效渠道，尤其民营运营商。** 颐高这类民营园区把招商联系人放公众号里、官网只留集团 400。用户自己从公众号找到时，**别重复输出，只补他没的那部分**。

## 输出格式（用户偏好，照做）

- 分渠道列，**每条号后面标核实状态**：✅ 官网核实 / ⚠️ 总机需转部门 / ❓ 第三方未核实 / ❌ 别打。
- 每条号注明**性质**（集团总机 / 招商专线 / 政策窗口 / 物业）和**地址门牌差异**（总部地址 ≠ 园区地址时要点破）。
- 单辟一节「别打这些」，点名噪声号并说明判定依据 —— 用户自己搜到会以为是官方号。
- 末尾给**纯文本可复制话术**（见 `templates/inquiry-message.md`）。用户明确要求可整段复制的纯文本，不要选项按钮/下拉档位。
- 最后给**咨询顺序建议**：先政府窗口问口径 → 再拿口径去谈园区。
- 用户中途说「我已经在官方公众号找到了 X」→ **只补他没找到的那半**，别把已给过的内容再讲一遍。
- 结尾点出**一处落地前必须回头核实的风险点**（例：注册地址证明由产权方出还是二房东出，错了登记会被卡）。

## Pitfalls

- **把「入驻运营方」当成「产权方」。** 同一个园区里常有多个运营方（政府平台公司 + 民营运营商），注册地址证明的出具权在产权方手里。交付前必须点明这层关系。
- **只看截图里的电话就回答。** 截图常自带「第三方目录，未核实」，照抄等于背书。
- **拿中介号当主推渠道。** 用户打过去只会被推销场地，得不到政策口径。
- **政策口径自己推断。** 「某地有没有集群注册」这类问题，各地落地形式不同（如苏州是「商务秘书公司住所托管」而非常规集群登记），只能引用原文或让用户问窗口，不要替政府下结论。
- **不核就说「已确认」。** 抓不到的页面、搜不到的号码，如实写「查无出处」，别用别的号顶上。
- **只看集团总机就下「查不到招商专线」的结论。** 这是本 skill 最贵的坑：只抓了官网「联系方式」页，把集团总机当成唯一号码交付，被用户当面追问。项目子站往往就在同一域名下（`/xdfwgc/index.html` 这类），必须先翻子站再下结论。
- **交付里漏掉政府侧专项窗口。** 园区招商说政策一定比窗口宽松，专项服务中心（专班入驻、有固定服务日）才是用户「问扶持政策」的落点；而「这地址能不能注册」只有产权方和市监窗口能答，招商代理答不了。
