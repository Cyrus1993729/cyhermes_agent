## 一、饮食核算(最高频)

**逐项列出**食物 → 用食物成分表算 蛋白/脂肪/碳水 → **算术自检** → 对比目标 → 落盘。

### 🔴 核算一律走引擎（2026-11-13 起，他拍板试行）

**不要再用临时脚本一步步试算。** 算术部分统一交给通用引擎：

```
C:\Users\Administrator\health\tools\nutri_calc.py
```

两步，别多：

1. `write_file` 写一个 spec 文件，逐项列出：`name` / `source` / `grams` / `per100` / `purine`
2. `terminal` 跑它：`cd C:/Users/Administrator/health/tools && python <spec文件名>.py`

spec 里只放**判断**（取哪条食物数据、克数、入口比例、来源标签）；
引擎负责**算术**（逐项表 / 合计 / 算术自检 / 未收录项 ⚠️ 提示）。

引擎**不做**的事，仍要自己做：
- 看图确认商品参数（`vision_analyze`，酱汁标签这类必须看）
- 口径判断（入口比例、可食率、拆分比例、生熟口径）
- 口径说明散文、假设清单

### 🔴 成品菜先查条目，再决定拆不拆（2026-11-13 他要求）

核算一道**复合菜**（香菇青菜、白菜炖肉、番茄炒蛋、鱼香肉丝…）时，
**必须先免费 `anchor()` 查一遍菜名**，不许直接拆成单料。口径说明里写明是哪种：

1. **查到且适用** → 用成品条：「已查，命中 `<code>` `<菜名>` XX 卡，采用」
2. **查到但不适用**（无油盐版/少油商品版 vs 食堂家常）→ 拆项：
   「已查，命中 `<code>` `<菜名>` XX 卡，因<理由>不采用，改拆项」
3. **查不到** → 拆项：「已查 `<试过的词>`，薄荷无成品条，按单料拆项」

`anchor()` 纯免费，多试几个词（全名／换语序／加去做法词）。

**四个已固化口径，不许改**

- **每 100 g 值取薄荷公布的 1 位小数** —— 用 `norm1(kcal=65, P=1.18, F=0.08, ...)` 归一。
  直接用 `cache.json` 的多位原始值会让分项与历史档案差 0.01~0.08（2026-11-13 实测）。
- **沙拉按历史构成等比拆分时保留 0.1 g** —— 用 `split_by_ratio(total, ratios, ndigits=1)`。
  保留 2 位小数会让热量差 0.01、钠差 0.07，与历史档案对不上（2026-11-13 实测）。
- **来源标签栏不可省** —— 引擎只消除算术错误，**不消除取数错误**。
  查错了食物条目，引擎会忠实地把错误放大到合计。
- **没收录的字段按 0 计，但必须标出来**，引擎会打 ⚠️。**不许编数。**
- **调味钠差额这类直接给值的行**用 `DirectItem(values=dict(Na=...))`，不走「每 100 g × 克数」。

🔴 **自检铁律**:`蛋白×4 + 碳水×4 + 脂肪×9` 必须等于所报总热量。
对不上就说明数据有错,**先纠正再评价**。已实测两次出错:

- 某日自报"910 kcal / 蛋白 98g / 脂肪 24g / 碳水 210g" → 反算 1448 kcal,差 538
- 用手指食物清单逐项复算,真实约 1300 kcal / 蛋白 116g / 脂肪 31g / 碳水 157g
- 结论:**「碳水 210g」是错的,真实约 76g**(用 910 反推 + 它自己列的碳水来源吻合)

**生重→熟重折算**(干重/可食部问题):
- 例:白灼虾生重 350g(带壳带头)→ 可食率 ~60% → 生可食 210g → 熟制失水 ~12% → **熟可食 ~185g**(系数 0.528)
- 营养按**生可食部**折算,因为烹饪只失水、蛋白脂肪不流失
- 敏感区间:可食率 55–65%、失水 8–15% → 熟可食 164–209g

## 一·B 运动消耗核算（2026-10-31 补：之前本 skill 完全没有这块）

**先定档再算数**，三档口径见 `references/tdee-deficit-calibration.md`：
档 A 无额外运动／档 B 外出步行／档 C 正式运动（力量训练、羽毛球、跑步机=档 C）。

```
净增 = (MET − 1) × 体重 kg × 小时
全天 TDEE = 基线 2198.8 + 净增
```

🔴 **一律用净增 `(MET − 1)`，不用满额 MET** —— 基线 PAL 1.25 已含静息，满额就是重复计一遍静息。

**MET 取值（Compendium of Physical Activities 2011，标来源时必须写这个出处）**

| 项目 | 档位 | MET |
|:--|:--|:--:|
| 力量训练 | 轻 3.5｜**常规抗阻 5.0（中等强度主值）**｜大重量多组短休息 6.0 | 3.5–6.0 |
| 跑步机 | 按「距离 ÷ 时间」反推实际配速再对表 | 见下 |
| 羽毛球双打 | 中低强度 4.5｜中高强度 5.5 | 4.5–5.5 |
| 有氧快走 | 6.4 km/h 平地 ≈ 5.0〔17190, 4.0 mph〕；**5.0 km/h ≈ 3.4–3.8**（平地 3.0 mph=3.3、跑步机 4.8–5.5 km/h≈3.8，取 3.8） | 3.3–5.0 |
| 慢跑 | 7.2 km/h ≈ 7.0；8.0 km/h ≈ 8.3 | 7.0–8.3 |

🔴 **他给了强度定语就以他的话为准**，不要用自己的一般性推断覆盖。他说「中低强度」→ 取低档；
「有对抗性」不等于要往上抬档（2026-10-26 踩过）。

**每秒都要分段算的情形**：他说「慢跑 + 快走各半」这种混合有氧——
先用总距离÷总时间求出平均配速做交叉校验，再按两段的实际配速分别取 MET，**不许整段套一个平均 MET**。

### 🔴 阶段性铁律：运动可以记，赤字不能记

| 阶段 | 写进 `diet/` 的 | 明确不写 |
|:--|:--|:--|
| 报一餐 | 该餐各项 + 全天累计 | 赤字 |
| 报运动 | 运动净增 + **全天 TDEE** | 赤字 |
| 他说「吃完了」 | 才补 `赤字 = TDEE − 全天摄入` | — |

理由：他的加餐是临时的，赤字提前落盘 → 加餐一吃就要改两处，文件里出现两套账。
详见 `references/exercise-intensity-and-staged-logging-2026-10-26.md`。

**EPOC（运动后过量氧耗）不要记进档案**：中等强度抗阻一次约 11–28 卡，比任何测量误差都小，
记进去只会制造来源不明的几十卡。口径见 `references/epoc-and-resting-metabolism.md`。

## 四、安全边界(硬约束)

1. **用药决策不由你判断** —— 指标解读、风险分层、是否启动他汀/降尿酸药,一律交医生
2. **出现胸闷、胸痛、明显气短、活动耐量下降 → 立即建议就医**,不许"先观察看看"
3. **减重速率优先于减重总量** —— 宁可慢,不可快。目标区间 **0.35–0.70 kg/周**,超过就是在掉肌肉
4. 指标异常时**主动提示复查**,不自行下诊断结论
5. 不做"这个数字没事"式的安慰性判断 —— 他明确要直率准确

### 🔴 六个坑（全部实测）

1. **必须 `cmd.exe /c` + `.cmd` 绝对路径** —— 直接调 `codex` 会 WinError 2（bash 的 PATH 不在 Windows PATH 里）

6. **stdout 含 ANSI 控制字符** —— 解析前先清洗：
   `re.sub(r'\x1b\[[0-9;]*[a-zA-Z]', '', text)`；

## 六、已知陷阱

- 🔴 **别把临床惯例说成指南原文**。「嘌呤 300mg/天」**不在《成人高尿酸血症与痛风食养指南2024》里**——指南全文无任何 mg/天 数字，只给噦呤四分类（mg/100g）+「以低嘌呤膳食为主」。引用阈值时必须标明「指南原文」还是「临床惯例」。详见 `profile.md` 六节「阈值口径」。

## 八、🔴 血脂风险分层流程（2026-10-23 新增）

**每次讨论血脂，先做分层，再谈目标值。** 不分层就说「LDL 要降到 xx」是错的——目标值完全取决于风险等级。

依据：《中国血脂管理指南（2023年）》+《基层版2024年》。他的具体结果见 `profile.md` 第十四节。

### 七步流程

```
1. 先判是否已患 ASCVD → 是则二级预防（极高危 / 超高危两组）
2. 未患病 → 一级预防，先排除三条「直接判高危」（符合任一即高危，不进 21 格表）：
   ① LDL-C ≥4.9 或 TC ≥7.2 mmol/L
   ② 年龄 ≥40 岁的糖尿病
   ③ CKD 3~4 期
3. 都不符合 → 查 21 格表（LDL-C/TC 三档 × 有无高血压 × 其他危险因素 0/1/2/3）
   🔴「其他危险因素」只有三个：吸烟、低 HDL-C(<1.0)、年龄≥45男/≥55女
   🔴 高血压单独一维，不重复计入这三个 —— 这是最容易算错的一处
4. 10 年风险 <5% 低危 ｜ 5~9% 中危 ｜ ≥10% 高危
5. 中危且 <55 岁 → 再查余生风险（5 条中 ≥2 条 = 高危）：
   收缩压≥160 或舒张压≥100 ／ 非HDL-C≥5.2 ／ HDL-C<1.0 ／ BMI≥28 ／ 吸烟
6. 分层 → LDL 目标：低危<3.4 ｜ 中高危<2.6 ｜ 极高危<1.8且降>50% ｜ 超高危<1.4且降>50%
   非HDL-C 目标 = LDL 目标 + 0.8
7. 中危人群另查「风险增强因素」表（非HDL-C≥4.9／ApoB≥1.3／Lp(a)≥500／
   TG≥2.3／hsCRP≥2.0／肥胖或腹型肥胖／早发心血管病家族史），
   多个时「更倾向按高危处理」——但几个算多个是临床判断，不是你能拍板的
```

### 🔴 五个必须记住的坑

1. **「非 HDL-C 4.1」和「非 HDL-C 4.2」是两个不同的数，都在指南里。**
   表3「低危人群参考标准」合适水平 **<4.1**；表7 注「非 HDL-C 目标 = LDL 目标 + 0.8」→ 低危目标 **<4.2**。
   **参考标准 ≠ 治疗目标。** 混用会被医生当场问住。
   （另：《混合型高脂血症基层诊疗中国专家共识2024》表2 把低危非 HDL-C 目标写成 <4.1，与 2023 指南不一致，遇到时照实说明分歧。）

2. **低危的 LDL<3.4 是 Ⅱa 类推荐 / B 级证据，不是 Ⅰ 类 / A 级。**
   中高危/极高危/超高危才是 Ⅰ/A。**这个强度差异直接关系到要不要吃药**，引用时必须带上。

3. **「直接判高危」的余量要单独算。**
   他 TC 6.91，距 7.2 只差 0.29 —— 一旦跨过去，21 格表作废，目标从 3.4 直接变 2.6。
   报分层结果时**必须同时报这个余量**，否则是只报好消息。

4. **21 格表算不出「血管上已经有的东西」。**
   模型预测的是 10 年发病概率，主动脉钙化、颈动脉斑块这类**已经存在的结构改变不在模型内**。「低危」不等于「血管没问题」。

5. **他是低危也没用——先看有没有风险增强因素。**
   指南对「按流程不高但临床上不放心」单列一张表；他的非 HDL-C 5.45（≥4.9）和 TG 3.27（≥2.3）两项都命中。
   **「倾向按高危处理」这句话必须转达，不能筛掉。**

### 输出时必须带的免责

**分层是「按指南表格推算」，不是诊断。最终由医生拍板。**
问诊的正确姿势不是要求医生放宽标准，而是**拿指南表格去核对，把决定权交回医生**。
