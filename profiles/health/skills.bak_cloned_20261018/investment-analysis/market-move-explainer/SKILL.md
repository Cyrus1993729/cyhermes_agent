# Market Move Explainer（行情截图解读 + 涨跌归因）

## 何时用

用户：
- 发来行情软件截图（K 线图 / 分时 / 盘口），问走势、形态、或者"这两张图怎么不一样"
- 问"最近为什么跌/涨成这样""是不是因为 XX"
- 问"帮我看看这段走势"（如"这两天的黄金走势我有点看不懂了，帮我解释一下"）

**交付物 = 一个有可验证数字支撑的解释，不是预测。** 与 `investment-analysis` 的分工：那个是"搭评分系统"（长周期工程），这个是"回答眼前这一问"（单轮问答）。

---

## 铁律一：图表截图只信「印刷数字」，不信 K 线形状

🔴 **vision 读 K 线图时，逐根蜡烛的形态和总根数在多次读取间会自相矛盾。** 2026-10-08 实踩：同一张日 K 图，三次读取分别得出"从最高点起 14-15 根""5-6 根""8 根"。视觉得出的根数/阴阳**不能当结论报给用户**。

**可以稳定读到的（都是图上的文字，不是形状）：**
- 坐标轴刻度与时间轴月份（定时间跨度）
- **均线数值标签**（MA5/MA10/MA20 的具体数字 —— 信息量最大的一处）
- 高低点标注价、当前价、涨跌幅、昨收、成交量、振幅
- 周期标签（分时/日K/周K/月K）、标的代码、收盘时间戳

**提高读取质量的两招：**
1. 先全图读「文字型事实」，再对**绘图区**做 region 裁剪（`vision_analyze` 的 `region` 参数用原图像素坐标），问**窄而客观**的问题 —— "最高点那根在最右边第几根" 远比 "分析一下走势" 可靠。
2. 即使如此，回答里对视觉读出量用区间措辞（"大约 8 根"），把**可算的量交给铁律二**。

> 反面教训：把视觉数出来的"跌了 14 根"当成事实写进回答，会被用户拿着图对账。

## 铁律二：用公开数据源重建 OHLC，再回答

截图上给了最后收盘价和日期，就去公开历史数据表把连续序列取回来重建：

**链式自检（必做）**：相邻两日 `前一日收盘 × (1 + 当日涨跌幅) ≈ 当日收盘`。
- 全部对上 → 数据可信、日期对齐正确，可以放心拿来算
- 对不上 → 日期错位 / 取错标的 / 截图里的"昨收"指的不是你以为的那天，全部推倒重来

重建之后所有量都能算，不再靠肉眼：单日涨跌、周涨跌、距高点回撤、**哪天贡献了大部分跌幅**。最后一项直接决定归因怎么写（见铁律四）。

> 实例模板见 `references/nasdaq-2026-10-week.md`：从 investing 的 NDX 历史表重建 10/08-10/16 六个交易日，逐日涨跌幅全部自洽，得出周跌 **-5.49%（-1,696 点）**、距 52 周高点 **-6.93%**，并发现**周三+周五两天贡献了 81% 的跌幅**。

## 铁律三：日K/周K「看着不一样」的标准答法（高频问题，可直接套）

用户常问"周K看着只跌了一根，日K却跌了很久，是不是图有问题"。按这个顺序讲三层，别只讲一层：

1. **周期聚合**：1 根周K = 5 根日K（周一开盘当周开、周五收盘当周收、周内最高最低当上下影线）。日K上 N 根下跌 ÷ 5 ≈ 周K上应该出现的根数。**"周K只跌一根"往往是对的**——日K上那一整段，本来就只值周K上的一根。
2. **横轴跨度差 5-6 倍**：日K通常只显示 2-3 个月（~45 根），周K通常显示约 1 年（~52 根）。同一段下跌占日K图宽度约 18%、占周K图宽度约 3% → **这是"日K跌了很久 / 周K就跌了一下"的最大来源，是视觉占比，不是趋势不同。** 可用"地图 vs 放大镜"作比。
3. **均线周期也差 5 倍，且排列可能相反**：日K的 MA5/10/20 = 5/10/20 个**交易日**（≈1周/2周/1月），周K的 = 5/10/20 个**周**（≈1月/2.5月/5月）。**这才是"趋势不一样"的技术本质**：2026-10-08 实例中日线 `MA5 30061 < MA10 30537 ≈ MA20 30524`（空头排列，短期已转跌），周线 `MA5 30226 > MA10 29883 > MA20 29541`（多头排列，中长期未破）。

**收尾必须给用法**：周K定方向、日K定时机；只看一张必得片面结论（只看周K觉得"没事"容易高位接盘，只看日K觉得"崩了"容易割在回调尾巴）。

## 铁律四：归因要分「触发因」和「放大因」，并主动找反证日

🔴 **不要用当天头条解释当天涨跌。** 做法：
1. 把这一周**逐日**涨跌列出来（铁律二给的数据），标出哪几天贡献了大部分跌幅
2. **逐日**去找当天的主导新闻 —— 不同日子常常由完全不同的东西驱动
3. **主动检查反证**：某个假设如果成立，应该有某天的表现与之矛盾

> 2026-10-08 实例：用户问"是不是因为加息预期"。周三 -2.02% 确实是（CPI 爆表 → 当月加息概率 22%→37%）。**但周五 -2.50% 时，当月加息概率反而从 28% 降到 15%、美债收益率还回落了** —— 加息预期不可能是那天的主因，真凶是 AI 债务/信用事件。顺着用户的假设写就会给出错误归因。**用户提出假设时，要验证它，不是确认它。**

**表达结构**：A 是触发因（点火器），B 是放大因，写出两者打结的链条。例：

```
加息预期↑ → 融资成本↑ → 靠债务扩张的板块最先扛不住
          → 该板块权重股领跌 → 指数被拖着一起下
```

**看权重，不看板块本身**："某板块崩"≠"全市场崩"。必须给指数之间的对照（本次：道指 -0.34% / 标普500 -1.09% / 纳指100 -2.50%），并给出权重变化的量级（芯片占标普500 已从三四年前的 ~8% 升到 **>20%**）。**指数被单一板块绑住时，跌的是那个板块，不是整个市场。**

## 数据源清单（实测可用）

| 用途 | 来源 | 备注 |
|---|---|---|
| 指数历史 OHLC | `cn.investing.com/indices/<slug>-historical-data` | 含收盘/开/高/低/涨跌幅，整段可复制，最适合做铁律二的重建 |
| 各国股指 + 宏观 | tradingeconomics.com（中文站 `zh.tradingeconomics.com`） | 带月/年涨跌幅，可做横向对照 |
| 当日快讯（带时间戳） | `tags.news.sina.com.cn/<关键词>` | 滚动快讯密集，适合逐日找当天新闻 |
| 央行利率概率 | CME FedWatch（investing「美联储利率观测器」页 / 媒体转述） | 归因利率驱动时的**硬数据**，不同日期对比能直接证伪 |
| 事件日历 | FOMC/CPI/PPI 日历页、券商日历 | 判断"下周该盯什么"用 |

⚠️ 快讯标题经常与正文矛盾、时效性极强 → 关键数字至少两源交叉。
⚠️ 政策/利率概率这类数字，不同媒体的转述时点不同（同一天可能写出 37% / 45% / 28%）→ **写清是哪一天、什么时点**，或直接用同一来源做前后对比。

## 交付注意事项（针对本用户）

- 用户是**中长线 / 定投**（纳指定投 + 黄金积存金，年操作 1-2 次），落点要回到"**对他意味着什么**"，**不做点位预测**。
- 明确区分**归因梳理**（可以给）和**后市预测**（不给）；结尾一句话交代清楚。
- 数字给到可验证精度（`周跌 -5.49% / -1,696 点 / 距高点 -6.93%`），不要用"暴跌""重挫"这类无刻度词。用户对数字论断会核对。
- 截图里若同时出现两个不同标的/时区的数字（如场内 ETF 的 `+1.71%` 与美股指数的 `-2.50%`），**主动指出它们不是一回事**，避免用户混淆。
- 定投用户面对回调时，落点通常是"这正是定投机制在起作用"，而不是"该不该抄底"。
