# Financial Statement Analysis（上市公司财报深度分析）

## When to Use

用户要求分析某家上市公司财报/财务状况/中报/年报/业绩预告，尤其是说"让 Opus 分析"时。已实战验证：龙湖集团 2026 中报（`references/longfor-2026h1-case.md`）。

## 用户偏好（2026-08-26 龙湖案例确立）

1. **往期数据多往前追溯**：至少追溯到行业周期峰值（地产看 2021-2022），不要只对比上年同期
2. **结合行业变化**：把公司放进行业总量/竞争格局里解读（行业腰斩 vs 公司幅度：方向是共性、幅度是个体）
3. **结合公司业务布局**：多业务公司必须评估转型/新业务对冲旧业务的能力
4. **对比往期数据**：年度同环比 + 近三年同期半年报对照
5. 交付物完整内联（禁"见 terminal 输出"），中文输出

## 核心流程

### Step 1: 确认财报类型（陷阱最多）

- 8 月中旬的"中报"通常是**业绩预告**（如"归母净利预计 18-20 亿"区间值），正式中报月底才发布——分析时必须注明数据类型
- 公司官网"投资者关系-公司公告"列表可确认最新公告类型（业绩预告=盈利警告；营运数据=月度销售/经营性收入）

### Step 2: 数据收集（多轮 web_search，按需 4-8 轮）

- 近 5 年年度核心数据：营收/归母净利/核心净利（剔除公允值）/毛利率/合同销售额/有息负债/在手现金/净负债率/现金短债比/融资成本/平均借贷年期/新业务收入及占比
- 近 3 年同期半年报（如 2024H1/2025H1/2026H1）
- 最新月度/季度营运数据（销售、经营性收入、拿地）
- 行业总量数据：全国销售额/开发投资/新开工面积（统计局、中指、克而瑞、财新）
- 同业对比：百强名单、民营/央国企分化
- 权威顺序：公司官网业绩稿 > 港交所公告 > 证券时报/财新/每经 > 券商研报 PDF（东财）

### Step 3: 材料组装（给 Opus 的 prompt 文件）

- write_file 写到 `C:/Users/Administrator/hermes_output/<公司>_<报告期>_opus.txt`
- **数据来源标注**：已核实（✓ 官方/权威）vs 推算（相邻年份推导/四则运算）——不确定的显式标注而不是编造，Opus 才不会跟着幻觉。这是本流程最关键的一步
- 结构：①任务+输出要求 ②年度数据表 ③半年数据表 ④最新公告要点 ⑤行业背景 ⑥业务布局 ⑦信息盲区说明
- 模板：`templates/financial-analysis-material.md`

### Step 4: Opus 调用（姿势来自 claude-code-workflow，长 prompt 用 stdin 重定向）

```bash
export HTTP_PROXY="http://127.0.0.1:7897" HTTPS_PROXY="http://127.0.0.1:7897"
# smoke test 先行
claude -p "回复OK" --model opus --max-turns 1 --output-format text
# 正式调用
timeout 580 claude -p --model opus --max-turns 3 --output-format text \
  --disallowedTools Read Write Edit Bash Glob Grep WebFetch WebSearch TodoWrite \
  < C:/Users/Administrator/hermes_output/<file>.txt 2>&1
```

- `--disallowedTools` 禁全部工具（材料已内联，禁止它上网搜旧数据/编数）
- `--max-turns 3` 足够（纯分析 1 轮）；Opus 深度分析首响应 2-5 分钟，timeout 给 580-600s
- 为保险可在 prompt 加"不要调用任何工具，材料已内联"横幅

### Step 5: 交付与归档

- 结果全文内联 TG（9000+ 字系统自动拆条；streaming 已关无双投递）
- 归档 `D:\Workspace\output\YYYY-MM-DD_<公司><报告期>_Opus分析.md`（先 write_file 再交付）
- 结尾告知用户：业绩预告 vs 正式中报的时间差；正式版发布后可再跑一轮更新

## Opus 输出结构要求（写进 prompt，6 项全覆盖）

1. **长周期趋势**：峰值→现状轨迹 + 关键拐点
2. **半年报对比**：利润结构剧变重点拆解（如归母 vs 核心净利剪刀差）
3. **行业背景定位**：共性 vs 个体、同业位置
4. **业务转型评估**：新业务对冲旧业务亏损的能力（含"分母式占比上升"甄别）
5. **财务安全垫**：成色 + 至少五个局限
6. **结论**：一句话定性判断 + 核心结论 3-5 条 + 未来 1-2 年观测指标表（按优先级）+ 风险清单
7. 全部判断带数据，标注（已核实/推算），不给买卖建议

## Pitfalls

1. **归母净利 vs 核心净利剪刀差**：剔除公允值后的核心利润暴跌而归母净利"还行"= 报表利润依赖投资物业重估。拆"公允值贡献占比"=(归母−核心)/归母，看三年趋势（19%→57%→95% 即盈利质量终点）
2. **分部毛利率推算**：开发毛利率 ≈ (总毛利 − 新业务毛利)/开发收入——用收入结构 + 分部毛利率倒推，能定位"增收不增利"的真实根因
3. **"占比上升"可能是分母塌陷**：新业务收入占比 9%→27% 但新业务收入本身三年仅 +13%——占比是被总收入崩塌推高的，别被口径骗；同时报新业务收入绝对值增速
4. **同比口径错位**：营运数据"1-6月 vs 1-7月"含税口径矛盾时，用 7/12 折算或分部加总交叉验证
5. **现金短债比改善可能是分母改善**：在手现金连降但短债降更快；现金/总有息负债是更硬的绝对缓冲指标。去杠杆资金来源要拆：压降额 − 经营现金流 = 消耗现金额
6. **跨天会话先 date 确认当前时间**（见 gold-investment-analysis Pitfall 40）
7. 用户对"数据/价格/额度"类结论凭直觉质疑且常正确——多源验证，推算必须显式标注
8. 利润"恢复增长"目标要拆：基数≈0 时任何正数都叫"恢复增长"，实质条件需另列（库存出清/新业务利润/分部亏损收窄/无大额减值）
